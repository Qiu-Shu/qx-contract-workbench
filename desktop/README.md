# Windows 本机验证候选版 0.5.2

复用现有合同工作台和全量法律资料库。0.3.0 新增工作区与接待：咨询登记、追问、材料清单、跟进、版本核对、客户/内部 Word 和合同转案。原有 Python 业务、登录、权限及原文核验继续使用；这是本机阶段版本，完整统一应用和生产交付仍在推进。

## 使用

运行 `Qunxing-Workbench-0.5.2-Setup.exe`，按安装向导选择当前用户安装。先保存正在编辑的内容并退出旧版及其他安装窗口。首次打开设置本机用户名和 6–12 位密码；其后登录进入工作区。密码不写入命令行或设置文件。当前没有找回密码服务，请自行妥善保存。

## Word 读取问题与升级

0.4.1 改善含 Word 2010 文字填充样式的 DOCX 读取。未使用的合法样式不再阻断整篇文字；实际应用于文字的填充效果仍标为可见性待核，未知结构继续保留读取缺口。这与是否运行大模型是两个独立环节。

升级后，如果旧案件显示“已保存的读取结果与当前解析结果或材料版本不一致”，在接待或事实页展开“重新读取当前文件”，填写原因并确认后执行。本案全部当前文件将一并重读；原件、旧解析和历史成果保留，原文位置及文字未变的事实回到待确认，发生变化的事实只保留历史。旧审查、批准及成果不会自动成为当前结果。请重新核对事实和意见后再导出。

页面先显示提取数量和读取缺口分类，展开可查看完整详情，并可下载对应版本的原件核对。“已提取”不代表全文已核对；脚注、尾注及其他未支持内容仍需检查。

点击“新增接待”登记咨询，再填写追问、材料和跟进。每次保存保留历史；客户回复与内部意见分别复制、分别导出，未保存修改不能导出或转案。客户稿需勾选核对这一版文字，内容来源仍待核验。查看旧版时，右侧显示该版完整记录，中间保留当前版。转案只接入既有四类合同，接待锁定只读；原件在合同页逐份确认导入。其他业务模块在导航中明确标为待接入。

菜单“工作台 → 连接法律资料库…”选择已完成索引的库根目录。本机已验收的库为 `D:\Documents\群兴法律资料库`，不是 F 盘原始文件目录。连接后需重新登录。法规、案例的命中及原文仍显示待核验状态；检索成功不等于官方效力已核验。

用户账户和案件保存在 `%APPDATA%\QunxingWorkbenchValidation\workspaces\main`，资料库仍保存在自己的目录。程序安装目录与资料分开；卸载选项不主动删除用户数据。资料库暂不可用时，菜单“断开资料库连接”后仍可使用案件工作台。已有或不完整工作区不会自动重建；错误时保留现场供维护处理。

0.2.0 工作区首次由新版打开时，会先校验并将升级前数据库保存在工作区 `upgrade-backups`，记录在 `upgrade-intake-v1.json`，再添加接待表；升级中断后只恢复这一精确变更。原件继续原地保留。这份升级数据库快照不包含原件；完整备份请使用下面的新菜单。

## 主模型与 Jev 设置（开发版）

开发源码提供“工作台 → 主模型设置…”，可保存、替换、移除本机 DeepSeek 密钥，选择固定模型并配置或停用本次运行。凭据由 Windows 系统保护，单独放在桌面资料目录的 `model-credentials`，不显示已保存内容、不进入案件备份、普通设置或后端启动参数。当前日常设置与返回工作台保留同一后台、登录和草稿；备份维护仍停止服务，恢复核对副本禁止配置。

保存密钥不配置模型，配置模型也不授权外发。主模型已保存的选择会在启动时尝试恢复配置，恢复失败可从设置页重新配置；这不会自动发送。普通文字已接具体内容、接收方、模型和单次预算的独立原生确认，重启后不续权；更广材料范围、Jev 具体发送许可及真实调用尚未验收。上述能力已随 0.5.0 更新本机安装；实际外部调用仍需逐次核对具体内容并确认。Windows 保护不防范同一 Windows 用户下的其他恶意进程；系统保护不可用时不降级为明文，需轮换的旧凭据显示维护提示。换电脑或恢复案件备份后需另行配置本机凭据。阶段实测见 [日常设置](../docs/testing/native-model-settings/20261019/README.md)及[具体发送确认](../docs/testing/native-send-confirmation/20261019/README.md)，仅使用合成材料和本机模拟服务。

开发版另有“工作台 → Jev 辅助设置…”，与主模型设置在同一页面显示。TypeSafe 密钥单独受保护，可保存、替换、移除、配置和停用；两套配置互不干扰。保存不配置，配置不发请求或批准发送；重启后仍需重新配置。旧后台没有 Jev 能力时显示不可用，主模型仍可使用。Windows 源码及新冻结后台各9组实测已完成，详见 [CH-05C](../docs/testing/jev-native/20261020/README.md)；Jev 设置已纳入 0.5.0，实际辅助判断和真实服务效果不由本次安装验收证明。

## 备份与恢复核对

先保存当前页面，再选择“工作台 → 备份案件资料…”。设置独立的 12–128 字符备份口令，选择新的 `.qxbak` 文件位置。程序暂时停止本应用后台服务，核对数据库与全部受保护文件，生成加密备份并解密复核后显示完成。目标位置只接收密文；明文临时文件保留在原工作区内处理，正常结束或受控失败会清理。已有备份不会被覆盖。

备份包含当前工作区的全部账户、案件、接待版本、原件、历史导出、来源证据和审计。首版限制总量 2 GiB、20,000 个文件、单文件 512 MiB；超限失败，不截断材料。独立法律资料库、浏览器缓存、日志及旧升级快照不在此备份中。口令不会写入设置，也不提供找回；请与备份分开妥善保存。

选择“从备份建立核对副本…”，输入备份口令并选择文件。程序在资料目录 `workspaces/recovered/<唯一编号>` 创建新副本，验证身份、结构、文件数量及摘要后打开。使用备份时的账户重新登录，可核对原件、历史 Word 和各版接待记录；历史会话撤销、未完成任务阻断，副本仅供核对，当前审查/签发接口不可使用。点击菜单“返回原工作区”继续办案。旧原件及历史记录不改，原工作区始终保留。

恢复副本是历史截面，无法自动知道备份之后的账户撤权、账单或对外发送；因此没有自动解除隔离和可写灾备切换。不能把副本中的历史批准当作当前批准。只处理本机文件，不上传资料。

菜单“视图”可调整字号。导出通过现有权限校验后打开 Windows 保存窗口。关闭程序会停止本程序启动的后台服务，不触碰源码版的 8767 服务。

## 重建

前提：固定项目 `.venv` 依 `requirements.lock` 建立；Python 3.12.14、Node 24（0.5.0 本机实际构建为 24.22.1）。本机原有环境保持不变，构建工具单独放 `.local/desktop-tools`。

```powershell
.\.venv\Scripts\python.exe .\scripts\prepare_desktop.py
.\scripts\build_desktop.ps1
```

Electron 44.8.0 / electron-builder 26.15.3 由 `package-lock.json` 固定，npm 12.2.0 tarball 用固定 SHA512 校验；Electron 官方 GitHub zip 对照 npm 包内 SHA256 校验。PyInstaller 6.22.3 及构建依赖由 `requirements-build.lock` 固定并校验哈希。NSIS 和 7-Zip 由固定 electron-builder 的构建工具配置下载校验。无签名账号或付费服务。

后续构建仅收集 Chromium 的简体中文、繁体中文和 en-US 回退语言资源，使用固定 electron-builder 的 `electronLanguages` 配置；不删除字体、ICU、安全组件或许可通知。产品页面仍以中文提供，其他系统语言采用可用回退；这不是新增多语言产品界面。0.5.0 已验证此语言资源配置并更新本机安装。

打包仅包含显式代码、界面、固定配置、已登记虚构样本、规则草稿及依赖许可文本；不会收录 `.local` 工作区、法律库、密钥或真实案件。Python 的第三方许可放在安装目录 `resources/backend/_internal/third-party-licenses`，Electron 的许可随运行组件附带。

`QX_DESKTOP_DATA_PARENT` 仅供由操作系统启动的维护/验收进程指定隔离资料目录，网页不能修改。合成验收脚本位于 `desktop/tests`，使用本机 Playwright Electron 驱动；`PLAYWRIGHT_MODULE` 可指向已安装模块绝对路径。无需最终用户安装 Python、Node 或设计技能。
