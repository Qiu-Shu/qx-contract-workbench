# Skill 融合无人值守：首批方法质量修复

用户于 2026-11-02 要求进入无人值守模式，持续推进 Skill 融合；允许子智能体与 WorkBuddy，评分由 Codex 承担。复用既有两份方案及初评，不重做盘点或重构全项目。首片范围由 `docs/testing/legal-method-ab/ai-preliminary-review.md` 的真实问题限定。

## 实施顺序与接口

1. 保留已冻结的 v1 系统文本、方法来源和渲染语义。新增 case-evidence-v2、contract-review-v2、trademark-triage-v2 方法修订；现有 JSON 成果结构不变，format_version 仍为对应 v1。当前新任务默认 v2；历史根据快照版本重建，不套当前路由。
2. 案件：拟写文书集中为可编辑连续段落，依据与待核事项放到其后的复核区；材料陈述、推断和法律分析继续区分。提示词要求避免同一事实反复拆分，反向线索只用于有具体相反内容的材料；缺证和核账要求不等于相反证据。界面明确这些关系仍待核，程序不假装能判定任意自然语言矛盾。
3. 合同：新路由区分交易履行义务与保密背景/违约赔偿，避免 NDA 仅因“设备服务、支付赔偿”就进入供应商审查；实际混合履行与保密内容仍保留组合方法，SaaS/DPA 未覆盖边界不变。减少同一附件重复问题，保留不同观点与原文位置。
4. 商标：新方法要求面向律师的中文说明，不把 holder/respondent 等内部字段操作写进正文；确定性清理仅限明确的内部字段占位表达，不能改逐字引文或扩大为法律改写。
5. 后端 DTO 允许两版方法标识，桌面形状校验同步；来源摘要、版本、旧成果回读与请求重建必须保持一致。测试现有公开接口：选择/构造请求、候选校验与渲染、历史重建、桌面材料依据。无需引入新库、数据库字段或独立 Agent。
6. 每片先失败测试再实现，运行相关回归，按 Standards/Spec 独立审阅；冻结新输入后使用同一虚构材料做第二轮内容对照。工程通过与 AI 质量评分分开记录，不回写第一轮原始成果及成绩。结果存在分歧时保留并继续修正，不据单次评分作生产采用结论。

## 接续与边界

持续目标已 active；本聊天每 30 分钟接续，旧会话的暂停自动化不动。每轮先读 TASK_STATUS 与最新证据，避免重复工作。伙伴模型未就绪继续待办，接待保留超级销冠派生能力，刑事 synthetic-only-v1 不绕过。仅使用独立虚构材料，保护既有 WIP 和暂存区；本片不提交混合工作区、不推送发布、不安装、不调用工作台付费模型或发送法律材料。后续推进以当前计划及真实验收门槛为准。
