# 本人微信接入统一任务（M6）

基线 da1131d，2026-10-28。授权来源：本会话整理稿、本人扫码微信助手通道及继续实施指令。已验证独立通道，不重做固定回复验收。采用 implement / subagent-driven-development；保留当前 codex/contract-review-v2 与其他未提交工作。

## Global Constraints

- 复用现有 SQLite、Weixin Inbox、TaskDraft、会话附件、业务调度和模型执行账本；不创建第二套任务系统。
- DTO 只定义在 domain.py；旧 synthetic 记录保持原义。真实通道必须有显式来源，与合成注入接口隔离。
- 微信仅限扫码本人和固定 bot/peer；不接管好友聊天、不由正文决定联系人或工作区。群聊拒绝。
- 普通测试只用独立虚构数据；真实账号扫码和远端验收单独记录，不用模拟测试代替。
- 模型仍受原生设置中的模型、材料范围和单请求预算保护；关闭、注销、撤销、恢复态或配置变化不得继续外发。unknown 不自动重发。
- 不覆盖原件、旧消息、执行快照。多附件归集、重复消息去重、歧义询问、执行中新材料进入后续执行。
- 网络不占数据库写事务。凭据、下载密钥和 context token 不进入日志、模型正文或可分享备份。
- 首版连接凭据仅驻留本次进程；退出后重新扫码恢复同一账号任务记录，备份恢复不自动连接。是否增加受保护的免扫码重连另行决定，不阻碍本次业务闭环。
- 用户已有 WIP（UI/版本/安装记录）保持。禁止广泛暂存；仅提交本项文件/相关片段。

## Task 1: 真实来源与既有账本兼容

扩展现有 task_channel_bindings.channel 与 weixin_accounts.mode，仅增加 `weixin_personal`。绑定唯一约束由 conversation_id 改为 (conversation_id, channel)，以便已用桌面业务的聊天同时接收本人微信；旧绑定不改名，仍共用同一 conversation/task_drafts。默认 create_binding 精确选择 synthetic，personal 入口精确选择真实通道；任务列表汇总同会话所有未分配消息。新增精确版本 `weixin-personal-v1`，保留历史 schema 指纹，正常新建、旧库升级、备份/恢复验证均识别它；不得跳过完整性验证。

内部服务允许可信运行时根据已确认远端 bot/peer 建立本人账号、固定会话绑定，并刷新同一 scope target 的 input/material revisions；跨 owner/workspace/binding_revision、撤销、恢复态必须拒绝。复用现有授权历史。对外的合成创建、绑定、收件、分发、offline 注入与 generation 授权路径不得创建或写入真实账号/绑定。读取历史可按原 ACL 保留。

对后续运行时暴露一个专用模块 `weixin_inbox/personal.py`，提供可信内部绑定、同目标刷新、原始 poll 保存及有序分发入口；网络认证由后续 private native runtime 提供，本模块不注册 HTTP 写入口。明确函数契约写入报告。其记录仍由既有 integrity/dispatch/grant 校验验证，不额外保存敏感传输字段。

验证：失败测试证明旧 schema 不接受真实来源；新旧数据库原记录/触发器不变；真实来源注入合成 API 被拒；同 peer 去重与 cursor CAS、跨账号/会话/撤销/restore 阻断；完整目标回归。此任务不引入网络、UI、模型调用、临时绕过或新任务表。

## Task 2: 复用已验证的本人微信协议

从现有 weixin_probe.py 抽出共享薄协议层，保留独立 probe 的固定虚构文件与口令保护。复用已实测的二维码、重定向白名单、登录、getupdates、文件 AES 解密与安全下载；产品运行时通过此层收取原始响应，远端游标由既有数据库管理。固定登录 bot/peer，群聊、其他收件人与不支持的文件不能进入业务。文件只接受有界 DOCX/PDF，核对声明长度和可用摘要，再由附件服务生成 SHA256。传输层只保留内存凭据，不写数据库、不决定任务归属。

发送接口只允许固定本人 peer，调用方提供已持久 claim 的 client_id。返回 submitted/rejected/unknown，缺少肯定回执或网络中断均保留 unknown，不自动重试。传输层不提供任意联系人、URL、shell 或模型能力。所有协议错误只返回固定代码，原始响应不得进入日志。验证共用协议与原 probe 的边界回归，既有真实通道证据仍独立保留。

## Task 3: 原生授权下的收件与业务闭环

受原生私有控制授权后才启动连接；凭据仅在内存，注销/关闭清除。单连接串行长轮询，当前会话/账号精确校验，网络读失败可等待后拉取，发送未知不重试。对页面暴露的只读状态必须经过同一会话 ACL，不能提供 HTTP 开启真实通道的捷径。

先登记附件原件并解析到已有 attachment 服务，成功持久化后才前进远端游标；恢复重复 poll 用固定请求 ID 找原附件，保留原 pending 描述和来源解析。接入 TaskDraft 后按已知唯一任务归集；指令/多个附件收集完成才触发业务。先指令缺材料等待，明确新任务创建新执行，歧义只提必要问题。

复用 business.submit + material preview/native authorization/GenerationTasks，模型结果在同一会话保存。执行结果与来源消息、TaskDraft/版本关联；原生自动范围不开启时只收件并明确提示，不擅自扩大授权。完成/失败/待补信息回本人固定会话；发送前持久 claim，崩溃或未知保留且不自动重发。持久记录仅包含来源与业务关联、发送状态/摘要/client_id，绝不保存传输凭据。

明确新增的持久记录仅用于来源 TaskDraft/版本到既有业务运行及模型请求的关联、外发 claim 与状态，不另存任务/材料/成果正文。新表须有精确迁移、完整性与备份/恢复验证。业务 submit 的可信来源适配必须复用已收集的 TaskDraft，不能再通过 synthetic 入口新建重复合同任务；不得在桌面有未发送草稿时清空草稿。执行中的输入快照保留，随后材料只触发后续执行。

TaskDraftManifest 原有 synthetic=True 是旧模拟桥接的历史字段。真实通道归集时按来源准确标为 false，保留旧默认与旧执行哈希；不得因此开放原 synthetic-only mock bridge。账号/绑定来源与模型发送授权分别核验，不能用某个布尔标签替代原生授权。

## Task 4: 桌面入口与实际验收

在现有聊天提供连接本人微信、扫码状态、暂停/断开及任务状态入口。原生 IPC 获取当前已登录工作台会话，后端私有管道授权；网页不得通过伪造 bot/peer 获得真实通道。复用既有中文样式和模型设置，避免新独立首页。

使用 Task3 报告冻结的私有操作、ready 能力和同会话只读状态契约。原生侧重新读取当前会话和会话 cookie，并从当前模型设置取得自动范围；页面只提供当前会话操作意图或验证码，不指定模型预算、身份、token 或任意目标。连接/扫码失败、等待验证码、已连接、暂停与断开都显示中文状态；重复点击和过期异步结果不得开启额外连接。导航、退出、工作区切换和原生关闭的行为应与后端固定范围一致。

二维码只在本机生成。若采用 qrcode 8.2，复用已核验官方 wheel 与许可证据，同步精确依赖清单、哈希锁、第三方通知和冻结后端打包；不借助外部二维码网站。新入口继承现有浅色中文 Operate 界面，不更换框架或设计系统。真实 TaskDraft 标签与可用操作必须准确，不能显示为“模拟合同任务”或开放旧 mock 执行入口。

微信收件和结果变化应自动刷新当前聊天，保留未发送文字、材料选择和本地未保存编辑。复用现有 controller 的刷新与冲突处理；后台状态查询不能触发模型调用。覆盖原生来源/页面守卫、严格参数、模型设置变化、重复操作、迟到状态、只读恢复、断开、未保存草稿和窄窗口键盘操作。

覆盖桌面权限/注销/工作区切换、前后端闭环及重复消息。先完成虚构端到端与独立审阅，再请本人正式扫码及发虚构文件+业务口令。验证同一任务、附件原件、真实模型结果和微信回传分别记录，未实测项明确标未验收。更新阶段证据、TASK_STATUS、TODO 并按已有协作规则提交同步。
