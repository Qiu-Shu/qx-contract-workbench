# C：合成 PDF 持久合同任务

用户于 2026-10-24 明确要求继续无人值守实施并与 GitHub 同步。本片延续 A+B，不重新实现已验收的消息聚合、冻结、权限、事实确认与 Mock 审查。

范围：注册的独立虚构原生文字 PDF，从对话附件读取到 TaskDraft、冻结、案件材料、人工事实确认和 Mock 结果；DOCX/PDF 混合收集继续使用同一任务。真实合同模型、微信账号、OCR、安装包和生产验收不在本片。

## 固定接口

- `assistant.attachments` 复用 `documents.pdf_adapter.parse_pdf`；PDF 只接受无 baseline 或 `original`，存储一律 `original`，parser_version 为 `qx-pdf-attachments-v1`。DOCX 版本 `qx-docx-attachments-v1` 保留。
- 读取状态沿用现有 readable/partial/failed；非空锚点且无 unsupported_parts/quality_issues 才 readable。partial 不能冻结，界面允许排除或更换可读版本；不伪装人工核对已经完成。
- 冻结和 Mock 来源只扩大 MIME 至 DOCX/PDF，保持精确版本、摘要、当前归属、ACL、服务器合成登记与不可变执行核验。案件重新解析生成案件版本锚点，保留页码和 bbox。
- 新固定 PDF hash 只加入对话附件和备份合成登记，不修改历史 assisted-v1 策略，也不扩大普通合同上传授权。无 DTO/schema/依赖迁移。

## 实施与验证

1. 后端先失败测试：双页解析、baseline、部分可读/坏文件/加密和原件保留、冻结/桥接、页锚点重复确定性及权限/来源拒绝；最小实现后定向回归。
2. 根代理生成并渲染两页中文独立虚构原生 PDF，固定 hash；验证默认桌面 assisted 配置可上传该对话样本，普通未登记或原有合同入口仍拒绝；验证备份登记。
3. 前端先失败测试：读取 PDF、原始视图、页/锚点展示、partial 明示阻断、主材料候选、更新读取状态；保留 DOCX 交互及已有任务恢复。
4. Chromium 源码服务使用原生 assisted 配置分别走先指令、先附件，并验证结果回查、数据库数量及零外网。DOCX/PDF 混合收集和 qxbak 恢复另作针对性验证。
5. 独立复核、开发门、证据及 TASK_STATUS 更新，按明确文件集正常提交推送，并核对远端 SHA 与文件树。
