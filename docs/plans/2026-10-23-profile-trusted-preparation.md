# CH-07C2b2a 档案发送的数据库核验

基线 `2997d4602d842c6cab8e514a4c7340085910ad0c`。沿已批准 v2.1、C2a 和 C2b1 接续，由 Codex 认领。开始时工作区干净、远端无分叉、无开放 PR、无本阶段活动测试；已安装桌面进程保持不动。

## 本片要解决的问题

C2a 的纯函数能证明输入彼此一致，却不能证明 run/message 属于数据库中的这次提交，也不能读取律师刚刚修改的档案或接待版本。C2b1 已准备新账本结构，但发送与自动保存尚未开放。本片补上后续许可、登记和结算共同需要的数据库核验，不增加另一套模型或档案存储。

新增 `assistant/profile_preparation_service.py`，复用 `service`、`attachment_records`、`profile_store`、`intake.service` 和 C2a 纯准备函数。业务 DTO 继续使用 `domain.py` 中已有定义。

- `build_profile_basis(actor, conversation_id, message, db, *, config, project_intake=False)`：验证当前用户、会话访问权、可写工作库、未归档、完整作用域和输入框版本；提交文字须与数据库当前草稿逐字一致。点选技能、提交附件、当前选中的附件都不属于本片支持范围。档案基线和接待目标/版本只能从当前数据库读取，不能让调用者填写；已转案接待拒绝作为投影目标。
- `prepare_profile(actor, run_id, basis, db, *, config)`：按 ID 读取实际 run 和同会话的 user message；显式核对 run 的 actor/session、请求 ID、未取消的 queued/generating 状态、消息版本和原请求摘要。通过原始 actor/workspace/conversation/AssistantMessageInput 重算摘要，证明保存前的输入版本与实际消息相符。当前作用域必须等于批准前 input_revision 加一，当前档案及接待版本重建出的完整 basis 必须完全相等，不能悄悄更新旧许可的保存目标。
- 保存后继续打字可以推进 composer_revision；新草稿不进入发送正文、来源或档案。准备结果中的固定 composer_revision 由已核对的原请求重建为批准版本加一；当前 composer 不得倒退，材料/输入/绑定作用域仍需精确相等。
- 旧档案即使摘要有效，也必须与当前会话的固定作用域字段一致，且其输入和材料版本不得领先当前作用域。复用档案合并器现有语义，提前拒绝换绑后必然不能保存的计划。
- 结果只证明当前数据库与给定计划相符，不等于发送许可、费用预留、claim 或允许写档案。传入 Session 由调用者管理；保留现有权限检查的 flush 和拒绝审计语义。本模块不主动新增业务记录，不能把这点宣传成任意失败路径全库零写入。

## 验证与接续

### 独立复核后补入的共用修复

SPEC-01 的有效探针发现，既有附件选择解码把 JSON 对象或空字符串迭代成空结果，使损坏快照可能被当作未选附件。修复放在 `attachment_records.decode_items`，复用既有严格 JSON 解析与 DTO 去重规则，要求数组根、最多20项且附件ID不重复；当前选择和历史请求回执共用。合法空列表、20项上限及顺序不变。增加独立合成损坏快照的失败验证，关联回归扩大至13个文件，覆盖原附件、上下文、主模型、Jev和检索调用者。

本段是复核发现后的实施范围记录；两份独立报告的计划输入哈希对应补记前的冻结版本，产品和测试的最终哈希另列于报告，不把文档补记冒充该冻结窗口的输入。

先保留有效失败验证，再实现。用独立合成 SQLite 记录验证来源替换、跨用户/跨登录会话、篡改请求摘要、取消/终态、草稿隔离、作用域及材料变化、档案/接待版本和配置变化、恢复隔离、已转案接待等拒绝路径；核对成功读取不增加消息、运行、档案、接待或模型账本。目标回归、四开发门及独立 Spec/Standards 复核通过后更新协作文档，正常推送并核对远端 SHA。

本片不修改 registry、native、runner、HTTP 或新格式验收 guard。下一片 C2b2b 必须同时完成完整 basis 用途授权、登记/claim/结算、费用独立记账、固定 response.ready 与原子保存回执、语义历史重放及备份验收，才能去掉封闭 guard；不能把本片装配函数直接暴露成生成入口。C3 再接档案面板。
