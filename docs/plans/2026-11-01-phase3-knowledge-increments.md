# 阶段 3：复用现有检索的增量接入

阶段 2 源码验收通过后实施。伙伴模型服务尚未完成，已由用户指定列为阶段 5 待办，不影响本阶段合成验证。

## 复用边界

接待沿用 `reception/knowledge.py` 的导入、原件摘要校验、段落定位和 `KnowledgeStore.search/resolve`，接入现有九份资料，不重建另一套接待知识库。家事沿用本机 0.2.0 的五个 reference 文件（两份通用路由/底表和三份既有知识文件），保留原文件名、内容摘要及来源声明。公开法律镜像沿用固定持衡项目的 `PublicCorpus.search`，保留 `unverified_mirror`、来源链接、版本和效力未核验提示，不复制法库。

## 实施顺序

1. 在可信本地配置登记知识根与摘要。来源不能由聊天或材料指定，配置不改变案件权限。
2. 复用已有搜索，为当前问题自动选取有限片段。逐项记录检索词、来源、定位、版本摘要、核验状态和本次引用标识；无命中明确为空，不声称已查全。
3. 将本次片段快照加入现有材料调用、授权摘要、成果和恢复校验；总输入上限继续生效，旧记录保持兼容。
4. 在当前聊天与 DOCX 成果展示来源。来源目录变化不能重写历史；发送前变化需重新预览。
5. 合成验证通过后，在隔离目录用现有本地资料验证读取/检索路径。只保存数量与摘要等验收元数据，私有知识正文不进入 Git、公开日志或外部服务。

## 验收门

覆盖接待九份资料/八份独立原件的保留关系、家事参考文件、持衡镜像检索、无命中、摘要变化、引文伪造、跨会话、取消、旧记录恢复和导出。知识片段与案件原文分开标识，引用知识不等于事实认定或现行法律效力核验。未完成前不关闭阶段 3。
