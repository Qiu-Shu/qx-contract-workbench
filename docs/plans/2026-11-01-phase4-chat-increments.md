# 阶段 4：在现有界面统一聊天操作

依据用户已确认的六阶段方案，阶段 3 验收通过后进入本阶段。继续使用已确认的温情配色、中文系统字体、FastAPI/Jinja/静态 JS 及同节点双视图，采用 Impeccable Operate 的布局与可用性规则。核心问题是：律师在当前事项里下一步做什么、有哪些材料、正在处理什么、成果在哪里。

## 最小实施范围

1. 默认对话视图；四项业务卡片放到输入框上方，点击只选择当前能力，不产生请求或切换工作区。保留工作台视图及原节点。
2. 修正现有聊天列收缩问题。左侧保留新对话、事项历史与已有导航；中间对话和输入框共享主轴；右侧增加可收起的事项概览，展示当前范围、实际任务状态、本次材料与最近已保存成果的方法/知识来源。
3. 档案、底稿、事实、跟进、任务与成果继续复用当前控制器和原面板。“任务与材料”直接在当前聊天侧窗打开，不强制切回工作台。后端继续核验归属、取消、版本与权限。
4. 宽屏为并列上下文，窄屏为可关闭侧窗。保留未保存文字、原件节点、滚动位置；关闭恢复焦点，遮挡主区时禁止焦点落到背后。
5. 上下文只投影当前会话已返回的状态。未产生实际调用时不显示“已调用技能”；未核验参考资料保持待核验；切换/撤权时清空旧事项。

## 十项实际验收

| 原则 | 本阶段可执行验收 |
| --- | --- |
| 状态可见 | 草稿保存、任务状态、发送未知与材料读取状态可区分 |
| 现实语言 | 使用客户接待、案件整理、合同审查、模拟法庭、材料与成果 |
| 用户可控 | 保留取消/补件入口，关闭概览与侧窗恢复焦点，草稿不丢 |
| 一致性 | 相同节点与控制器，能力卡片与自然语言进入既有业务路由 |
| 防止错误 | 卡片点击不发送，撤权/跨事项不显示旧上下文，未知结果不重发 |
| 识别而非记忆 | 当前范围、材料及实际来源在概览中可见 |
| 灵活高效 | Enter/Shift+Enter、四卡、键盘打开/关闭及返回输入 |
| 简约 | 默认聊天；概览、来源和工作表按需展开 |
| 错误恢复 | 保留原因、原输入与查找回执/重读入口 |
| 帮助 | 能力范围及材料核对说明在当前对话可查 |

在 1440、1024、390 三种宽度使用虚构账号实跑页面，检查不溢出、遮挡/键盘焦点、卡片、任务/材料及同对话操作；来源只用合成数据。浏览器验证不等于安装版 Electron、真实微信或律师法律质量验收。
