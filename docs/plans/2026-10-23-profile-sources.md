# CH-07B1：服务端重建档案提案来源

基线 `0eb341a2d25da88b05ac4b62f16d45a77a6a140b`。本片是 CH-07B 持久化的可独立验证前置，不修改 schema 或拆开首次持久化的事务/迁移/备份闭环。

## 接口与边界

`assistant.profile_sources.read_profile_sources(actor, patch: ProfilePatch, *, database) -> ProfileSourceSnapshot`

- 复验嵌套 DTO；从提案引用中取去重 ID，最多200条消息、20份文档，超限拒绝，不截断。只读取被引用来源，不扫描整个历史或所有材料。
- 复用当前会话所有权、案件/接待权限、工作区、恢复栅栏和精确 ScopeSnapshot 检查。未发送草稿或助手回复不能充当用户原话。composer-only 变化不使已发送原话过期。
- 消息从数据库重建；附件必须属于当前选定材料快照，解析版本逐引用一致。复用原件路径/摘要和解析摘要校验，不运行解析器。部分读取保留全部 ParseResult 限制；未解析、需基线或失败的来源拒绝。
- 文件读取在数据库事务外；返回前另开短事务重核授权、恢复/归档及作用域。快照只描述检查时的来源，不是未来保存许可。后续写事务仍须重核。
- 引用中的原话、摘要、锚点仍由 `merge_profile` 与真实快照精确匹配；这个读取入口不确认法律事实，也不执行投影。
- 不新增业务 DTO、依赖、HTTP/UI、模型调用或档案/接待/原件写入；权限拒绝沿用既有安全审计，不抑制授权失败记录。已有档案内核与当前授权服务、附件 records/files 是复用点。

## 实施与验证

1. 新增合成集成用例，先观察入口缺失的失败；实现实际读取接口。
2. 验证原话/文档→既有纯合并，伪造引用拒绝、选择/解析版本、损坏原件、待基线/部分读取、容量、当前和文件读取期间撤权/换作用域/归档/恢复、composer-only兼容及无数据库/原件写入。
3. 执行受影响的纯内核、会话、附件及恢复相关回归与四项开发门；独立复核，记录真实退出码及源文件摘要。
4. 更新 TODO/TASK_STATUS/README/执行记录，审查公开仓库上传集合，正常推送并核对远端 SHA/树。
