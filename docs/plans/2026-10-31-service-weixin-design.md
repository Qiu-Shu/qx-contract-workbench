# 服务台微信与辅助判断：已确认实施范围

依据用户 2026-10-31 的需求、上一轮分析及“落地实施”，沿 codex/contract-review-v2 实施。此前的分析是本次设计依据，不再重复征求同一授权。

- 主模型显示 DeepSeek V4.1 Flash，API ID 继续 deepseek-flash（官方当前对应 V4.1-Flash-1017）；保留 V4 Pro。
- 工作台内 DeepSeek 不设费用上限，自动分析默认开启并保存；显式关闭必须保留。费用统计、未知结果、去重、超时、版本核验继续存在，不自动重发旧未知请求。
- 本人微信连接工作区与登录律师的服务台，入口在左下业务能力上方，切换聊天不影响连接。仅本人现有微信助手通道，退出登录/撤权/关闭后台仍停用。
- 新业务自动建会话，补充沿原事项；候选档案须有权限，多个可能归属只问一个问题，不能按最近时间猜测。测试/问候回复不启动法律分析。
- 连续消息先归集。初始静默窗口 5 秒（可按实测调整）；明确等待继续等待，附件未就绪不能启动，明确开始可跳过静默等待。新消息使旧判断失效；分析中晚到材料保留进入后续执行，不覆盖原材料版本。
- 规则先行、Jev 辅助、DeepSeek 执行业务。Jev 首版复用点为输入是否完整、任务延续、四能力路由和材料类型；判断失败可回退，不授予权限、不确认事实、不判断法律结论。复用既有 TypeSafe 传输与配置，不另建模型平台。
- 只发送判断所需的文本与候选摘要；不把完整档案库作为路由输入。现有主模型与 Jev 分别管理凭据，显示其实际可用状态。
- 保留同伴前端、所有原件/历史/旧执行；普通测试只用独立虚构数据。不重建任务数据库。必要的持久路由或批次字段在现有库作兼容增量迁移并覆盖备份恢复。

验收：两条文字+两附件只形成一次初始分析；先附件/先指令均可；两个不同事项各自新建会话；明确追问继续原事项；歧义一次澄清；切换桌面聊天不掉线；重复消息不重跑；执行中补件不污染旧执行；Jev 不可用可明确回退；取消费用上限在后台生效；关闭自动分析的设置重启后保留。
