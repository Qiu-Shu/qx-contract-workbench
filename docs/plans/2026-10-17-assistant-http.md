## Contract

- Add thin `web/assistant.py`, registered by app assembly, using existing request_context authentication, same-origin/CSRF and bounded strict JSON. Authenticate and authorize before awaiting request-body bytes, release the transaction, then recheck at the write. Routes are conversation create/list/read/draft/message, run read/cancel and events. Skills return an honest fixed catalog with generation not connected; no provider settings or secrets.
- Existing storage request DTOs remain authoritative: `expected_scope` and `expected_composer_revision` are complete, not replaced by guessed current values in HTTP. POST message returns 202 and the persisted queued run; GET does not execute it. No assistant worker exists yet.
- Add service list/cancel/event reads and corresponding domain DTOs. List fetches at most 50 owner/workspace rows ordered by created_at/id, filters linked-scope permissions, and uses the last scanned UUID as cursor. An empty authorized page may still have a continuation; never fetch all histories or leak another owner's records.
- Cancellation is idempotent per run: queued/awaiting_input cancel immediately; in-progress states only set cancel_requested and record a request event. Finished or already requested runs are unchanged. It never claims an in-flight external call was not billed. Immutable event and flag/state writes share a savepoint.
- Events read only an existing permitted run, bounded batches, with validated monotone integer sequence. HTTP accepts after_seq or Last-Event-ID (header takes precedence for browser reconnection). Missing/future sequence requires snapshot reload rather than rerunning a job. SSE yields committed event envelopes; authentication and scope are rechecked every batch. No transaction spans yield, delay, socket work or model calls. After authorization loss, send only a generic access-revoked control event and close.
- SSE uses a 15-second polling window, waiting up to 250 ms (or the smaller remaining window) between reads outside a database transaction. Check the deadline before/after each read and before emitting any further frame. This is not a hard socket lifetime: existing SQLite lock waits and network backpressure can last longer, and the existing 15-second SQLite busy timeout is not a total read-operation bound. It emits existing event IDs and closes once a terminal run is drained. Idle reconnect never creates messages, attempts or fees. First request must pass same-origin checks before headers. Data frames have run_id, conversation_id, seq, event_type, audience, payload and created_at; no fabricated output.delta.
- Recovery middleware allows only exact read-only assistant routes (list/detail/run/events/skills); service write fence remains independent. No blanket `/api/assistant/` allowance and no new recovery page redirect override.
