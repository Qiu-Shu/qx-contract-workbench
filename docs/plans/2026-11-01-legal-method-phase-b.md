# 法律方法第一批 B：合同组合分流与专项草稿

沿用已批准的分阶段方案，本片只增强现有合同材料引擎，不增加工作台、任务表或独立 Agent。客户接待保持原能力，伙伴模型仍待办。

## 接口与边界

- 后端为新合同预览创建 `contract-review-v1` 快照：每份已读附件按正文中的有限线索分流到 general、nda、vendor，可组合；文件名不决定类型。SaaS、DPA 只记录未覆盖专项，未知合同保留通用方法。路由是候选分流，不宣称任意文本语义识别正确。
- 注册方法包含群兴编写的通用、保密、供应商方法文本、摘要及上游出处/许可。只将选中的方法放入同一次原有模型请求；上游操作脚本、自动发送、独立事项数据库和静态法条不进入运行链。
- 主协议及附件保持同一 task、manifest、请求与成果；逐文件逐方法的返回条目必须齐全，不能仅显示技能名称。成果保存本次方法快照和结构化分析，后端生成统一可读文本；回读、Word、恢复共用校验。
- 每条问题保留精确引文、候选审查立场、差距、法律风险、商业摩擦、替换文字与不接受时的备选方案。引文仅来自该附件实际解析的原文；知识资料不能充当合同原文。我方角色只可引用本次用户指令，无法确认则为待确认。
- 仓库已有 matter 政策批准链，但聊天材料流程未桥接其实际批准/撤权状态。本片不将模型、附件或普通字段当作律师批准。审查立场均为候选；成果只黄/红，绿色关闭。所有输出未签发、不得自动发送或执行修改。
- 未读部分、解析质量、材料正文或当前指令中的 URL、未覆盖 SaaS/DPA 由后端显示；不抓取 URL。零正文附件保留目录且 methods 为空，不要求分析；全部附件均无正文时发送前阻断。NDA 检查隐藏权利义务；供应商方法区分直接/间接损失、责任基数和例外，不默认我方采购方。
- `contract_review` 为可选且缺省不序列化。旧 C4 METHOD、旧快照和旧 wire 不变；历史重建沿冻结字段。新模型 JSON 仅为 format_version、stance、stance_quote_ids、quotes、reviews、gaps，拒绝旧格式降级和额外批准字段。

## 实施与验证

先冻结修改前字节和原暂存摘要，再运行失败测试。验证组合 MSA/NDA、隐藏 IP、供应方立场、无批准不绿、URL 缺口、同任务补件和旧新版本、来源/方法篡改、保存回读/Word/备份恢复。测试使用独立虚构材料、模拟模型和短路径临时目录；分批运行受影响回归，保留首次失败和实际数量。真实模型 A/B、律师质量验收、安装及全仓测试不由本片代替。

已有混合工作树保持，不在本片提交或推送。子智能体分别实现有限方法模块、补充集成测试与独立复核；主代理负责 DTO、主链、桌面、最终验证与证据。已失败的 WorkBuddy 任务不自动重试。

实际执行调整：实现子任务未产出文件后由主代理接手；子智能体完成兼容盘点及 Standards/Spec 独立复核，两项具体缺陷已修补并复验。实际结果以阶段测试报告为准。
