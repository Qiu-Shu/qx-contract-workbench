# CH-04H 本次文字发送的原生确认

基于已批准 v2.1、CH-04F 私有授权管道和 CH-04G 日常设置继续。只处理当前已保存的普通文字；技能、附件、Jev、真实外发和安装版更新不在本片验收中。

## 目标与边界

律师点击发送后，在独立原生窗口核对完整文字、DeepSeek 接收方、固定模型、一次调用的最高预留费用及待核状态。取消不登记任务、不发模型请求。确认不代表确认事实；输出仍为内部待核草稿。

主进程重新读取自己持有的后台 origin 和隔离 session 的登录 cookie，通过已有只读接口读取已保存草稿与能力。页面只提交固定 request_id、完整 scope/composer/摘要作为一致性提示；身份、模型、配置版本、价格与预算均不接受页面自报。读取用数字回环固定路径、禁止重定向、响应字节上限与超时；不增加授权 HTTP 端点。

确认窗口为独立文件页和 preload，隔离 session、sandbox、contextIsolation，禁 Node、webview、任意导航与新窗口。完整原文纯文本可滚动；取消为默认焦点，明确点击确认才批准；关闭、超时、父窗口或后台变化均取消。IPC 限于当前确认窗口的主 frame 和准确文件 URL；普通页面不能提交确认决策。

批准前后复核后台实例、工作区、页面 epoch/对话路径、真实 cookie、完整 scope/composer/摘要及配置版本。授权通过现有私有管道，绑定同一个 request_id，仅一次、短有效期、固定成本上限。授权不确定时结束拥有它的后台，不自动重新授权。确认后前端再次核对本地草稿、技能、附件和页面，沿已有 generation POST 与原队列登记；失败/不确定仍用原 request_id 查询，禁止新 ID 自动重发。配置保存、能力 GET 和恢复副本均不能授权或调用模型。

原生批准已成功、但前端尚未提交时若本地文字变化，前端放弃 POST。此时具体授权最多保留 120 秒，只能用于同一请求身份、原已保存版本和原摘要，不能自动运行；保存新版本立即使旧内容不匹配。下一次显式批准替换当前会话授权。本片不另增通用 renderer 撤权入口。

## 模块划分

- `model-session.cjs`：继续私有持有配置版本，增加可信主进程内授权消费；不把版本或密钥投影至 renderer。
- `model-approval.cjs`：可信 context 读取、scope/版本验证、串行确认及短期授权，固定错误输出。
- `model-approval-window.cjs` 和独立 HTML/CSS/JS/preload：只负责本次批准窗口，不访问账户、网络或存储。
- `assistant-generation.mjs` 及现有控制器：先保存、以同一请求身份确认并登记；浏览器无原生桥时保留既有受控路径。`main.cjs` 只接线和生命周期 guard。

## 验证与交付

先边界测试：普通/子 frame/其他窗口拒绝、错误/过期配置、cookie/草稿/材料/版本变化、取消和关闭、重复点击、IPC 不确定、非法回环和响应上限、恢复副本、原请求查询。接着在独立中文路径的真实 Windows Electron 中，以合成凭据、已有 loopback provider 测试实际确认与一次队列生成；无任何真实供应商请求。确认窗口检查小窗口与常见缩放、键盘和长中文换行。

变更稳定后运行关联回归、开发门禁和独立复核，记录输入摘要与退出码。若修改了冻结后端携带的静态资源则重新构建独立冻结后端并验证；不覆盖安装版或用户工作区。TASK_STATUS、阶段记录与 Obsidian 仅写已测事实，阶段通过不等于 CH-04/Jev/产品生产完成。
