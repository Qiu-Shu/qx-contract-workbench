# 持久本机工作台

2026-10-09。复用现有审查服务、账户权限、原件、版本、后台任务和工作稿功能；本入口解决重启时另建试用库、使用公共演示密码的问题。

## 启动

在项目根目录双击 `启动工作台.cmd`。首次在窗口中设置用户名和至少12位密码，密码输入不显示；随后打开 http://127.0.0.1:8767/login 。以后双击同一文件，直接继续原有案件库，不重新创建或重置账户。关闭服务用窗口中的 Ctrl+C；正在运行的任务完成前，退出会等待。

固定保存目录是本项目 `.local/workbench`。不要删除、改名或手工覆盖其中的数据库、workspace.json、protected；它们共同构成工作区。遇到重复运行、目录不完整、数据库损坏或身份/结构不匹配，入口拒绝启动，保留文件，不自动清空重建。数据库结构升级和旧试用库迁移尚未实现，不可把旧库直接复制进来。

原试用服务8766及原案件仍保留；新入口使用8767，不自动搬迁旧案。

## 账户

首次账户只有经办角色，不创建公共演示账户，也不自动获得复核、管理或签发权限。停止工作台后，本机维护人员可以在项目目录显式添加单一角色账户，密码仍在隐藏提示中输入：

```powershell
.venv/Scripts/python.exe -X utf8 -m cn_contract.web.local_server add-user --username reviewer --role reviewing_lawyer
```

已有同名账户会被拒绝，不借添加操作重置密码。新账户不自动加入所有案件。当前未实现密码找回、自助账户管理、律所实名身份或组织单点登录。

其他维护入口：

```powershell
.venv/Scripts/python.exe -X utf8 -m cn_contract.web.local_server --help
.venv/Scripts/python.exe -X utf8 -m cn_contract.web.local_server serve --port 8767
```

账户秘密不得通过命令参数或聊天提交。本机有项目文件写权限的维护者仍属于信任边界；此入口不是操作系统隔离或公网服务。

## 当前可处理范围

仍只接收 `tests/fixtures/assisted-v1/` 中12份登记虚构合同；文件准入、原文核对、候选意见、律师处置及工作稿确认仍走已有后端规则。没有开放用户真实合同、真实DeepSeek、企查查、正式签发或生产使用。个人本机账户不等于律师现实身份已核验。

这次开发没有替用户设置账户或保存真实密码；首次账户由用户本机输入。启动分支已用实际应用测试，双击脚本的人工交互尚未验收。验证细节见 [本轮记录](testing/LOCAL-workbench-20261009.md)。

## 本案法源核对与谈判标准（2026-10-10增量）

加载本批新源码后，在“18维意见与证据”页已有候选意见时：

1. 展开“登记本案法源原文”，录入已经取得的来源信息、原文及日期。保存只是本机登记，网址不会被自动访问，真实性仍待核验。
2. 在具体意见下展开“本条意见的法源核验与谈判标准”，勾选随处置保存记录。选择本案来源、填逐字摘录和所核命题，分别记录支持关系、案件适用性及理由，填写所核时点。
3. 如记录商业要求，选择“商业偏好”，填写标准立场、退让方案和升级条件；这些条件只属于本案本轮立场/政策，不自动成为跨案标准或法律要求。
4. 保存人工处置后重新生成工作稿。客户稿会保留核验状态，内部理由、退让及升级条件仅进入内部稿。新处置使旧稿失效；原记录留存。

一条记录核对一条法源，不表示所有引用均已核验。法源原文存在、律师采纳意见、来源真实性核验是不同状态。来源或核验资格变化会提示重核；系统不会因为勾选“支持/适用”自动批准真实性。列表超过100条可“加载更多法源”。实际测试和本批未覆盖的法律验收见[QX05增量记录](testing/QX05-BASIS-20261010.md)。本轮没有重启现有8766/8767或宿主进程，旧页面看不到入口时先核对实例实际加载版本。

## 修订全文复审（2026-10-10增量）

加载新版本源码后，在“修改预览与签发”页：

1. 完成意见处置、批准精确草案修改，选择“内部”，生成草案预览。
2. 下载实际文件，并对照“修订后的全文复审”逐段核对。页面显示原基线、接受全部修订的文字及数值/期限/引用线索；含历史修订时也列明差异。附件、表格及未读部件限制不可忽略。
3. 分别填写法律、金额、期限、附件、定义与交叉引用的结论和理由。没完成就选“待核”；法律项还需要当前法源真实性/支持/适用链，不能靠勾选替代。数值线索不自动计算正确性。
4. 保存本版复审记录后，再核对实际草案和限制，保存工作稿版本核对。待核项会继续显示；新修改、新处置、新复审或资格变化后，旧记录不能套用。

对外人工修改表没有已落实的合同全文，仍可下载人工处理，但不能冒充已复审修订合同。无补丁报告的核对仍只证明该版报告的版本与待办范围。详细证据和限制见[QX06记录](testing/QX06-EFFECTIVE-TEXT-20261010.md)。旧服务需重新加载源码才能看到此入口，本轮未重启或改动个人案件库。

## 让本机插件读取当前案件并提交候选

在8767持久工作台完成原文及事实确认，打开“18维意见”，勾选同意让当前虚构材料进入调用插件的聊天，再点击“开放所选连接权限”。默认仅可读取，持续15分钟，一次只选择一案；在已加载0.1.5源工具的聊天调用 `read_selected_case`。可随时在原案件页面撤销。

如需把插件建议保存到工作台，再单独勾选“另行允许插件提交一轮待律师处置候选”。调用 `submit_selected_candidates` 后，刷新案件页面，逐条进行律师处置，再生成工作稿。授权不会自动采纳意见、确认事实、修改原件或批准。每次授权只容纳一轮；同样内容再次提交返回原收据，改变内容将被拒绝。超时不能当作失败而自动重试，应先到工作台核实。

插件返回当前事实、可引用原文和独立来源核对记录。插件候选的模型身份及推理未核验，来源会保留在工作稿中；工作台没有调用真实DeepSeek或QCC。原手工候选录入继续可用。连接仍只接受登记虚构材料，网页ChatGPT账户连接未完成。

注销、授权到期、权限或材料上下文变化后，需要重新选择。服务重启取消连接，但已提交候选保留。运行期间账户/成员/会话的ORM或批量权限写入均保守取消选案；跨进程账户维护须先停服。本机文件与进程访问权限仍属于信任边界。凭据留在固定本机目录，不要复制到聊天或对外共享。非默认保存目录或非8767端口不提供连接。
