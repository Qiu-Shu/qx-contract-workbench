# 持久本机工作台

2026-10-09。复用现有审查服务、账户权限、原件、版本、后台任务和工作稿功能；本入口解决重启时另建试用库、使用公共演示密码的问题。

## 启动

在项目根目录双击 `启动工作台.cmd`。首次在窗口中设置用户名和至少12位密码，密码输入不显示；随后打开 http://127.0.0.1:8767/login 。以后双击同一文件，直接继续原有案件库，不重新创建或重置账户。关闭服务用窗口中的 Ctrl+C；正在运行的任务完成前，退出会等待。

固定保存目录是本项目 `.local/workbench`。不要删除、改名或手工覆盖其中的数据库、workspace.json、protected；它们共同构成工作区。遇到重复运行、目录不完整、数据库损坏或身份/结构不匹配，入口拒绝启动，保留文件，不自动清空重建。数据库结构升级和旧试用库迁移尚未实现，不可把旧库直接复制进来。

原试用服务8766及原案件仍保留；新入口使用8767，不自动搬迁旧案。

## 账户

首次账户只有经办角色，不创建公共演示账户，也不自动获得复核、管理或签发权限。本机维护人员可以在项目目录显式添加单一角色账户，密码仍在隐藏提示中输入：

```powershell
.venv/Scripts/python.exe -X utf8 -m cn_contract.web.local_server add-user --username reviewer --role reviewing_lawyer
```

已有同名账户会被拒绝，不借添加操作重置密码。新账户不自动加入所有案件。当前未实现密码找回、自助账户管理、律所实名身份或组织单点登录。

其他维护入口：

```powershell
.venv/Scripts/python.exe -X utf8 -m cn_contract.web.local_server --help
.venv/Scripts/python.exe -X utf8 -m cn_contract.web.local_server serve --port 8767
```

账户秘密不得通过命令参数或聊天提交。本机有项目文件写权限的维护者仍属于信任边界；此入口不是操作系统隔离或公网服务。

## 当前可处理范围

仍只接收 `tests/fixtures/assisted-v1/` 中12份登记虚构合同；文件准入、原文核对、候选意见、律师处置及工作稿确认仍走已有后端规则。没有开放用户真实合同、真实DeepSeek、企查查、正式签发或生产使用。个人本机账户不等于律师现实身份已核验。

这次开发没有替用户设置账户或保存真实密码；首次账户由用户本机输入。启动分支已用实际应用测试，双击脚本的人工交互尚未验收。验证细节见 [本轮记录](testing/LOCAL-workbench-20261009.md)。
