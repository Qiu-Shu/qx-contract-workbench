## 范围与信任边界

工作流从后端重读实际 session/roles/member、Matter、全部 current originals、完整事实/政策/规则快照及 hash；对所有保存解析复用 T04 `trusted_parse` 从只读原件重算 anchors、unsupported 与 quality。客户端 DTO、自报确认、清空草案规则、删文档/范围、伪 quote 和伪 manifest 均不能替代服务端。规则选择仍接收完整快照，模型 context 仅投影实际 applied 规则与核验引用。三份本项目独立编写 prompt 实际进入模型请求，初始、结束和受保护读取核对 prompt hash。

无现实获批法律规则时，完成状态仅指有限工程步骤完成。18 维全部明确状态；除材料缺口、数学关系和义务方向观察外保留 insufficient_material/unsupported，不能填满 reviewed_no_issue。完整法律审查请求返回 failed / RULE_UNAPPROVED。任意法律话语、法源 ID、HumanDecision 与正式批准不能靠模型 JSON 创建；已批准来源存在也不表示支持任意分析。mock 不签发、不制造修订件。

每个逻辑操作最多原始请求加一次结构修复；严格 raw JSON 拒绝重复 key、NaN/Infinity/溢出浮点、非对象、超长和超过 64 层的嵌套。失败和修复均保存实际 usage/hash/ref；sent_unknown、blocked、failed 不自动重发；预算耗尽保留部分处理证据。逐块和跨条款的准确 anchor IDs/input hashes/usage 都有记录，不按前 N 块宣称全文处理。重复语义观察合并所有精确位置，不按 quote 丢掉尾块。

业务 ReviewRun 和调用尝试为不可变技术表。另用不可变 operation records 保留预确认 intake 成功/失败/修复/unknown 与结束时当前性/授权拒绝的已执行尝试，不制造 current ReviewRun。读取均核实际案件权限，raw 只经受保护读接口取得。记录加入 caller transaction、无隐藏业务 commit；caller catch 后 commit 可保完整失败记录，外层 rollback 仍会回滚。这个 mock 事务模型不保证真实外部账单的耐久性，未来真实发送需要另行受控的账单持久化边界。
