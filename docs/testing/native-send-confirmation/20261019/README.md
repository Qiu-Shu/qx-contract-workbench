## 验收覆盖及修正记录

实际路径使用真实 Electron 主入口、Windows 系统保护存储、隔离合成中文资料目录和实际 Python 服务。验证：只配置不授权；取消零登记；原文中的 HTML 标记仍为文字；确认期间另处改变已保存草稿会阻断旧输入；同一明确批准通过原队列得到内部待核草稿与回执；刷新历史不重发；所有原生窗口保持隔离设置；退出后数据库完整性和记录数量准确，合成密钥不进入普通文件或日志。

作者测试和独立探针另覆盖7个scope维度、composer、文字/技能改回原值仍属新编辑、附件、页面切换、子frame/其他窗口、旧后台、恢复副本、重复点击、取消、cookie变化、过期配置、错误回包、撤权失败等。只读查询限数字回环、固定路径、5秒/262144字节，拒绝重定向与异常内容；任何模糊授权终止对应旧后台，不用新请求身份自动重试。

保留失败证据，不将中间轮计入最终通过数量：

1. 新接口/模块缺失产生初始RED；旧预算耗尽状态被协调层过早拒绝的行为RED已修正，现在可重新进入明确批准，原材料和版本边界不变。
2. 首次实机在Enter取消时，窗口立即销毁，CDP输入确认报TargetClosed。驱动仅在目标已关闭时接受该特定结果，随后仍验证草稿保留、授权未产生和零POST；不是忽略产品失败。
3. 第二次实机已完成回环和历史，但测试网络计数为0。查明实际供应商使用 `httpx2`，旧计数只覆盖 `httpx`；现在两套transport均设白名单/外网阻断。最终回环请求恰好1、外部0，由服务端POST和数据库记录交叉确认。
4. 独立P3指出前端声称窗口显示“当前范围”，而四字段窗口只展示文字/接收方/模型/费用；已收窄提示，不冒充显示案件名称。全scope后台核验一直保留。第一轮关联测试162通过、1失败于旧文案正则；该轮输入变化和失败保存在 `before-wording-test-*`，最终163全绿。
5. 视觉检查发现默认取消焦点可能把最小窗口滚到底；新增回归先失败，改为 `preventScroll:true` 并去掉 HTML autofocus。最后实机验证初始scrollY=0、费用可见且取消仍有焦点。
