## 服务接口与T04接入

```python
from cn_contract.documents import ingest, parse_document, resolve_anchor

# database来自服务明确配置，actor来自实际会话，file_stream为当前获授权上传流。
with database.session() as db:
    version = ingest(file_stream, upload_meta, actor, db=db)
    parsed = parse_document(version, database.settings, actor=actor, db=db)
    span = resolve_anchor(parsed.anchors[0], version, actor=actor, db=db)
```

前三个位置参数保留规格约定。`db`是T02 Database绑定的SQLAlchemy Session；parse/resolve另需明确actor。无全局默认数据库，不能传入客户端storage绝对路径。parse/resolve每次先`read_version`重取可信同案版本，随后`read_original`授权并核对实际原件byte_size/hash；不采用调用者伪造storage_ref/mime/hash，也不以缓存免除授权。resolve重新解析已校验原件，严格核对版本UUID、结构路径、anchor UUID、原文/hash、offset和坐标；错位、改quote、冒填新ID或跨版本均返回VERSION_CONFLICT。不存在模糊原文搜索或替换。

Anchor示意（实际DTO严格字段来自domain.py）：

```json
{
  "part_name": "word/document.xml",
  "element_id": "body/tbl[1]/tr[1]/tc[1]/p[1]",
  "kind": "table_cell",
  "quote": "付款100元",
  "start": 0,
  "end": 6,
  "table": 0,
  "row": 0,
  "cell": 0,
  "page": null,
  "bbox": null
}
```

这是字段子集示意，完整实例另含稳定id、document_version_id及精确UTF-8 quote_sha256。offset采用此段/单元内Unicode字符串`[start,end)`；本次提取完整段，因此start为0。同一个单元中的多个段落有各自p序号；跨run直接拼接原字符（不strip/normalize），tab/换行保留。table/row/cell为物理OOXML零基序号；引用锚点不能仅靠quote去重。纯表格合并/渲染布局和文本框等自动修改属于T09人工边界。

ParseResult没有新增DTO字段：PDF逐页状态放在parts的`page:N:read/manual/unsupported`，pages包含实际每页编号。扫描/空白无可靠文字层页列`unsupported_parts=("page:N",...)`及`OCR_NOT_DEPLOYED:page:N`；不会吞掉尾页或读取前N页后返回整体完成。页Annots/复杂交互/不可见文字标manual及对应unsupported/quality，PDF native表格单元含独立路径、原文、page和bbox。`read`表示文字层已提取，不是视觉一致性证明；图片、字形、透明度、遮挡、字体映射、复杂版面均未完成全面渲染/OCR校验。

T04须保留ParseResult所有parts/unsupported_parts/quality_issues，并结合事实的具体anchor决定缺口影响；不能仅因anchors非空宣布完整材料或已确认事实。未读附件、文本框、隐藏文、既有修订、未知对象和PDF手工项仍为缺口。原登记DocumentVersion保留pending及不可变原件；parse_document每次追加独立快照，不覆盖旧ParseRow，不擅自把Matter推进parsed/ready或宣称律师确认。

## 安全边界与实际支持

- ingest先实际会话/角色/成员授权及案件配额预检，再读取有界流；单文件50MiB、案件20文件/200MiB，所有配置只能收紧。T02 BEGIN IMMEDIATE和条件计数UPDATE保留事务并发边界。
- 仅扩展名、MIME、魔数一致的docx/pdf。docm/zip拒绝；文件名只作显示/类型判断，原件服务固定UUID地址，与原名中的路径无关。
- ZIP不extract，不信任中央目录file_size或ZipExtFile的截断行为；核对EOCD/中央目录范围、local header、flags、名称、压缩类型、实际raw deflate载荷、CRC/eof及声明大小。stored/deflated以外、ZIP64/分卷/异常padding/非法flags不支持。实际解压总量最多200MiB、成员及总比例最多100倍；限制10000 entries。路径穿越/绝对/drive/UNC/反斜杠、符号链接、规范化重名、加密、宏部件/宏content type均拒绝，不写出ZIP成员。
- 所有XML部件通过defusedxml禁止DTD/entity/external解析。正文/表格支持明确结构；页眉脚、脚尾注、批注、图片、文本框、隐藏文、样式/编号、未知OOXML及嵌入内容均列未支持清单。关系部件只解析元信息，不加载外链；docProps二进制缩略图是未读部件。
- 有既有修订时meta.baseline_view必填，即使选original也检查实际handling/reviewing律师成员的confirm_baseline授权，并追加baseline_selected审计。original/rejected选旧文，accepted选新增文，不混入删除条款；复杂修订仍人工项。confirmed_custom缺少实际view工件时返回零anchors+CUSTOM_BASELINE_ARTIFACT_REQUIRED，不把原文冒作自定义基线。
- PDF超过配置页数即FILE_LIMIT；按PDFPage.create_pages逐个构造pdfplumber Page，最多构造获准页数，发现第N+1页立即失败，不使用库的全量pages/close再次物化路径。chars、extract_text、find_tables及单元bbox接口真实执行。文字渲染检查采用锁定pdfminer的解析textstate；模式3/7及clip模式为manual，无模型/云OCR。输入字节与页数有界；没有完成独立PDF流内解码内存/CPU沙箱或生产渲染兼容试验。
