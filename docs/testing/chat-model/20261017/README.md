基线 `114a1ab`，沿 `codex/contract-review-v2`；本片完成工程验收，仅使用独立合成资料、本机回环和假凭据。页面发送和真实模型仍未开放。

## 已实现的边界

新增独立的主模型协议、受信策略、单次调用账本和运行器；保留现有合同引擎、统一业务 DTO、账号权限与恢复隔离。完整规范化请求保存系统提示、输出契约与消息来源；输入、配置、预算和归属不可覆盖。旧 queued 消息不会因升级获得外发资格。

主链为：明确授权的消息→预占→一次性 claim→事务外网络→费用回执→当前权限与版本复核→内部待核候选。传输只提供一条 DeepSeek HTTP 路径，复用已锁定 httpx2 2.13.1，没有新装 SDK。Jev、模型设置、页面发送、附件外发、自动档案与具体法律技能仍未接通。

未 claim 的取消释放额度；已发送或无法确认是否发出时保留未知。收到 usage 但正文无效／权限已变时仍记费用；超额回执不丢弃、不归零、不阻止历史备份，但会阻断后续超预算发送。估算金额不是供应商确认账单。普通重启与 qxbak 恢复均不补发旧请求；恢复副本保持只读。cnbak 对非空模型历史明确拒绝，防止漏备。

## 独立复核与实际失败记录

1. 计划审查补齐整个实际请求的不可变证据，避免只记录用户文本却遗漏系统提示和输出契约。
2. 服务审查实证三项并关闭：已结算超额后排队请求仍发送、发送前取消不释放额度、案件撤权审计结束事务后结算未重查恢复 fence／claim。
3. 传输复核补配置快照：运行器传递 claim 时配置，适配器先核对当前配置，再使用独立快照组装完整请求；不因在途设置变化切换模型或提高输出量。
4. 费用补强经有效失败验证：应用层拒绝超预占范围正文但保留使用量；计费与 DTO 校验隔离调用者 Decimal 精度；极大无效计数不伪造费用。
5. 备份独审实证事件序号断档仍可恢复，修复后全 run 事件先验证连续编号；两项有效 RED 后新备份文件 54 项通过，原独立探针在备份前被拒绝。

辅助失败单列：早期缺失类导入、测试错误属性名不算业务 RED；依赖清单漏同步 root_requirements 导致一次开发门失败，补齐既有版本声明后通过。首次构建在源码尚未冻结时中止；事件补丁前的成功冻结验收亦只覆盖其历史快照。

最终双轴独立复核范围内无未关闭明确问题；[服务审阅](service-independent-review.md)、[备份审阅](backup-independent-review.md)、[schema审阅](schema-independent-review.md)、[低精度独立探针](independent-low-precision-report.json)。HTTP下一片准备亦经只读复核，无必须更正项。最初汇总脚本要求全套零跳过而退出1；随后明确保留原两项skip，并按完全相同测试身份核对独立环境补验，不篡改原JUnit。
