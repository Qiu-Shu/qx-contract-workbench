# 首批法律方法对照验收包

本包准备六个虚构场景的相同材料与两组请求，供检验新方法是否值得保留。用户已明确暂时没有律师，由 Codex 负责评分并安排独立 AI 复核，不再以律师评分作为开发验收前置。本准备包只有输入和空表；实际 AI 初评另存运行记录，工作台真实模型、律师评审、法律标准答案状态分别保留。

## 对照范围

| 场景 | 方法组 B | 主要检查 |
| --- | --- | --- |
| chronology | Chronology，经 case-evidence-v1 适配 | 多材料时间线、矛盾、日期不确定、来源定位 |
| brief_section | Brief Section Drafter，经 case-evidence-v1 适配 | 实质文书草稿、事实与主张、引用、缺项占位 |
| criminal_case | Criminal Case Analysis，经 criminal-analysis-v1 适配 | 证据链、矛盾、定罪与量刑区分 |
| defense_strategy | Case Analysis + Defense Strategy，经 criminal-analysis-v1 适配 | 要件与双方观点、阶段限制、待核策略；不单独归因于 Defense |
| commercial_review | Commercial Review，经 contract-review-v1 适配 | 同任务主协议及附件分流、供应方立场、NDA 与未覆盖 DPA |
| trademark_triage | Infringement Triage，经 trademark-triage-v1 适配 | 仅商标八因素、双方线索和缺口；其余权利没有纳入 |

A 是当前保留的通用案件材料协议；合同 A 保留 C4 方法。B 使用已接入的方法提示、方法快照和结构化输出协议。两组问题、材料、来源标识、任务标识、模型占位名及输出上限相同；方法与格式作为整体变量。**这不是整个历史 0.6.0 与当前产品的比较，也不能把差异单独归因于某一段提示词。** 本包不加入能力注册、知识检索、历史会话或完整桌面流程；这些能力在前四批分别验证。

六个场景是公开的开发材料，不是盲藏测试集；两组民事场景共享材料，两组刑事场景共享材料。结果应逐场景解释，不能按六个独立案件宣称统计显著，更不能代表所有合同、犯罪类型或知识产权类型。

## 本包内容

- `inputs/`：原始段落 JSON、便于阅读的材料 Markdown、来源标识索引。所有内容均为独立虚构。
- `coordinator/requests/`：12 份只在本机生成的请求样本，A/B 各六份。它们没有发送回执。
- `coordinator/source-snapshot.json`：生成时源码与资料摘要，用于识别方法版本变化。
- `reviewer/checkpoints.md`：材料核对线索及逐字定位；不是法律标准答案，只交给评审者。
- `reviewer/rubric.md`、`reviewer/scorecard.md`：评分规则和空表。输出产生后，再分配匿名 X/Y 标签。
- `status.json`：模型与律师结果保持 `NOT_RUN`，分数为空、保留决策待定。
- `sha256.json`：本包其他文件的 SHA-256；清单自身不递归计入。

输入的引用锚点由本机段落构造，`original_sha256` 对应各份段落 JSON，`result_sha256` 对应段落数组。它们**不代表完成 DOCX/PDF 上传、解析、数据库授权或模型发送**，不得导入生产请求表当作已授权材料。Markdown 是阅读副本，段落 JSON 是本包的输入源。阶段 A–D 的真实材料处理与合成传输检查见各阶段报告，不能写成这次新包的运行结果。

## 生成与核验

在主仓库目录执行。每次使用新的输出目录；脚本不覆盖已有记录。

```powershell
.venv/Scripts/python.exe -B -X utf8 scripts/prepare_legal_method_ab.py --output .audit-local/legal-method-ab-20261101/package
.venv/Scripts/python.exe -B -m pytest tests/unit/test_legal_method_ab_package.py -q -p no:cacheprovider
```

脚本只加载仓库固定虚构资料和现有请求构造函数，不读取本机账户、密钥、业务库或真实材料，也没有发送、自动评分或安装入口。配置中的模型名和虚构费率仅用于既有协议的离线构造，不能作为真实报价。生成后应核对文件摘要、六组相同事实输入、方法选择、评分空白状态。源码或资料变化后另建版本，保留旧包。

## 后续验收操作

1. 由 Codex 固定材料核对点、七维评分口径和判定建议，独立 AI 复核；记录评审来源、日期、修改版本。不要让生成答案的代理看到评分线索或预期偏好。AI 初评可以推进开发，但不替代正式法律成果的审核与签发。
2. 工程人员准备经授权的隔离评测入口，采用现有材料导入、授权、请求、结果校验、费用回执和导出链路。不得直接把本包 JSON 发往服务商，或为了比较而关闭业务权限。当前没有针对本包的真实模型发送器；伙伴模型接口仍为待办。
3. **两个刑事场景仍受 synthetic-only-v1 限制。** 包内 A/B 都只准留作离线构造与本机合成协议检查。模型预算授权本身不能解除该限制；需另行完成并批准刑事材料政策与执行链路，才能安排真实模型质量比较。其他场景也需明确模型服务、合成材料范围、次数和费用预算后运行。
4. 正式运行前冻结模型及版本、可用参数、相同输出上限、时间窗、检索范围、工具权限、材料摘要。不得把首次未读材料补入某一组而不更新另一组；每组使用独立空会话。固定重复次数与顺序后再看输出。建议每场景每组 3 次并交替先后；这是建议，尚未批准或执行。
5. 每次记录：场景、组别、重复序号、模型版本、请求/响应摘要、请求 ID、实际方法快照、开始与结束 UTC、完成/截断/失败/超时/未知、用量、实际费率、成本、重试记录、成果版本、原始及呈现输出。失败和截断计入分母，不挑选最佳输出。未知结果沿现有流程查询原请求，不自动重发。
6. 原始响应先按各自协议验证；不通过的记为协议失败，不代修答案后评分。A 的 text/citations 与 B 的后端派生文本统一为相同版式提供评审；保留内容及引用，隐藏方法名、内部格式和组别。协调人随机分配 X/Y 并单独保存映射。结构可能泄露分组，因此只能称尽量减少偏见，不能保证完全盲法。
7. Codex 与独立评审查看相同原材料、匿名输出与核对点，逐项记录错误出处。未提供输出时保持空白；输出虽缺内容则按规则记 0，不混为未运行。引用原文吻合不等于引用支持结论；法律条文、案例和效力须另以当时权威来源核实。无法测得的费用与审阅用时标记未知，不编造。
8. Codex 汇总配对结果、失败率及可得的成本和用时，核对分歧后逐场景提出开发保留、修改后复测或停用建议。没有明显改善、出现新增重要错误，或样本不足时，不写“已提升法律质量”。

当前会话可先做四个非刑事场景各一组的 Codex 内容冒烟对照，记录 `execution_mode=codex_subagent`。代理读取请求中的系统方法和材料并生成候选，保存后再由既有协议校验和独立 AI 评分；这不执行请求 JSON 中的 deepseek-flash，不是桌面或伙伴模型测试。服务商请求 ID、Token、价格和账本成本不可得时标 `NOT_AVAILABLE`，不能套用占位费率。只有一次、同一模型家族、上下文与工具环境不同于正式运行；结果只用于发现问题和安排下一步，不代表稳定提升。两个刑事场景不在此生成范围。后续正式配对运行仍按上述固定预算和政策流程执行。

当前不扩充第二批 Skill，不更换客户接待能力，不运行真实模型或微信，不签发或发送任何成果。
