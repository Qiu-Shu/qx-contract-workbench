## 已实现范围

位图 OCR 和 PDF OCR 入口共用进程内非阻塞锁与 Windows 文件锁。锁取得后才执行完整资产/环境核验、PDF 渲染、模型暂存和隔离推理；忙碌调用返回 OCR_BUSY。原有 bytes/metadata 调用兼容；新增延迟准备回调仅在内部服务使用，不是客户端提交的代码或跳过校验参数。

核验、准备、暂存、原生启动、超时、输出校验及成功返回均退出准入范围。文件句柄上下文与外层 finally 分别释放跨进程资源和进程内锁。案件授权、幂等回放、保存前来源/版本及成员权限重检保持原位。模型/资产全量哈希、许可检查、Windows AppContainer 和资源上限保持不变。

### 下一增量的具体依据（尚未实施）

`ocr_worker.py` 使用工作目录内的 ASCII 相对模型路径，原因是原生 Paddle 文件读取器不能打开当前工程的中文绝对路径。因此不能直接删除复制步骤或简单改回共享模型绝对路径。单页复制耗时仅约 0.035 秒，暂不足以支持把它当作主要延迟来源；但副本持续保留是独立的磁盘占用问题。

后续先定义每任务可写目录的配额、正常/失败终态的保留策略、清理失败的显式阻断，再验证目录边界与重解析点拒绝。历史目录不自动一刀切删除。完整核验本次约占总耗时 55%，需分别测量冷/热条件并验证资产篡改仍会失败后，再决定是否引入受控缓存。PDF 页面解码目前仍在父进程，必须单独落实时间/内存/异常终止隔离，当前 OCR worker 隔离不能替代它。
