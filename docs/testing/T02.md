## 服务接口和事务边界

```python
database = Database('sqlite:///approved-local-development.db', service_storage_root, settings)
with database.session() as db:
    actor = authenticate(server_generated_cookie_token, db)
    version = create_version(meta, actor, db, content=file_stream)
```

`Database`必须显式传SQLite URL、服务控制的原件根和Settings；不存在隐藏默认数据库。`database.session_factory()`供后续服务注入，Session.info绑定本Database；调用者自行管理commit/rollback/close。`database.session()`在成功时commit，异常时rollback。原件按真实root/nested SessionTransaction登记：savepoint提交仅将本层文件所有权转给父层，savepoint回滚仅删除本层新文件，root commit保留原件，root rollback或未提交的Session.close删除本层新文件；不因嵌套after_commit提前丢失清理记录，不因嵌套rollback误删父文件。Settings从实际model_dump重新校验并用canonical_json重算真实配置hash，不能通过model_copy启用QCC或伪报旧hash。

`create_version(input, actor, db, *, content)`保留规格前三个位置参数，内容流为新增关键字参数。缺流、空流、缺baseline、错案前继、超配额和归档案上传明确阻断。授权先于读取/hash；原件地址固定为`matter_id/version_id/original.bin`，与客户端文件名、路径或全局hash缓存无关。原件独占创建、实际分块hash及大小核算、fsync后设置只读。事务失败只删除本次已核对根内的新建原件及空版本目录，不递归清理、不改已有原件。流故障及调用者事务异常均有实际回滚测试；突然断电/crash的原子恢复尚未实现。

SQLite连接启用外键，每个事务使用BEGIN IMMEDIATE。并发文件数及总bytes配额由条件UPDATE核算，两线程实际验证只能一个成功。此处是规格规定的单应用实例SQLite试点，不支持多容器/网络共享SQLite，也没有PostgreSQL迁移验证。

`authorize(actor,matter_id,action,db)`每次重新读取会话、用户真实roles及membership，拒绝客户端Actor.roles、未知action、会话撤销/过期/禁用、错用户、错案与不存在案件。admin仅有管理角色时没有正文特权；assistant成员仅能读、材料和候选事实操作；确认事实/立场/baseline须真实律师角色；`approve`须reviewing_lawyer且membership.can_sign。动作授权仅是T09的前置权限，不能自行签发。

拒绝事务边界：先rollback整个调用者事务（包括尚待提交的业务变更和新原件），再保存并commit一项独立短拒绝审计，最后抛统一ServiceError。外层HTTP错误rollback不会抹掉这项审计；用例也证明拒绝日志不能顺带提交原来的业务标题修改。AuditRow攻击目标ID不设业务外键，以记录不存在UUID；文档、会话、成员及其他业务表均有外键。

`append_event(event,db)`仅接受受控action/entity_type，自由reason仅存SHA256，保留必要UUID、hash、UTC时间和correlation_id；不保存原始reason、测试密钥或完整正文。原件版本、追加审计、解析和事实快照有数据库UPDATE/DELETE拒绝触发器；不声称数据库管理员无法移除触发器或改文件。每日签名归档/哈希链与生产审计策略属于后续部署任务。

HTTP接入调用`configure_app(app,database)`、`get_db`、`get_actor`及`require_matter(action)`；cookie名`qx_session`，写请求header为`X-CSRF-Token`。所有Actor来自服务生成opaque会话token的数据库查询，不接受X-user/X-role。`service_error_handler`输出code/message/correlation_id/retryable，不含堆栈或敏感路径。实际FastAPI TestClient验证伪身份header、缺/错CSRF、拒绝无业务改动且审计保留、正确CSRF能写。登录/管理路由、HTTPS部署、cookie设置、限流和完整生产认证流程仍由后续HTTP/部署任务完成；T02没有对外服务。

`provision_user`、`provision_matter`、`set_membership`、`remove_membership`、`revoke_session`是可信服务初始化/管理原语，**没有注册为客户端接口**。默认无账号，密码用pwdlib维护的Argon2id实现，会话/CSRF仅存hash、8小时过期；开发测试不等于用户管理生产上线。

## T03/T04/T09接入与限制

- T03：先`read_version(matter_id,version_id,actor,db)`和`read_original(...)`重取可信元信息及hash核验原件；`save_parse_result(matter_id,result,actor,db)`保存独立追加ParseResult，`get_parse_result(matter_id,version_id,actor,db)`取得最新追加快照或None。原DocumentVersion保持登记时pending，不修改原件或旧版本字段。baseline实际律师动作`confirm_baseline`和审计`baseline_selected`已注册；既有修订识别、魔数、部件/锚点可靠性属于T03，不在T02假称解析完成。
- T04：`save_fact_snapshot(matter_id,snapshot,actor,db)`、`get_fact_snapshot(matter_id,version,actor,db)`保持T01 tagged FactValue、Decimal字符串和单位。`fact_snapshot_sha256(facts)`约定sorted compact UTF-8 JSON list；后端核对hash、同案归属与顺序版本。候选使用candidate_facts，包含confirmed/corrected则使用confirm_facts；确认人须当前实际律师，或保留完全一致的已存历史确认（只改变version）。`set_position(matter_id,position,actor,db)`及新原件/事实使旧批准stale、旧export标记superseded并回到相应步骤。完整事实选择、锚点归属、客户端决定与并发期望版本由T04接入补齐。
- 状态：`transition_matter`拒非法跳转和归档后的材料变更；合法步骤可流转，但进入approved明确NOT_IMPLEMENTED，避免登录或状态边自动形成签发。事实变更只回到awaiting_fact_confirmation，不自动宣称ready或已确认。
- T09：ApprovalRow/ExportRow以及`read_approval`/`read_export`是基础存储与读取，已有制品只改变superseded标记、不覆盖内容snapshot。测试直接插入独立虚构审批/制品来验证失效机制，不存在T02正式批准写API。完整manifest核验、双审、例外、费用批准、正式制品、幂等及律师签发尚未实现。
