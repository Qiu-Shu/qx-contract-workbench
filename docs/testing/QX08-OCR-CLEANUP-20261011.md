# QX08 第二增量：任务临时文件治理

日期：2026-10-11。基线 9247c0cfcda7942840e61cc37d7b7e89ea166cfa。只使用独立虚构数据；保留既有架构、完整哈希与许可检查、现有授权/来源重检和 AppContainer。

## 实现结果

新 OCR 任务使用 `managed-<32位hex>` 工作目录，沿已有串行准入执行。成功或普通失败结束时，在隔离进程终止确认后，先有界盘点整棵临时目录，再删除本任务文件。原件存储、候选数据库、审计记录及历史 uuid 目录不在清理范围内。

路径检查拒绝越界、软链接、目录联接、硬链接及不规则文件；删除每项前再次验证。盘点限制为 4096 项、16 层。清理不是“忽略错误后继续”：删除失败、隔离清理未确认或新制式目录残留时返回 OCR_CLEANUP_REQUIRED；下一请求在资产核验前被拒绝，不自动删除残留或累计第二个任务目录。工作台增加中文阻断提示。

运行预算为 256 项、128MiB，覆盖暂存后、隔离等待循环和输出消费前；运行前可用磁盘空间要求至少 256MiB。这是轮询软预算和可用空间检查，**不是硬磁盘配额、独占预留或瞬时写入上界**。越过轮询间隔的突发写入、外部进程占满磁盘、应用强杀仍可能留下残留；残留会阻断后续识别。

隔离清理确认包括：终止 Job Object 与子进程、等待子进程结束、查询 Job Object 活动进程归零、撤销权限及删除临时 AppContainer profile。授予前即登记撤销责任，避免部分授予后超时漏清理。运行范围不保证抵御同权限本机管理员恶意并发替换文件系统；遇到可见异常则拒绝清理。

Windows 结构和语义核对依据：[Job Object 基础统计](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_accounting_information)、[Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)。采用 ActiveProcesses 检查，不能把普通 Job Object 等待事件误认为任意终止场景下的清零证明。

## 运维与剩余范围

出现 OCR_CLEANUP_REQUIRED 时，普通使用者停止重复识别并联系本机维护人员。维护前保留失败目录及必要诊断；先核实应用实例、活动进程和相关 ACL/profile 状态，再决定有记录地恢复。仅清空标记、改目录名或忽略错误继续调用都不能代替核查。此增量不提供一键绕过或自动历史清理，也不销毁旧证据。

QX08 仍待：PDF 解码全过程隔离、冷/热与多进程压力和峰值系统性基准、Windows 硬磁盘配额及历史目录治理。新任务退出清理不等于这些事项已完成。未重启旧常驻工作台/插件；真实 DeepSeek、QCC、真实材料产品准入、网页 ChatGPT、正式签发和生产验收边界不变。
