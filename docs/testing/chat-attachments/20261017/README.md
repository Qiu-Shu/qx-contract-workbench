# CH-03A：建案前 DOCX 收件、原文回查与原生恢复

基线 `00b106c`，现有 `codex/contract-review-v2` 分支；仅使用独立合成材料。范围以[经复核的材料实施计划](../../../plans/2026-10-17-conversation-materials-readiness.md)为准。本文记录本阶段已完成的工程验证与本地提交证据；不代表 CH-03 全部完成或安装版已更新。

## 实现范围

对话可独立接收 DOCX，无需先创建合同案件或接待事项。选择文件或取消选择不建空记录；实际接收才创建对话。附件原件、解析修订和本次材料集合分别持久化，原件只读、历史追加。移出本次材料不删除原件，重新读取保留旧解析版本；上传不覆盖律师正在编辑的文字。所有读取和写入仍核验当前用户、对话及绑定业务权限。

首页新增文件选择、本机处理确认、材料列表和原文面板，沿用原生 ES 模块与已有设计。原文用纯文本呈现，显示精确部件／段落、读取修订及待核实状态；复杂对象及未读项继续展示。含修订的文件须先选择基线。超过 100 段的展示按批展开，后端仍保存有界完整结果。关闭原文、切换对话、撤权后，迟到解析不能重新打开旧材料。

业务 DTO 仍集中在 `domain.py`；收件、文件、记录、归档校验与 HTTP 分别在独立模块。`app.py` 仅装配路由并允许新静态模块，未增加第二套解析器、身份系统、前端框架或运行依赖。上传接收、DOCX 解析均在 SQLite 写事务外进行，提交前再查权限／完整作用域；相同请求先找原回执，再对新请求检查版本和配额。网络结果未知时按原请求身份对账，不能换键重传产生重复材料。

原件准入复用服务器上传大小和 ZIP 限制。每对话最多 20 份／100 MiB，若既有服务器限制更低则采用更低值；单材料最多 64 次解析，单解析 JSON 上限 64 MiB、会话累计 100 MiB。超限或解析失败保留原件和明确状态，不将其当作已读内容。开发普通入口按登记合成摘要限制；既有原生本机模式还须本次明确勾选本机处理，外发字段固定为 false。

数据库新增 `assistant-attachments-v1`，冻结旧 `assistant-v1` DDL，不改写旧迁移历史。三张新表均有不可变更新／删除保护，已知旧库按既有受控链升级，未知或残缺 schema 拒绝。原生 `.qxbak` 保留附件原件、所有解析及材料快照，核对身份、摘要、版本、时间先后和引用关系；恢复副本可核对原文而禁止上传、重解析、调整集合。`.cnbak` 保留原合成合同契约，对非空对话附件明确拒绝，避免静默漏备份。
