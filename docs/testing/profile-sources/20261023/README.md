# CH-07B1 档案来源重建：Windows 源码证据

2026-10-23（北京时间），基线 `0eb341a2d25da88b05ac4b62f16d45a77a6a140b`，现有分支 `codex/contract-review-v2`。全部测试使用独立合成数据库、原话和DOCX。

## 已实现

`assistant/profile_sources.py::read_profile_sources` 复验 ProfilePatch，再按实际引用ID从当前授权会话重建 ProfileSourceSnapshot。它给已有纯合并内核提供真实存储来源，不信任提案携带的原话、文件摘要或解析内容。

- 最多200个唯一用户消息、20份唯一文档；重复引用去重，超限拒绝。仅重建本提案引用的来源，长会话不整段读取；未引用的未解析附件不阻断本次读取。
- 复用会话所有权、当前角色/会话、案件及接待/投影权限、工作区、归档/恢复栅栏与绑定/输入/材料版本检查。助手回复和未发送草稿不能成为用户原话。
- 附件必须仍被选中且解析版本精确一致，可明确选择历史解析版本；原件路径/大小/摘要与解析摘要检查复用既有实现。部分读取完整保留未读项，失败、未解析、待基线不能作为档案来源。
- 原件读取释放数据库事务，返回前新开事务再检查；并发撤权、转案权限变化、新发送、换材料、归档和恢复会拒绝。仅修改输入框草稿不误拒已发送来源。
- 成功读取不写业务记录/原件；权限拒绝沿用既有安全审计。快照不是未来写许可，后续提交仍需在写事务重新核验。来源定位不代表事实核实。
- 无新DTO/依赖/schema/HTTP/UI或模型调用；不导入Web、解析器、python-docx或供应商模块。这里只验证依赖边界，不声称启动/RSS/包体改善。
