# 群兴合同审查工作台项目说明

群兴合同审查工作台是一套面向律师的本机合同审查辅助工程，围绕原文核对、事实确认、候选意见、律师处置和 Word 工作稿形成可追溯流程。当前版本用于登记虚构材料的受限开发与验证，尚不能直接用于真实合同办案或正式签发。

## 项目资料

- 私有仓库：<https://github.com/Qiu-Shu/qx-contract-workbench>
- 开发分支：`codex/contract-review-v2`，保留原有提交历史。
- 接手说明：[项目交接](HANDOVER.md)。逐任务事实以[任务实际状态](TASK_STATUS.md)及其测试证据为准。
- 需求基线：[v2.0 实施规格](../sources/specification-v2.0.md)。来源与许可：[上游锁](../sources/upstream.lock.json)。

## 当前已有能力

|环节|已实现的受限工程能力|
|---|---|
|本机工作台|中文网页、个人账户、持久案件库、角色与案件权限、后台任务|
|材料与事实|DOCX/PDF 解析、原件保留、版本锚点、原页核对、离线 OCR、人工转录与来源记录|
|意见与复核|18 维审查框架、人工及插件候选、律师逐项处置、本案法源核验记录和谈判标准|
|工作稿|按受众导出 DOCX、受控原生修订、具体版本确认、修改后有效全文与复审记录|
|本机插件|显式选案、限时只读连接、另行允许的一轮候选提交、幂等与撤销检查|
|工程保障|唯一领域 DTO、Decimal 与单位、UTC、后端权限和批准核验、不可覆盖审计及源绑定|

技术栈为 Python 3.12、FastAPI/Jinja2、SQLAlchemy/SQLite、Pydantic、python-docx 与 MCP；锁定版本见 [pyproject.toml](../pyproject.toml) 和根目录依赖锁。Windows 本机环境承担现有启动与部分 OCR 隔离验证。

## 使用与交付边界

持久工作台目前仅接受 `tests/fixtures/assisted-v1/` 的 12 份登记虚构合同；旧 CLI 演示另有四份固定示例。DeepSeek 仅有离线协议适配，真实模型调用与企查查关闭。法律规则批准、律师金标准、真实身份与数据政策、网页 ChatGPT 接入、正式签发及生产部署仍有阻断。

在已配置的当前电脑上，双击根目录 `启动工作台.cmd`，访问 `http://127.0.0.1:8767/login`。首次账户由使用者在本机交互窗口设置；已有账户及 `.local/workbench` 数据继续使用。详见[启动与账户说明](LOCAL_WORKBENCH.md)。克隆仓库不会带来本机数据库、虚拟环境、OCR 资产或宿主插件安装状态。

最新历史完整工程回归为 2026-10-11 的 1695 项通过；2026-10-12 密码增量为 115 项目标与关联测试通过。2026-10-13 交接时重新执行 159 项相关测试通过。不同日期、范围的数量不相加，也不替代法律质量验收。详见[本次上传核验](testing/GITHUB-HANDOVER-20261013.md)。

## 后续方向

用户希望能够实际使用真实合同。现有[差距记录](plans/2026-10-12-real-use-gap.md)提出本机真实材料工作稿路径，但该模式尚未实施。后续应明确材料政策和实施范围，复用现有权限、事实、版本与导出流程，并保留模型外发、QCC、插件及签发的独立批准边界。同时继续完成 QX05–QX10 中尚未关闭的审计事项。
