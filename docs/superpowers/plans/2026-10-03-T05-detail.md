# T05 有限来源注册、规则批准门与客户隔离

依据 v2.0 §5/7/8/T05；依赖 T04 已授权事实确认和 T02/T03 的真实案件/版本服务。先实际 RED，再实现、目标回归、独立审阅与记录。本计划不是法源核验或规则批准，原件/Skill/网页内容仅作数据。

1. 正式目标 tests/unit/test_authorities.py、test_rule_scope.py 先失败：draft 不参与结论；适用事件日期改变选择；没有通用价款 30% 法定上限；劳动竞业三年线索转专项而不是冒认完整劳动审查；客户 A 偏好不能进入客户 B。
2. AuthorityInput/Authority、Rule/RuleSnapshot/RuleSelection/PolicySnapshot/ApprovalEvidence 复用 domain.py；服务保留规格位置参数并额外传 matter_id、actor、db。不新增同义 DTO，不信任客户端 status/approved_by 或 Actor.roles。rule_id/version 字符串严格转规范 UUID/正整数。
3. register_authority 仅登记本地取得的明确原文/元信息，不根据 URL 自动抓取。实测正文 hash、公布/生效/失效及 fetched_at 区分；登记默认 unverified。虚构来源的服务器分类禁止认证成现实法律，空正文、搜索摘要或不明施行日期不能获批。
4. 来源和规则技术表按版本追加，原文不可覆盖。明确 initialize_storage、实际角色/成员与服务器规则负责人 grant；批准证据绑定规则精确版本/hash、逐源正文 hash、真实当前确认人/UTC、适用性和例外。默认没有真实律师 grant；测试的虚构身份只验证工程授权。未批准来源/规则保留草案。
5. 先注册规格首批 14 张 draft 卡：SCOPE、LIABILITY、LIQUIDATED、ARBITRATION、DATA-NOTICE、LABOR-NONCOMPETE、FORM、DEPOSIT、GUARANTEE、SALES-ACCEPT、SERVICE-OUTPUT、LEASE-USE、NDA-SCOPE、TECH-TRAINING。使用服务器稳定 UUID、正整数版本，四类及 18 维映射明确。卡片不是法律结论；科技专项关闭，尚未核验的中国法索引只登记 pending，不编造法条原文或批准。
6. select_rules 重读真实 Matter、事实快照、政策和登记规则/批准记录，重算规范 hash。types、position、allowed_scope、法域、确认事实、例外和逐规则适用事件日期均核验；未确认例外不能视为不存在。按事实日期检查窗口，不用今天或最高版本替代旧交易时点，不执行 trigger 字符串。
7. 客户政策绑定真实 client_ref、version/hash 和服务端批准。非空未批准 preferences 不进入后续模型上下文；显式无偏好的空政策与已批准偏好区分。变更须使相关当前审查/批准失效，历史原快照仍保留。
8. 无真实批准时阶段/limitations 记录 BLOCKED_RULE_APPROVAL；GateIssue.code 和 ReviewRun.error_code 使用 domain 已有 RULE_UNAPPROVED（实际 code 是 ErrorCode，不能塞阶段字符串）。技术登记不代表法律覆盖或生产完成。
9. 目标回归与受影响核心回归/全套、独立攻击审阅；记录命令、退出码和实际分母，再本地提交。必要窄 core 集成限于真实规则负责人权限读取、审计允许项和失效包装，不重写已完成 T00–T04。

T06 接口准备：后端提供准确 rules/policy hash 和已批准选中规则；无获批法律规则仍可输出有已确认事实与锚点支持的数学/缺件观察，其他维度如实不足/未支持。draft、虚构法源和未批准偏好不得进入运行法律结论。独立只读设计记录在忽略的 .audit-local/t05-t06-preflight.md，不计作测试 PASS。
