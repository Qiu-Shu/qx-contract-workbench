## AEAD归档格式与密钥边界（未执行设计）

- 首发采用已安装AESGCM标准接口，256bit服务端批准密钥、每份新96bit随机nonce；`secrets.token_bytes(12)`及key resolver只能未来执行，本轮均0。密钥解析绑定实际key版本/用途/授权用户和部署，key_ref不能是客户端任意路径/env名；密钥bytes只在受控内存，绝不写归档/日志/manifest/shell。
- 有版本的固定header包含算法ID、备份UUID、恢复域/部署ID、schema/config hash、UTC截点和manifest digest；canonical header是AAD。完整matter/来源/文件manifest及SQLite/制品bytes在ciphertext内，AAD仅绑定其hash以避免明文暴露客户名/文件列表；nonce、key版本标识与长度也认证。改header/body/tag或wrongkey必须InvalidTag且0可见恢复结果。
- AEAD一次调用需要有界完整message；首发明确受批准max_backup_bytes/max_manifest_entries/max_file_bytes/内存预算限制，超限返回阻断，不把AESGCM当无界stream。需要更大备份时另经ADR使用标准流式认证容器/分块AEAD（sequence/final marker/总manifest认证）再测，不能拼自造加密或每块独立tag后漏末块。
- 受控明文临时DB/归档stage必须在批准私有目录/账户ACL内；Windowsread-only属性不是加密或ACL。加密成功、fsync/完整hash核对后才发布新不可变backup UUID；失败只清理此次已核界的stage文件，不能递归删除原库/其他路径；断电恢复留下未完成stage不得当可用备份。
- key不和归档同目录或同访问主体不受控暴露；DPAPI API只是候选且尚未调用，它的账户/机器绑定会影响异机灾备，不能凭key_ref字符串保证可恢复。运维必须有批准的独立key保管/恢复证据；本轮不生成或解封任何key。

## SQLite一致性截面与immutable文件manifest

当前Database engine每次BEGIN都BEGIN IMMEDIATE，source originals由create_version先新建/fsync、后DB记录，caller rollback/Session.close清理未提交文件。不能用`.db`简单copy、从ORM已打开写事务调用backup，或认为hash列表等于一个真实截面。

首发选择明确**维护窗口**，不宣称无停机在线全仓快照：

1. 服务器维护登记暂停新写/新job/新dispatch，单worker确认已无网络in-flight；遗留dispatching先持久unknown，unknown仍占预算/次数。停掉retention/垃圾清理，不让snapshot引用的文件在采集中删除。所有caller Session完成或rollback/close，记录checkpoint；不借维护令牌提升律师案件读取权。
2. 从`database.engine.url.database`提取已批准本地文件SQLite绝对路径，校验与该Database配置一致；拒绝不存在、`:memory:`、任意UNC/shared位置。独立stdlib sqlite3源连接以mode=ro打开、目标连接只指新stageDB，不走SQLAlchemy begin hook、不借活跃Session/raw uncommitted connection。
3. 调用source.backup(target, pages=受控值, progress=计数/时长检查)。SQLite backup负责journal/WAL一致性，不拷主文件忽略WAL；BUSY/超时/源异常是失败，不能sleep无限等锁/记PASS。maintenance不意味着持有SQLite写锁，source/target连接都明确关闭后才进入文件加密。`SQLAlchemy.raw_connection`绕hook的隐含事务风险避免成为默认方案。
4. 以目标SQLite副本中已提交行生成canonical manifest：每件内部UUID/所属matter、技术role(type/original/export/raw evidence)、精确相对storage_ref、byte_size/SHA256、关联immutable版本/批准/来源；T05 source_evidence bytes在DB，本身也在行digest。只枚举DB实际引用文件和阶段明确存储清单，不把未提交孤文件/.env/key/整个repo缓存打包；缺被引用文件、重复/别案归属、未知raw ref应失败。
5. 从本案trustedread或受信系统backup权限读取original/export/raw store，检查安全路径/size/hash再复制新stage，不改变源bytes。DB snapshot inventory决定当时批准/activefacts/policy/rules/run/ledger/job截面；T05 snapshot sha包含metadata/批准/来源，policy_runtime_sha不同于内容sha，不能简化成文件名hash。捕获已停止维护期间外部修改则fail。
6. 关闭快照连接、认证归档并保存server BackupRecord（UUID/ciphertext SHA/header/manifest/schema/cut UTC/恢复域/实际操作人）。源维护屏障按明确运维步骤解除；本轮未设置任何屏障或backup记录。

若日后做online backup，SQLite consistency只覆盖数据库，不自动覆盖磁盘删除、runtime secrets/记录；需单独versioned immutable store/retention pin/读者fence及跨store测试再ADR，不能悄悄替换上述维护合同。

## 受控新目录恢复与服务级核验

1. 从批准backup登记解析固定归档路径/ciphertext hash/key用途/restore授权，reject纯路径/客户端hash即approval。恢复父目录server限定；生成全新UUID子目录且不存在，resolve目标在父内、与源DB/storage/backup目录不同。先验证文件上限/header/认证，不extract任意zip；若容器包含archive，逐entry名单/长度、压缩ratio/总量、Windows安全路径、重复归一化名必须严格检查。
2. 禁止`..`、absolute/drive-relative、UNC/`\\?\`/device路径、colon ADS、NUL、Windows保留名/尾随dot-space、slash/backslash混用、大小写collision、symlink/junction/reparse/hardlink逃逸；manifest路径由内部UUID/已知类型生成。`Path.resolve/is_relative_to`仅一层检查，不保证防TOCTOU；stage父ACL排除非可信写者，读/写安全句柄核对最终路径。当前只规划，未改变ACL。
3. 将认证明文仅放private quarantine新目录，不mount为web/static，不自动启动worker。用raw SQLite检查schema version/完整required表/真实trigger SQL，与受批准schema/migration registry对照，再`PRAGMA integrity_check`/`foreign_key_check`；FK=ON必须每个新连接设置。先检查再Database构造，避免Base.metadata.create_all/IF NOT EXISTS自动补表/假同名触发器掩盖坏archive。
4. exact immutable触发器/外键合格后构造**独立**Database与已核settings，显式各阶段storage.initialize_storage恢复Python服务flag。必要升级只能批准的迁移、更改单独记录，不能以“补触发器后成功”抹去原差异。实际SQL UPDATE/DELETE拒绝测试验证行为，不仅数trigger名。
5. 对恢复manifest全部files/DB行digest、DocumentVersion.original size/hash、Parse/Fact完整版本、Authority source证据、RuleSnapshot含依赖/Policy runtime SHA、ReviewRun/18维、Audit append-only、exactpatchset/Approval/ExportArtifact bytes、QueryPlan/receipt/ledger/price/job作数量和hash对账；不因missingfile/unknownstatus跳过。T08/T09/T10未交付时不能虚构调用次数或helper存在。
6. 先确认恢复内容与备份截面完全一致，再实施明确**安全启动delta**：全部Session.revoked=true、所有provider出站默认off、worker不自动领queued/running、current正式批准/制品处隔离待当前证据复核状态。历史签发者/时间/字节不覆写，隔离/stale/会话撤销事件另存；期望delta与真实差异分开，不将安全delta伪称字节损坏，也不借恢复复活旧角色/grant为当前ops权限。
7. 以真实重新登录/实际server member+role调用read_original/read_version、T04trust、T05read_rule_snapshot/policy_runtime、T08余额/次数、T09download/approval与T10job读取，核验0外发及原库仍可独立读取。DRAFT/MOCK保持原水印与限制；原件未变、旧批stale、篡改制品不能下载。恢复可解密但服务失败、缺证据或余额不符都不能BackupReport.ok=true。

BackupReport没有backup_created状态，restored_at只在真正完成新目录服务级恢复后填实际UTC；本轮不构造假report。格式拒绝可用受控ServiceError/ValueError，真实核验结果用ok=false/differences逐项列精确ID/hash/计数；避免塞不存在BACKUP_*枚举。日常仅创建备份不可调用backup_and_verify却声称已验证恢复。

## 防重放、未知付费与授权回滚

AEAD确保authenticity而非“这是最新”或“恢复过一次”。合法旧archive可能在发送前截点，restore后预算看起来空，但供应商实际已收费；已撤销会话/member/grant、过时法源、旧有效Approval也可能复活。

- 需备份之外的**当前可信恢复登记/checkpoint**，绑定恢复域、备份UUID/序列/ciphertext hash/维护截点、最新不可逆dispatch/账单高水位和明确restore授权；受保护实际ops身份/批准服务核验，不接受同archive内自带assertion。重复恢复同操作ID幂等，改backup/key/domain/hash拒绝；lower sequence默认拒绝，灾备回退需明确批准且保持外发fence。
- 恢复源中的permission/approval记录只证明备份时历史，不是当前部署操作批准。会话均撤销、需要新登录，当前成员/职责/许可/法源/对外scope按独立现状复核，严禁自动恢复签发能力。
- T08已保存sent_unknown/dispatching必须仍占预留和真实调用次数；遗留dispatching安全隔离为unknown，0重放、不因lease/timeout释放。若external highwater表明backup截点之后还有发送，或者高水位证据缺失，网关保持BLOCKED_LIVE/QUERY_STATE_UNKNOWN，直到可信对账补入真实欠缺记录；不能从“恢复库无行”推断未发送。
- 重复同幂等键、跨案同主体、重启/恢复/旧price/旧plan/hash或账单反复插入不产生新invoke；confirmed0不返还真实发送次数，超预留真实金额不截断。测试断言真实mocktransport调用计数与新Database读余额，不用内存计数伪恢复。

## 出站策略与实际OS隔离边界

EgressPolicy只有allowed_endpoints/regions/data_types，不含approval ID/reviewer/time/schema/price；必须来自当前批准登记的精确policy hash及T07provider绑定/数据政策/地域证据。HTTPS/“.cn”或caller.label='CN'、IPgeo结果不证明国内处理/日志/备份地点。

纯前置URL检查不能防DNS重绑定/redirect后自行resolve：批准transport须绑定解析地址及TLS验证，每次连接/每跳重新核验；默认不自动followredirect。SDK无法安全绑定时阻断真实通道或由已批准独立网关/OS出口策略提供；不手写不安全HTTP协议代替T07SDK。不把更改Python socket/requests/httpx2函数当OS禁网。

Windows候选实际API：JobObject通过CreateJobObjectW/SetInformationJobObject/AssignProcessToJobObject设置process memory、CPU时间/率、active process limit和kill-on-close；child CREATE_SUSPENDED后先赋job再ResumeThread，禁止breakaway及不受控handle继承，wall deadline由受控supervisor终止整个job。JobObject限制资源，**不负责网络或文件隔离**。restricted token+AppContainer无网络capabilities/专用最低权账户、必要ACL及WFP/防火墙规则属于未来实际部署，API存在不代表设置成功，当前全部NOT_IMPLEMENTED。

解析worker只获固定audited runtime和必要输入/输出句柄，environment allowlist清providersecret/代理/云认证；无shell、无真实DB/Secret访问、无任意磁盘权限，所有stdout bounded/无stack/正文外泄。现venv依赖admin `.cache` base解释器路径，必须未来验证受限身份所需runtime读执行权限，不能为可启动给整个管理员home权限；必要封装经ADR/平台锁核验。T07pywin32不在本轮偷偷装，ctypes候选也不启动任何进程。

- DOCX扫描全部ZIP正文/comments/header/footer/core/custom props/嵌入关联等，PDF/其他制品按已批准可读parts和人工限制；隐藏part和输出HTML/JSON/header/log不能带测试secret。pattern/entropy/canary不能证明图像/加密载荷无敏感信息；unknown格式和真实客户分类需人工/政策门，不误称全面无泄漏。
- 只用显式`SYNTHETIC_ONLY_QX_SECRET_CANARY`等独立虚构值测staged仅改内容、base64/URLencode/metadata/log/errors或keyfile误入bundle。命中报告只相对位置/规则ID/hash，绝不原值/snippet。备份是批准私有加密交付与publicrelease不同范围，密钥本身永不进入备份；.gitignore不能替代实际staged检查。
- build_release_manifest绑定实际源锁/平台wheel完整闭包许可/NOTICE/安装证据、规则与法源批准、config、真实测试/84状态、恢复/回滚/Word视觉/OS隔离/国内环境及TLS证据。每个ref须解析受保护实际批准记录、exacthash/适用scope/版本/时间/当前actor，路径存在/64位hash/客户端approved_by都不足。
- source缺失时SOURCE_UNLOCKED，未批准许可/规则/数据环境用现有LICENSE_UNAPPROVED/RULE_UNAPPROVED/DATA_POLICY_UNAPPROVED/BLOCKED_LIVE等；无实际文件不能用0hash补ReleaseManifest必填。开发manifest可基于真实存在材料构造approved_by/at=null，附受限验证输出；production检查非零，不能因生成DTO返回就声称已发布。
- 当前法律gold、全部生产source审批、真实法源规则批准、Word视觉、国内host/TLS、OS沙箱/实际恢复记录都缺失或未运行，production始终阻断；T11 mock断言/数学结果不是律师准确率，T09XML不是Word视觉，自签证书/配置文件不是生产TLS验收。
