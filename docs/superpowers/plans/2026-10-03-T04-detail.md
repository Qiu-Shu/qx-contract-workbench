# T04 事实确认、精确计算与主体歧义

依据v2.0 §5、6及T04；保留T01唯一DTO和T02已实现的权限/不可变事实快照。T03解析完成后接入，不重写已有模块。

1. 先实际RED：我方立场不得默认甲方；缺前月实付事实不得将年费/12当付款基数；白名单AST复利`1.02**12-1`约0.26824179；客户不续约期限不能当作客户自动续约负担；两个同名主体无决定仍ambiguous。
2. 候选抽取仅接有类型标签的事实值及原文Anchor ID，不把文本作为执行指令。调用者明确传入服务端matter_id、version及授权db/actor；不从模型自报IDs推导归属。所有document事实锚点须属于本案已存解析版本；无来源或冲突保留unconfirmed，不自动成为结论。
3. `confirm_facts(matter_id, version, decisions, actor, *, db)`把version作为期望当前版本，先对象级授权，再检查重复/错案/不属于当前快照的fact_id。确认/更正/拒绝保留原文，生成version+1新快照，后端计算hash；旧快照、批准和制品不覆盖，变更沿用T02失效机制。金额保持kind=decimal及原单位；只有confirmed/corrected人工事实供确定判断。
4. `calculate_expression(expr, values)`只遍历Pydantic批准AST，不使用eval/exec，不接受函数调用/属性/未知变量。Decimal有限值，指数/深度/除零有界处理；输入来源/单位、公式、舍入及假设保存。缺少实际付款/期间或输入事实不补猜。纯值数学结果需标明未绑定事实时的限制。
5. 主体候选按全称/代码冲突保留，不根据排名猜测。只有明确PartyDecision且确认人真实授权时才confirmed；不发外部请求。Party的matter_id/role由服务上下文给出；数据库保存使用统一Party模型，不另造字段同义DTO。
6. 法域或科技/劳动等专项线索只触发转交/待核实，不能从标题推导已完整覆盖。方向性续约观察为事实/逻辑，不宣称法律阈值。
7. 目标tests及受影响回归、独立review、实际证据/限制/状态更新，再本地提交。

接口细化：build_fact_candidates必须有明确本案上下文（ParseResult只有version_id）；resolve_party也需要明确matter_id与业务role，保留规范位置参数并增加keyword。保存/读取通过T02 save/get_fact_snapshot、fact_snapshot_sha256与read_matter；确认版本冲突不静默覆盖。若需要决定记录表，应使用既有Base关系与域DTO，且保持append-only，不向用户暴露任意初始化/管理原语。

只读预检集成约定：事实快照 hash 对 facts 列表顺序敏感，sort_keys 只排序对象键；保留原顺序。confirmed/rejected 不得借决定改候选值，更正使用 corrected 并保留单位和原锚点。外部收据在 T08 尚无可信持久化前明确不支持。付款基数由已确认实际付款事实 helper 取得，不能让通用算术按变量名字推断交易语义。0.05 等舍入步长必须准确实现，quantize(0.05) 仅改变小数位的行为需攻击测试。

主体记录需追加技术 revision 与决定记录；注册新 Base 表须显式初始化并创建 INSERT-only 触发器。Party.entity_id 保持 None，候选 UUID 不作权威实体映射。必要集成只扩充审计 party_changed/party，并提供窄持久化失效入口以复用原有批准 stale、制品 superseded；相应 core 改动在 T04 单一 implementer 范围内、先失败测试，不重写 T02。细化依据见 ADR 0002；预检本身未运行应用测试，不能标 PASS。
