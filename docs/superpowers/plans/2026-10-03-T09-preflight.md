**Goal:** 三种 audience 的 mock/DRAFT DOCX、精确不可变版本补丁、服务端批准和受控下载；正式签发继续真实门禁，视觉验收单列。

**Architecture:** 复用 T02 会话/成员/不可变原件/审计和 T03 结构锚点重算。先冻结已批准 exact patch 集合，再向新副本写真实 w:del/w:ins；候选文件与 bundle manifest 不可覆盖，批准只绑定已预览字节。业务 DTO 唯一置于 domain.py。

**Tech Stack:** 项目 Python3.12/FastAPI/Pydantic2/SQLAlchemy/pytest；待审计 python-docx==1.2.0；既有 lxml6.1.3；G04固定构造方法候选。PDF非首发必需。

**Spec:** `sources/specification-v2.0.md` §3/9/10/12/T09；实际只读证据 `.audit-local/t09-preflight.md`。T00–T04已实现，不重做；T06 ReviewRun 与 T08可信provider合同尚待交付，实施前重读最终代码。

## Global Constraints

- `model_provider_default: mock`、`qcc_enabled_default: false`、`production_autosend: false`；普通 CI 仅独立虚构资料。
- 批准、费用、案件授权、版本及锚点由后端核验；mock 不可正式签发。
- 原件和审计不覆盖；UTC；外部范围分别批准；客户/对方稿不含内部底线/日志/密钥/原始QCC整份结果。
- 开发锁/真实运行采用先核验；来源不明或未获准目标不得进入运行 prompt/rules/Skill。
- 失败测试必须功能断言失败，不把 ImportError/语法错误计RED；每轮命令/退出/实际数量真实记录。
- Word/WPS/批准renderer 实际打开检查单列，不把 XML检查、mock审批或人工降级当视觉/生产完成。

## Review Focus

- 同句出现在两个 paragraph/同 paragraph 两次，structure anchor 和整段 exact quote 必须唯一确定目标；不自动推断 subspan。
- 不同 run 样式、保留空格、制表/换行和非文字对象混合，保留未触及对象或明确 manual。
- 客户/对方输出的正文、批注、页眉页脚、core/custom props、嵌入件均无内部字段。
- 调用方捕获错误继续 commit、并发快照变化或批准后字节变异，没有半写/错误正式状态。
- 同人高风险例外伪 UUID、撤销成员、伪 Actor/manifest/provider、基础测试种子不能获得正式签发。

## 唯一接口与文件职责

- `domain.py`：仅在必要时新增 immutable patch approval/exception/bundle snapshot DTO；实际既有返回是 `ExportArtifact`/`ArtifactBundle`，没有 Report/ReportArtifact。
- `exports/report_docx.py`：新 DOCX 报告与可见 DRAFT/MOCK/限制/来源/人工表。
- `exports/audience_filter.py`：按批准的 recipient projection 先裁剪，未知字段 fail-closed。
- `exports/redline_adapter.py`：exact part/path + immutable baseline bytes + approved patch payload，普通正文 cross-run；复杂对象 manual；输出新副本。
- `exports/approvals.py`：保存/验证候选、实际权限/正式批准、download bytes/hash/ownership。若项目采用顶层 approvals.py，沿仓库命名明确一种，不复制两份。
- `exports/storage.py`（如需要）：新 immutable patch approvals/bundles/artifact bytes，reuse 原子写/事务清理，不能把 I/O 副作用放 DTO。
- 最小 `persistence.py/security.py` 接入：现有 foundation 保留；T09开始时与T05最终代码重新同步，禁止重写。
- 测试：`tests/unit/test_patch_preconditions.py`、`tests/integration/test_exports.py`、`tests/security/test_approval.py`；证据 `docs/testing/T09*.md` 与最终 junit。

对外签名在规格基础加明确 DB 注入（不是纯DTO可信授权）：

```python
prepare_exports(run: ReviewRun, audience: Audience, patches: list[Patch], actor: Actor, *, db) -> ArtifactBundle
apply_patch(version: DocumentVersion, patch: Patch, *, actor: Actor, db) -> PatchResult
approve_bundle(bundle_id: UUID, expected_hash: str, actor: Actor, *, db) -> Approval
download_artifact(id: UUID, actor: Actor, *, db) -> BinaryIO
```

Consumes：`read_version(matter_id,version_id,actor,db)`、`read_original(...)`、`resolve_anchor(anchor,version,*,actor,db,settings=None)`、`authorize(actor,matter_id,action,db)`、`verify_csrf(...)`、`read_approval/read_export`、T06可信保存run/T08供应商政策证据。Produces：以上四签名、唯一DTO，以及 exact immutable patch approval 服务（新增名称/DTO需在domain明确一次；不得仅设置Patch.approved_by）。
