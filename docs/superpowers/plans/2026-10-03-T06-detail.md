# T06 四类虚构材料的受控审查闭环

依据 v2.0 §5/6/7/T06；依赖 T03 材料/锚点、T04 确认事实和 T05 批准门。用户要求先完成此流程，再受控外查和真实修订。此阶段 QCC 调用必须为 0，真实模型默认关闭。

1. 先实际 RED：合同要求执行 shell 无工具权限；真正坏 JSON 最多原始加一次修复且两个 attempt 的 usage 都记录；恰好 18 项 coverage；伪造法源 ID 拒绝；缺附件是 insufficient_material；post_sign 不声称程序已改签订合同。
2. run_review(context, model, *, actor, db, ...) 保留原位置参数，服务器先授权并重读实际案件、当前文档/解析/事实/立场/规则/政策及 hash。输入 DTO 的自报身份、来源、批准和版本不成立。存储 ParseResult 本身也不是原文信任根：复用 T04 从不可变原件重新生成全部 ParseResult 的 trusted_parse 核验，包括 anchors、parts、unsupported、quality；不能只比较最新 stored DTO 或 ID。唯一业务 DTO/schema/defaults 保持不变。
3. mock adapter 是本地明确登记的受控对象，没有 shell/文件/QCC/网络工具。真实 provider 未有账户、地域、数据政策、价格和批准时在发送前阻断。prompt 只给获准当前块的必要事实/原文/规则；所有文档/网页文字是数据，不能改变系统权限。
4. 结构分块与跨条款关系审查都有精确 anchor IDs；去重合并保留全部证据，不靠标题/quote 丢弃重复位置。不读取前 N 块后宣称完整。未读部分、缺规则及范围外各有明确 18 维状态，不以 reviewed_no_issue 填满。
5. raw 层用严格 JSON 解析拒绝重复键、非有限值及坏 JSON；ModelResponse.payload 是 dict，不能用特殊 dict 冒充 malformed JSON。解析失败的内部异常保留受保护输出引用/hash及实际 usage。每个逻辑请求最多两个 attempt，失败/修复 usage 累计；耗尽预算或 sent_unknown 不自动重发，未知真实价格不调用。
6. validator 重校验 18 维/双向 findings、所有 anchor 精确归属和引用、选中规则/获批法源与实际 manifest。提供来源 ID 不等于支持任意法律分析；超出受控模板的文本须待律师审阅。mock 不能制造 human_decision、Approval 或正式签发。
7. 无获批法律规则时仍允许有限 mock 工程流程完成：仅服务器受控的数学冲突、材料缺口、主体待确认和方向性观察；不引用未批准法源，不自动认证 draft。其余维度不足或未支持。limitations 保留“虚构演示，非正式意见”、mock 不可签发、BLOCKED_RULE_APPROVAL；完整法律审查请求用 RULE_UNAPPROVED 阻断。
8. 保存不可变 ReviewRun、attempt/usage 与受保护输出技术记录；结束前再核验当前事实/政策/文档及会话，变更不能让过期结果成为当前结果。服务加入调用者事务，没有隐藏默认 DB 或业务 commit。
9. 为 sales/service/lease/nda 各创建独立虚构 DOCX，逐案实际 ingest/parse、候选提取、人工确认、审查/验证、manifest 和结果路径。新增 `cn_contract.cli demo` 使用 explicit fixture/provider mock/qcc off 参数，报告实际 run ID、18状态、synthetic=true、qcc_calls=0 和存在的文件。当前缺 Word正式制品/T10 UI 时清楚登记，而不打印不存在的报告路径。
10. tests/unit/test_model_schema.py、tests/integration/test_review_flow.py、tests/security/test_prompt_injection.py 目标与全套回归、独立审阅；父节点实际运行四份 demo 并验证产物，再记录 TASK_STATUS 和提交。本任务通过是工程演示完成，法律样本验收、真实试点和生产状态独立阻断。
