# T03 安全摄取与精确原文锚点

依据v2.0 §3、5、6及T03；依赖T02实际授权/原件服务和T01统一DTO。只用独立虚构DOCX/PDF，G06/G08开发采用不代表生产批准；OCR未部署时保持明确unsupported。

1. 先测试实际缺失功能：正文/表格都有锚点、文本框未读有缺口、重复原文不能按单字符串定位、压缩炸弹/宏/越界路径拒绝、PDF混合页逐页状态。实际RED不得是语法或收集错误。
2. ingest先授权和资源计数，再读有界stream；只docx/pdf，核对扩展名/MIME/魔数。DOCX不开启外链或执行对象；ZIP中央目录及实际解压同时限200MiB/100倍，拒绝绝对/..路径、反斜杠、符号链接、重名成员、宏和异常结构。过期/未知Actor和他案版本在任何存储读取前拒绝。
3. 受限XML建立正文/表格稳定结构锚点，保留精确原文/offset/hash/版本ID。同句、跨run和表格各有不同定位。所有其他部件做read/unsupported盘点，隐藏文/既有修订/远程部件不得被忽略；原件不能覆盖，baseline必须由明确元信息决定。
4. PDF用固定pdfplumber接口读取每页字符/坐标/表格。超过页数停止并失败，不假装已读全篇；扫描页/低质量数字或否定词标记manual或unsupported。未批准OCR不下载模型、不调用云识别。
5. resolve_anchor按原件具体版本/hash和唯一结构ID重新核对，禁止模糊全篇替换或把旧版本锚点用于新版本。T09复杂对象自动修改仍manual_required。
6. parse结果另存不可变快照，不修改DocumentVersion原件记录；后续界面汇总read/unsupported清单，不能以正文可读推导全文完整。
7. 目标与全套回归、独立安全审阅、实际命令/错误/产物记录后本地提交。

接口预检与最终决定：T02 `create_version`需要额外明确content流；T03保留规范位置参数并显式增加db/actor关键字：`ingest(file,meta,actor,*,db)`、`parse_document(version,settings,*,actor,db)`、`resolve_anchor(anchor,version,*,actor,db,settings=None)`。数据库由T02 Database/session_factory明确传入，不采用全局默认DB或客户端storage路径；纯adapter只接受已授权内容流。原件Version保持pending登记快照，解析结果通过save/get_parse_result另存不可变记录。
