## 当前工作台实际缺口

`bridge/server.py:83` 的 write_word_draft 新建 Word，仅输出标题和普通段落；`bridge/business_server.py:116` 的 export_case 在此基础上组织案件笔记和来源。它们已经有原件保护、同名另存与案件归属，但没有在原合同上写修订、批注，也没有专业模板填充。起诉状实质正文、证据与争点整理已有 Skill 方法，新增材料不必重复一套案件工作流程。

当前 DOCX 解析已能选择 original/accepted_view。读取某个修订视图不需要先把合同物理接受全部修订。旧项目 `src/cn_contract/exports/redline_adapter.py` 也有原生 ins/del 构造和版本定位，但仍耦合旧数据库/审批，范围仅普通正文段落，不可直接整套迁移。

## 原合同修订：必要性高，现成引擎不能直接包一层就上线

静态代码已确认：

- generate_trackchanges.py 的 find_run 只取第一个包含锚点的单一文本节点。重复文字可能改到第一处，跨 run 文字找不到；不能依靠“锚点取十字”解决真实 Word 拆分问题。
- do_replace 重建目标 run，可能丢失同 run 的其他文字、换行或非文字对象；仅复制部分字体属性不等于保真。
- 新增批注会覆盖已有 comments.xml/commentsExtended.xml，且 ID 从 0 分配，可能丢失或错连对方原批注。
- 输出路径没有当前工作台的同名另存和原子写入保护；部分入口允许源与输出相同。
- accept_trackchanges 主要处理 ins/del，不完整处理移动、格式、表格等修订；不能承诺“接受全部修订”。审查前自动接受对方修改也不适合默认采用。
- 包含的恢复脚本跨 run 回填会压平段落格式，且未完整覆盖批注和修订中的文字。“先脱敏、修订后自动恢复”尚不能直接当作可靠闭环。

最短可用做法是扩展当前文档工具：以明确材料版本和段落位置定位，保留原件及既有批注，输出修订副本。定位不唯一时仍给出建议文字并指出未落入哪处，不丢弃整份审查意见。已有旧项目的 XML 构造可以提取复用；新包作为实现参考，不把首个子串匹配带入产品。

成本主要在 Word 内容与修订历史的保真处理，不在 MCP 接线。完整细查见 `.local/package-assessment/contract/assessment.md`。

## 起诉状和证据目录：底版实用，填充器需要收窄并修正

七份模板为：买卖合同欠款、服务合同欠款、民间借贷、遗产继承起诉状；买卖合同段落版、建设工程段落版、表格版证据目录。它们不是新的法律知识库，也没有实现证据文件合并、连续编页或自动计算页码。

- 起诉状脚本缺少 claims/facts 时会按空列表删除对应段落，超过模板现有数量的内容未真正追加；继承模板的多原告、法定代理人和部分落款不匹配脚本写死的字段。
- 证据填充器主要替换现有段落，未实现表格行或证据项动态增删、连续编号及页码计算。重复文本选第一处，部分越界定位不会报错。
- 模板含示例事实、履行比例、律师费诉请、固定证据页码等，不能把没有替换掉的示例当本案内容。部分字体未嵌入，实际分页还需看目标 Windows 字体与 Word/WPS 渲染。
- 两包有路径/版本不一致：说明或 Skill 引用的部分模板名并不存在，模板 ZIP 又多一层根目录。应由工作台内部管理模板路径，不让用户手工修路径。
- 原 Skill 含强制脱敏、全部缺项追问、双重审核、外部法库及私有工具要求。保留有用写作方法，删除这些对本项目不适用的编排。

接入后仍由同一输入框理解需求，读取当前案件已保存的信息；只对影响内容的缺项问清，避免把用户重新送进一套长表单。模板必须保留独立原件，填充结果另存 drafts。

## 脱敏：区分外发副本与模型读取前处理

v2.7 是完整 Mac 应用，不是 Windows 安装包。较新引擎与合同包中的旧脱敏脚本同源，不应让两个不同版本在工作台内各自维护词表和映射。

目前发现的覆盖缺口包括：DOCX 图片需特定非空词表才进入处理，识别异常可留下原图；PDF 通过前几页文字量决定文字/扫描路径，混合扫描页可能漏处理；普通姓名并非全部覆盖。日期和金额默认关闭，但公司、项目与地址等会被替换，仍须保留跨材料身份对应及有意义的合同内容。还原 helper 指向包外的 WorkBuddy 脚本，不能称可独立完成还原。

两种用途需分别判断：

1. **准备对外分享的副本**：可以作为按需功能，生成副本、保留原件，查看实际处理范围及未处理部分。文档、图片和 PDF 的覆盖须分别说明。
2. **保证原文不进入云端模型**：必须在上传/工具读取返回原文之前完成本地处理，覆盖图片直传和其他原文读取路径；映射只留在本机并按案件隔离。模型已经读过原文后再调用脱敏 Skill，不能达成这个目标。

建议先接第一种明确用途，不把脱敏设为所有合同分析的强制前置。不能把规则检查通过等同于彻底匿名或没有残留；有可逆映射的处理也不等于不可恢复匿名化。

## 对当前安装包的影响

本轮只增加评估报告和 `.local/package-assessment/` 下的静态副本/读取记录，没有修改正在运行的 bridge、config、plugins、desktop 或安装接口，没有新增运行依赖，也没有新增 knowledge 插件。当前四能力及知识库入口的安装包不必等待这些候选功能；不要把评估用 ZIP、临时副本或示例数据纳入安装包。

本报告为必要性与静态可复用性判断，不是新包已通过运行或法律内容验证的证明。后续采用具体代码时再核清来源授权与随包依赖；当前没有将这些代码复制到产品执行路径。
