## 使用流程

侧栏「拓客内容」中填写业务方向和目标客户，选择采集方式并保存。默认 JustOneAPI；Token 在工作台输入，保存及检查凭据只确认本机是否已配置，不发起计费查询。第一次实际整理才验证账户权限及服务响应。另保留「本机扫码采集」，该方式需显式准备组件并用本人小红书扫码；登录失效提示重扫。

保存启用后，首次到期整理，之后每 72 小时整理一次；可立即整理、暂停或恢复。电脑必须开机、联网且工作台服务运行，关闭期间不会执行；重开后最多补跑一次，不回放每个错过的周期。这不是云端任务。

本期来源及摘要进入固定会话 `qx-content-watch`，绑定现有三层知识库中的「律师内容运营」项目。报告保留标题、作者、时间、链接、互动快照、实际读取范围及采集说明。点击报告中的选题，可在同一会话继续生成 60–90 秒原创口播、手机分镜、标题和发布文案；提示模型先以公开来源核实事实及法律依据，缺失处标为待律师确认。没有自动发布、私信、微信推送、视频转写、视频生成或数字人制作。

## 实现与边界

- API 搜索采用最多 2 组业务/客户关键词，各查热门与最新排序，时间范围近一周；最多 4 次搜索、6 次详情。仅第一页有限样本，不宣称全平台榜单或趋势。已推送 ID 在详情调用前排除，已知过期内容在适配器和任务层过滤。视频仅依据取得的标题简介，未获得转写不补写视频原话。
- API 结构按[搜索 V4](https://docs.justoneapi.com/zh/api/xiaohongshu-rednote/note-search-v4)和[详情 V1](https://docs.justoneapi.com/zh/api/xiaohongshu-rednote/note-details-v1)公开响应示例核对：搜索 `data.notes[]` / `timestamp`，详情 `data[].note_list[]` / `time`。不把更新时间当发布时间，未知互动数保留缺失。
- 按[服务使用说明](https://docs.justoneapi.com/zh/usage)识别业务错误码；凭据无效、限流、当日额度、账户余额、Token 预算、权限和采集故障分别提示。失败不自动重复付费请求，不自动切换到本机扫码账户。密钥和带密钥的请求 URL 不回传到界面、模型或报告。
- 连接设置独立保存于 `stateDir/connection.json`。Windows 复用现有 DPAPI；其他系统使用受限文件权限，界面说明未加密。Token 不进入前端持久存储、Git 配置或知识库。
- 状态、报告及提交意图在本机持久化。单轮互斥、提交前记账、已提交选题不重复派发；不确定的模型结果提示进入会话查看。异常中断保留报告，已有有效进程锁不会被抢占；不完整锁先提示并保留 60 秒保护期，确认未变化后可恢复。
- 自动采集/起草消息标记为 `source.kind=qx-content-watch`，不能充当律师确认规则的依据。专用会话只能读取本项目已确认的规则和表达偏好，不自动读取关联原件或客户项目；绑定异常时停止知识读取。普通会话流程保持原样。
- 插件注册、现有用户配置迁移、打包复制与可选组件准备脚本已接入。配置迁移只补缺失项，保留用户停用与自定义设置；不会自动创建已启用任务、账号、Token 或登录态。

主要实现位于 `plugins/content-watch/`；复用知识库服务的改动位于 `desktop/integration/knowledge-api.mjs`。本机组件与安装迁移细节见 [11 月 5 日记录](2026-11-05-拓客组件与安装迁移.md)。
