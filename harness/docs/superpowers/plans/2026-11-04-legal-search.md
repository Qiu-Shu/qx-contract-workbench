# 法律资料检索实施计划

> 使用 writing-plans 整理、executing-plans 连续实施。用户已批准上轮评估中的最小接入范围，不再增加业务确认门槛。

**Goal:** 保留现有检索，故障或空结果时自动使用一个独立备用渠道，结果留在本机并能按需回读。

**Architecture:** 新增独立法律检索工具，调用 Harness 的 `ctx.web.search`，复用其凭据与取消机制；备用通过已打包的 Scrapling Python 读取公开搜索页。完整返回资料写入本机，模型先读简短目录，再分页/按条回读。

**Tech Stack:** Node.js 内置库、Harness 工具接口、现有 Scrapling、union-search MIT 解析代码。

**Spec:** 用户确认的上一轮评估：最小复用、一个备用渠道、中文显示、不引入媒体下载与账号模块、不增加业务校验门禁。

## 约束与验证重点

- 不读取案件文件、其他软件账号或浏览器登录态；实测只用公开法律关键词。
- 一个查询失败不丢弃其他查询结果；取消后不继续请求备用。
- 验证码/解析失败不能被当成“没有法律依据”；正常检索不重复调用备用。
- 重复 URL 合并但保留来源，来源名称不等于内容已核验；不自动声称法条有效。
- 全文存档，不用全量搜索内容挤占模型上下文；分页不意味着删除未显示结果。
- 只改本功能文件；已有安装包发布由并行会话负责。

## 决定记录

- 百度首轮可用、第二轮验证码；360 三类公开查询可用，选 360 作唯一匿名备用。该观察不承诺其永久可用。
- 不新建 Skill：使用工具说明和系统路由即可让现有法律 Skill 共用检索，减少重复能力。
- 后续连续实测时 360 同样出现验证码，保留明确失败和 15 分钟冷却；没有换账号、绕过挑战或增加更多渠道。首次三查询通过不等于永久可用。
- 后端 presentCall 不控制当前 Harness 的工具列表标题；在既有 desktop-session 客户端以官方 tool.call.toolview 槽位注册中文卡片，真实页面验证通过。
- 独立复核的三个问题已先加失败测试再修复：逐渠道原始响应留存、失败与空结果区分、排队期间及时取消。
- 完成证据：42 项 Node + 12 项 Python、真实模型三查询 29 条来源及五次回读、真实界面中文卡片/8 个来源链接/零页面错误。发布边界详见检索交接文件。
