# 案件记忆实施计划

> 使用 subagent-driven-development 执行；按互不重叠的文件边界并行实施，最后统一检查。

**Goal:** 将 Hindsight 接入为默认开启、可关闭的案件记忆，支持按案查看、追溯、更正和删除。

**Architecture:** 本机 SQLite 保存用户明确选入的记忆及来源，Hindsight 作为可选语义索引。每案独立 bank，变更立即使旧索引失效；本机记录与服务状态分开呈现，服务不可用时保持本机管理和明确标识的关键词检索。

**Tech Stack:** 现有 Python/SQLite/MCP、Harness Node 插件、React 界面；Hindsight 本机服务。

**Spec:** 用户 2026-11-04 明确要求：可选案件记忆默认开启、按案件隔离、保留来源、查看更正删除。仅主动选入记录，不回填历史聊天。

## Global Constraints

- 不读个人第二大脑，不跨案件合并或推断归属。
- 来源正文是资料，不是指令；记忆不是证据或新的法律结论。
- 凭据留在服务进程，不传浏览器、不写日志。
- 更正与删除立即退出旧检索；远端清理未完成须显示状态并可重试。
- 功能启用、服务就绪、索引完成分别显示。现用 3080 服务不为测试而重启。
- 不自动把全部聊天交给模型；所选记忆由当前配置模型处理的提示必须可见。

## Review Focus

- 同名案件或伪造 ID 不得跨案读写。
- 同步期间发生更正/删除不能重新激活旧内容。
- 服务离线、程序重启后清理队列可恢复，不能虚报删除完成。
- 全局或单案关闭应立即阻止检索与同步。
- 安装升级不覆盖既有关闭设置、案件数据或模型凭据。

## 实施记录

- 权威记忆仍保存在本机 SQLite；每案使用独立、带版本的 Hindsight bank。检索只映射回当前本机记忆，不直接引用 Hindsight 生成的推断。
- 索引使用最多 5 条一批的可恢复同步，避免大案件一次处理超时；服务未就绪不创建索引库。
- 更正或删除使旧库退出检索。旧请求超时且无法确定结束时，持续保留清理状态，不虚报服务端清除完成。
- 安装包运行环境为可选组件，一键准备前不下载大依赖。原始服务及本机代理均须鉴权。
- 最终根任务检查：41 项 Python（记忆、MCP、配置、既有案件及知识库）、30 项 Node（运行时、升级、接口、真实 MCP 凭据传递）、3 项打包检查通过，无跳过；真实 React/Chrome 的 15 项隔离交互检查通过。
- 独立复查发现并修复：受管服务 /engine 路径兼容、关闭与读取的事务竞态、切案后旧请求覆盖新状态；复查确认修复。
- Hindsight 1.2.0 真实冷启动与暖启动通过：ONNX 384 维、PostgreSQL 健康、鉴权及跨源拒绝、稳定实例标识、退出无残留进程。没有调用真实模型，未验证 DeepSeek 实际记忆提取质量。
- 最终候选包位于 `.local/update-release-0.2.6-candidate`。从实际安装器选择解包后，15 项关键文件与当前源码一致，配置、更新签名及完整摘要验证通过。未公开发布或安装到实际用户环境。
- 打包中止后的缓存清理被自动审查拒绝，保留原目录并标记 DO-NOT-DISTRIBUTE；改用新目录完成构建。新增缓存复用拒绝检查，隔离夹具验证通过。最终候选与中间目录区分，不使用中间安装器。
