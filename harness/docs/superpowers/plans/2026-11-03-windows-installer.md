# Windows 安装包与首次配置实施计划

**Goal:** 用户双击 Windows 安装包即可安装，首次打开填写自己的 DeepSeek API Key，微信入口在左下余额上方。

**Architecture:** 沿用现有 Electron 和官方 Harness；安装版携带 Node、Python、业务桥与工具依赖。程序文件只读，配置、加密密钥和工作区放在用户数据目录。开发版继续使用既有启动方式，不中断当前真实会话。

**Tech Stack:** Electron 44、Node 24、Python 3.12、electron-builder NSIS。

**Spec:** 本会话用户明确提出的一键安装、首次 API 配置和微信入口位置；用户已授权同步协调两个并行会话。

## 边界和分工
- 当前会话：desktop 安装启动、API 配置、packaging 与验收。
- 部署会话：法律能力及微信入口；工具会话：工具/Skill 接入与依赖交接。
- 不复制 .local、真实 workspace、现有密钥、微信凭据、日志和个人浏览器资料。
- 独立安装标识，保留旧版；测试使用单独数据目录与虚构凭据，不调用付费模型。
- 不需要用户安装 Python/Node；微信扫码、浏览器扩展连接是用户各自完成的账号操作。

## 实施
- [x] 1. 首次配置：复用旧版加密凭据模块；新增配置页与仅主进程可读取密钥的 IPC；测试无效密钥、网络失败、保存与再次启动。
- [x] 2. 独立运行：可重定位路径、初始化干净工作区、保留既有设置；由独立主机进程运行 Harness；测试空目录与带空格中文路径。
- [x] 3. 打包：显式来源清单；携带业务解析器与工具依赖、法律库及许可；一键用户级 NSIS；检查包内无用户资料。
- [x] 4. 验收：构建真实安装包，在隔离安装目录运行；验证首次页、失败反馈、主机启动、文档桥、微信入口顺序；记录未实测范围。

## 验收重点
没有 API Key 时必须显示引导；失败不能当保存成功；不能把 Key 写到日志或配置；程序路径含中文空格仍可启动；升级不覆盖用户资料；不能依赖开发机绝对路径。

## Decisions
复用旧版安装工具链，新增安装版入口而不是重写正在使用的开发版启动器。当前两个会话共享未提交工作，按文件范围隔离；不创建会丢失并行未提交成果的 worktree。

后台由独立 Node supervisor 运行；API Key 只由 UI 主进程加密保存/解密，并通过子进程环境传入内存。避免多个 Electron 进程同时持有用户配置目录。换 Key 后重建主窗口，刷新新服务地址对应的权限判断。

2026-11-03 实证：6 项 Node 单测、2 项打包器单测通过；真实首次配置转场、换 Key、IPC、微信窗口全通过（服务商验真模拟成功，实际密钥为虚构）。便携文档/法律/浏览器/Scrapling/Windows 五服务实际启动；DOCX 读写与公开页面抓取通过。后台控制要求随机令牌，升级钩子仅结束自己启动的进程树。独立审阅发现的地址权限、依赖遮蔽、stderr 跨块密钥脱敏均已修复并验证。

最终0.2.1：23项Node测试、2项打包器测试通过。真实0.2.0安装、0.2.1覆盖升级、全新用户首开与卸载通过；材料、私有映射、加密凭据摘要一致，自定义规则保留。默认合同批注/HTML与Word意见书、模型失败请求恢复已纳入；实际settings/describe确认策略。ZIP条目限制及中文内部exe兼容问题已修复，内部使用QunxingWorkbench.exe，用户界面仍为中文。完整交付见docs/2026-11-03-Windows安装包交付.md。
