# 模型请求中断自动恢复

用户要求自动恢复、保留已生成内容和文件、不重复执行、不增加内容校验门禁，并实际合入新版安装包。

## 根因与方案

Harness 0.2.2-alpha.2已经有官方llm-retry插件，其默认normal策略重试EMPTY_RESPONSE、RATE_LIMIT、SERVER、TIMEOUT、TRANSPORT，但本次DeepSeek损坏工具参数被标为MALFORMED_RESPONSE，提前结束的流标为STREAM_CLOSED，未进入默认列表。

使用provider.retryPolicy补这两个错误码，沿用默认5次重试、退避和取消支持。失败请求在同一个step内重试，保留assistant/attempt，重新生成当前请求；之前成功的assistant/tool结果进入下一请求上下文。失败批次尚未执行工具，不重新发送用户任务、不重放前面工具批次。工具本身失败、认证、余额、无效请求和用户停止不进行盲目重试。保留当前工具的request_id机制，不添加回答校验、审批或新执行引擎。

## 实施及验证

1. 先用真实官方adapter/agent-loop/retry和隔离本地合成SSE端点复现默认配置中断。
2. config/cordis.patch.yml配置正常恢复策略；专用部署脚本只向现有profile添加该设置，保留其他用户配置和本机凭据。
3. 故障注入：成功生成文件后，后续请求返回损坏参数/断流，自动恢复；确认副作用执行次数、文件字节、历史记录、停止取消、失败上限、非重试错误。
4. 配置应用到当前本机服务；提供测试证据并冻结给安装线程，实际构建0.2.1，验证安装与旧版本升级保留用户材料。

恢复保证的范围是模型请求级重试；不宣称任意工具、断电或未知外部副作用都具备全局exactly-once。失败响应的用量可能未由上游返回，不能声称重试扣费完全可核算。
