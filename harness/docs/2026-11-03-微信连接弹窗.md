# 微信连接弹窗

左下“微信连接”改为程序内弹窗，沿用工作台现有颜色、字体和按钮。菜单“手机微信”与 `--wechat` 入口也打开同一个弹窗。打开和关闭不切换正在查看的聊天、不自动扫码。

- 会话下拉显示本工作区未归档会话的名称，重名用序号区分。选择后点击“切换会话”保存微信后续消息的去向。
- “新建会话”通过官方会话服务创建，并立即绑定微信。此前实现的首次材料自动命名规则继续适用。
- “重新扫码切换微信”暂停旧连接，手机确认后持久化新账号选择，再启动接收；保留旧账号记录。取消后可“恢复原微信连接”。平台若仅返回已有绑定而没有可确认的新账号，不猜测复用旧账号。
- 有微信消息收集或处理时禁止切换。扫码确认落盘期间锁定操作，防止恢复、暂停等请求覆盖新连接。接收去重按账号隔离，发送文件固定本次收件人。
- 支持验证码、失败提示、刷新状态、Escape、键盘焦点返回、侧栏收起和窄屏。

实现：`desktop/integration/client.js`、`desktop/main.cjs`、`plugins/wechat/qx-plugin.js`、`plugins/wechat/login.js`。原 `/qx-wechat` 页面保留兼容，但新入口不再使用。

验证：

- `node --test plugins/wechat/test/qx-*.test.mjs plugins/wechat/test/login.test.mjs`：27 个 Node 测试单元通过，其中两个内嵌套件分别包含 15 个扫码状态用例和 5 个回复归属用例。未声称全仓库测试通过。
- `desktop/check_wechat_dialog.py`、`desktop/check_wechat_entry.py`：独立 Chrome 使用实际客户端、合成微信/会话/二维码验证，无真实扫码或微信发送。证据位于 `desktop/checks/*-wechat-dialog/report.json` 和 `*-wechat-entry/report.json`。
- 本地运行服务已在会话和微信队列空闲时更新。实际设置接口返回 200，会话名称列表可读，原微信接收恢复；未改变真实会话绑定。
- CodeGraph 已同步；Impeccable 的 JS 静态检测无发现，其 regex 模式不代替浏览器验收。

已有窗口请先保留未发送输入，再用“工作台 → 重新连接”加载新版左下入口。菜单处理逻辑属于桌面壳，完整重开工作台后加载。安装包未重新构建。
