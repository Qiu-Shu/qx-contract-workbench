# 首次材料自动命名

用户确认：每个会话根据第一次上传内容自动概括名称，后续上传不再改名；三个并行会话独立处理。

已在 `D:/qx-harness-workbench-20261102` 实现，并于 2026-11-03 在本机 3080 服务加载验证。

## 行为

- 首次材料通过聊天输入框提交后，从该条消息的文字、附件名称和正文摘录生成简短中文标题。仅将文件暂存在输入框、尚未发送时不触发。
- 首条含文件或图片的用户消息优先。之前的“你好”等文字可以有临时文字标题，但不会抢占首次材料的命名机会。
- 同批附件使用前 3 份正文摘录（单份最多 6000 字；PDF 开头 2 页），同时保留前 30 个附件名；命名输入按 UTF-8 字节截断，避免原上游 4096 字节限制导致长材料命名失败。
- 图片使用已安装的本机 OCR，兼容 Harness 无扩展名的图片对象；解析失败时仍可依据首次文字和附件名概括。
- 首次材料标题写入既有 `session/title` 日志，后续消息、追加文件和服务重开不会自动替换它。手动名称优先，在途自动命名也不能覆盖手动名称。
- 工作按真实 Session 对象隔离，不依赖当前选中的窗口或标签。失败可在后续事件重试，但始终使用首次材料，不改用后来上传的内容。

## 代码与启用

`plugins/session-title/naming.mjs` 负责首次输入选择、并发隔离及持久化；`index.mjs` 复用官方 LLM 标题请求与清洗逻辑；`bridge/title_excerpt.py` 复用现有材料解析和 OCR。

源配置和实际 profile 均禁用原 `session-title-llm`，另插入 `qx-first-content-title`。注意上游 patch 的 `name` 是名称匹配条件，不能用它替换同 id 插件。`scripts/deploy-session-title.py` 仅追加本次配置，并在 `.local/backups` 保留原 profile。

`packaging/stage.py` 已将插件纳入后续打包，portable 配置的插件、Python、工作区路径转换已检查；本轮没有重新构建安装程序。

实际后台最初未加载磁盘配置。确认所有会话均无运行任务后重载后台，保留桌面窗口、会话及文件。旧窗口如需连接新后台，使用“工作台 → 重新连接”；避免在有未发送草稿时强制刷新。
