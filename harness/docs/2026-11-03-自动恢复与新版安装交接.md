# 模型请求自动恢复与0.2.1安装交接

本轮已修复先前合同任务遇到MALFORMED_RESPONSE就终止的问题。沿用Harness官方恢复机制，仅调整实际插件ID `llm-deepseek` 的provider.retryPolicy，未修改node_modules、未新增依赖或插件、未增加答案校验门禁。

## 具体行为

- 原默认EMPTY_RESPONSE、RATE_LIMIT、SERVER、TIMEOUT、TRANSPORT继续恢复；增加MALFORMED_RESPONSE与STREAM_CLOSED。
- 当前失败的模型请求在同一step内重试，不重发用户任务。之前已成功的工具结果与文件保留，工具批次不重放。失败响应文本和参数保存在assistant/attempt，作为失败记录，不冒充已完成答复。
- 沿用normal策略5次重试和默认退避500ms至10秒；用户停止可取消等待。认证、余额及工具执行异常不盲重试。若持续失败则停止并保留已有成果。
- 保留已有业务request_id机制；这是请求级恢复，不是任意外部工具或断电后的全局exactly-once承诺。上游失败响应可能不报告用量，不把估算当实际扣费。

## 实测

`tests/model-recovery/run.mjs`启动隔离的真实Harness、官方DeepSeek adapter、agent-loop与llm-retry，对接本机合成SSE端点和MCP工具。测试不使用真实客户材料，也不访问外部模型。

- 修复前真实复现同一MALFORMED_RESPONSE终止：`checks/model-recovery/red.json`。
- 修复后六场景通过：坏JSON恢复、无message_stop断流恢复、AUTH不重试、QUOTA不重试、退避中停止、持续错误5次后终止。真实写文件、展示、保存笔记各一次，用户消息一次，原文件字节与摘要不变，前步工具结果进入恢复请求。见 `checks/model-recovery/green.json`。
- 主任务独立复跑通过；部署与合同输出专项27项通过。独立复核指出源版部署脚本对行内数组和YAML终止符的兼容问题，已先复现再修复，保留原备份并原子写入。当前3080服务通过认证settings/describe确认实际策略已生效：`checks/model-recovery/live-config.json`。
