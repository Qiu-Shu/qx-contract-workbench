# 增强记忆冷备接入

接续 `58a4350`，沿 Ponytail / implement / TDD，测试既有 `createLocalBackup` / `restoreLocalBackup` 和快照入口。仅合成材料，不构建安装包或改动正在使用的工作台。

1. 核验已有锁定的 pg0-embedded 0.15.2 wheel，复用其 PostgreSQL 18.1 与 pgvector 工具。合成数据库干净停库、加密备份、隔离恢复后在新目录启动，核对身份、记录和向量索引。
2. 生产入口只做离线读取：冻结目录及文件、复制完整数据库和 instance.json；用固定摘要的 pg_controldata / pg_checksums 确认干净停库、版本及校验和。独审发现 WAL 漏检后补充 pg_waldump 校验 shutdown checkpoint 记录及其所属集群身份。缺身份、残留PID、恢复态、未启用校验和、外部表空间或异常版本均拒绝，不自动修复或启动用户数据库。
3. 保留完整目录清单（PG运行需要空目录），同时维持旧快照读取兼容；未知路径、外链及源变化继续阻断。PG工具显式传入，没有工具仍拒绝包含PG的备份/恢复。
4. 默认恢复仍隔离且不激活；本轮证明引擎级数据保存与恢复，不等于Hindsight业务迁移、模型语义验证或跨机凭据迁移。pg0 0.15.2 源码不识别 PG0_HOME；全局实例注册不迁移，不让恢复副本沿旧注册自动启动。
5. 目标失败/通过、完整离线回归、双轴审阅及证据后本地提交。停电/磁盘写满/大数据与UI单列后续。
