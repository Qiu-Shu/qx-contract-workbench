入口 `npm run eval:workflow`；实现与复现说明见 [评测 README](../evals/quality-baseline/README.md)。Promptfoo 0.125.1、完整锁文件、MIT 许可和 Windows SQLite 绑定独立保存在 `evals/quality-baseline`。产品依赖和打包源目录白名单不包含 Promptfoo、评测目录或候选实验目录。

离线适配器发出脚本化调用，实际执行现有 DSH agent-loop、工具执行器、技能发现/加载、交付保护与 Python stdio MCP。每案使用独立合成工作区，实际读取原件、保存案件底稿并导出 DOCX，回读文件和原件 SHA-256。不会以固定回答字符串代替工具运行。共同证据规范由只允许读取该单一文件的评测工具加载，记录内容和摘要。

所有研究法源均为虚构。材料自述核验状态单列保存；实际研究稿明确真实法源未核验。金额只作十进制计算，日期只算自然日，不能作为法律请求权或法定期限认定。

## 独立审阅后的修复

实际构造坏结果复现并修复了以下漏报：完成措辞未绑定真实文件；仅保存规范却未读取；未核对工具成功回执；金额用子串比较；把算术结果当法律认定；材料读取失败未拒绝；错误引用借无关警告通过；同一句有否定词掩盖另一处确定性结论。最终回答必须包含真实导出路径，金额按完整十进制值比较，原件、引用及不确定状态分别检查。

独立复验真实金额案例后，额外 7 种坏结果变体均被拒绝。另发现实际文件已导出，但脚本模型查找带前缀工具回执失配、回答称无文件；修正回执匹配并加入交付路径断言后重新跑完整 24 案，以上为修复后的结果。

开发期失败保留：Windows 绝对路径被 Promptfoo 断言加载器解释为导出名，改用相对 `file://assertions.js`；旧夹具以“已确认”的否定句描述状态导致强化断言失败，替换为明确“真实法源未核验”的完整证据卡。早期 13 通过/11 失败的报告与后续 24 通过报告均保留在 `.local/quality-baseline`，未拿较早的成功替代最后版本验证。

真实模型入口仍需另行明确预算和范围，并要求三个显式环境开关/凭据。共享 runId 对应一份预算账本，每请求加互斥锁并保守预留；直接 provider 没有共享 runId 时拒绝，不能逐案重置额度。mock 测试覆盖共享余额、并发拒绝和额度阻断。本轮未执行 live 分支。
