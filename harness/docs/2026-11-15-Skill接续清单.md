# Skill 接续清单与换机开发说明（2026-11-15）

本清单只列已由当前源码核对的状态。对应产品为 Harness 0.2.19，原始发布基线为 `d91377a865e94330692715cbb95494725889eee5`；根目录旧 Python 0.6.x 工程与当前桌面产品是不同版本线，不要把旧候选直接覆盖安装目录。

## 当前可用与未完成

`config/practice-skill-additions.json` 声明 194 个可发现入口、158 个允许自动调用、36 个旧入口停用。计数包含单独列出的 agent-desktop；文档中的引用材料不是另外一个可调用 Skill。此为配置及工程状态，不等于律师质量认证。

已开放 8 项新增方法：证据分析、来源文稿、劳动核查清单、来源台账，以及法源核验、类案比较、争点备忘录、讲座来源包。后四项已进入 0.2.18，本轮不要再当作未接入事项重做。

| 暂缓开放的完整专项 | 当前可复用的窄入口 | 下一阶段要证明的能力 |
| --- | --- | --- |
| qx-litigation-drafting | qx-source-drafting、qx-evidence-analysis | 不补造委托、签收、陈述媒介、诉讼状态；请求权、相反证据和真实法律时限都有可核来源 |
| qx-employment-review | qx-employment-checklist | 区分原文事实与法律判断；不预置未核补偿倍数、竞业程序或效力结论，验证复杂合同与表格关联 |
| qx-corporate-records | qx-source-registers | 不把签到或股东身份当董事/签署资格，完整核验名册、权限、审议及生效条件 |
| qx-compliance-work | qx-source-registers、qx-case-work | 未知实施状态保持未知；不扩写未经授权义务，按明确来源期限报告状态 |
| qx-ip-register | qx-source-registers、qx-case-work | 区分开发者、申请人、权利人和权利主张者，期限及实时权利状态另行取源核验 |

上表是根据已确认失败类型整理的接续目标，不表示存在已经验收的完整实现。当前 `config/skills` 不分发这 5 个完整入口；只移除 withheld 或改名开放不能算修复。

36 个停用旧入口的逐项原因与去向见 [skill-status](../workspace-seed/legal-library/workbench/skill-status.md) 和 [skill-lifecycle](../config/skill-lifecycle.json)。其中一部分是事实/法律质量失败，一部分是学生教学、旧插件管理等不在产品范围，一部分是指向停用目标的别名。**不需要把 36 项全部恢复。**

## 在另一台电脑接续

1. 从 GitHub 克隆本仓库，切到 `v0.2.19` 或其后的已确认源码提交，在 `harness` 下开发。先读本清单、当前 README、`config/practice-skill-additions.json`、`config/skill-repair-freeze.json`、`config/skill-lifecycle.json` 和 `config/skill-quality-upgrades.json`。
2. 安装 Git、Node 24.9+，按 [打包说明](../packaging/README.md) 准备锁定依赖及运行载荷。源码、用户资料、测试输出分开放置；不要复制旧机器 node_modules、DPAPI 凭据或依赖绝对盘符的临时启动器。
3. 先复跑 `node scripts/test-suite.cjs offline` 和 Windows 专项；Windows 模式需按脚本提供 `QX_TEST_APP`、`QX_TEST_PYTHON`、`QX_HDIFFPATCH_DIR`。包内 Python 不含全部开发测试依赖，应独立安装测试依赖，不向程序目录临时补装。
4. 每次只接续一项完整专项。复用来源读取、材料版本、案件归属、来源绑定文稿和受保护交付，不再建立平行工作台。先固定旧失败样例及新的独立反例，再做最小改动和对应回归。
5. `scripts/skill-eval-campaign.cjs` 支持隔离评测目录及已定义的 v2/v4/v5/v6 快照名称。旧机器的 `.local/skill-resume-20261105` 和原始质量评测目录本轮未找到可验证副本，不在源码交付中；不得据历史成功计数宣称新机器已复现。可以从已提交合成样例建立新的、独立编号的评测批次。
6. 真实模型质量评测需明确模型、预算和独立虚构材料。运行前冻结输入、评分规则、来源和候选摘要；保留原始输出与失败，不重复调用直至“碰巧通过”。工程测试通过和律师人工复核分别记录。
7. 只有对应质量与安全边界通过后，才更新入口开放清单、迁移摘要、路由及配套测试。已有用户修改必须保留；不要运行一次性修复生成器覆盖已审版本。

关键测试与工具：`bridge/test_source_bound_*`、`bridge/test_litigation_documents.py`、`bridge/test_employment_*`、`bridge/check_practice_mcp.py`、`scripts/check_skill_lifecycle.mjs`、`scripts/check_skill_routes.mjs`、`scripts/review_verified_delivery.py`、`desktop/skill-quality-migration.test.cjs`。部分检查依赖生成后的 workspace，先读入口约束，不在真实用户目录运行。

## 换机资料与账号

从程序“备份与恢复”创建加密备份，在新机器恢复到新目录，再核对配置和旧待办后启用；原副本保留。模型密钥、微信、飞书和其他账号需要本人重新连接。源码与安装包不会携带这些凭据，普通文件复制也不等于 DPAPI 凭据可跨机解密。
