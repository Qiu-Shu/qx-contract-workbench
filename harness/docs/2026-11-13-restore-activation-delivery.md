## 使用流程

在桌面“工作台”菜单或 API 设置页打开“备份与恢复”。先保存内容、确认任务结束，再点击停止后台进入维护。第一次可明确点击下载并核验固定版本备份组件；之后可以离线使用。

1. **创建备份**：选择保存位置，输入并确认口令，生成新的加密备份文件夹并读回校验。
2. **恢复备份**：选择完整备份及新的保存位置，恢复为独立副本。
3. **检查与启用**：查看恢复计数、可迁移偏好和重新连接事项，逐项选择保留待办、生成草稿或取消，再准备新副本。
4. **确认启用**：重新核对副本并初始化，成功后切换资料目录并真正重启。API、微信及拓客账号经原有入口重新连接，旧凭据不直接搬用。
5. **撤回**：停止后台后确认撤回上一资料目录，再次重启。原目录和新副本均保留。

“生成草稿”只生成供人检查的本机文件，不会自动发送。微信队列、拓客任务、Harness 定时任务和会话收件箱均冻结。恢复旧聊天后发出新消息，不会把旧收件箱重新交给模型。外部工作区会话只保留审核，不擅自改绑到本机。

## 实现与修正

- 原恢复副本保持文件内容与修改时间不变；设置应用、待办处置、会话路径重绑定均在新副本进行。旧配置和升级记录按本次恢复身份保存在审计目录，不能干扰新副本初始化。
- 固定启动根保存资料选择记录。只有经过摘要核验并初始化成功的 `ready` 副本能被选择。丢失激活回执但仍存在准备摘要时拒绝启动；初始化失败或副本被改动时保留阻断。
- 当前目录丢失、盘符离线或选择记录损坏时进入维护，不静默创建空业务库。可撤回实际上一目录；上一目录也不可用则明确失败。旧电脑的源路径只作为经认证的历史前缀，不要求原盘仍在线。
- 桌面实例锁、维护互斥和主进程原生目录选择已接入。维护中不重连业务后台；任务进行中防止关闭窗口。更新和停止入口采用同一资料选择规则。
- 修正嵌入式 Python 默认 GBK 导致的中文路径误读及内部长路径恢复失败。SQLite 仍只读且不能创建缺失数据库；PostgreSQL 工具仍核验固定版本、身份、WAL 与校验和。
- restic 固定为 `0.19.1`，下载包和可执行文件双摘要核验，BSD-2-Clause 原文随源码与打包复制清单保留。新增界面、runner 和 Python helper 已进入文件复制测试；未制作安装器。
