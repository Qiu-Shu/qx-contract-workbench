# AI师兄法律助手平台：Skill 逐项核对与中文名称

日期：2026-11-04。本次聚焦已有 Skill 的可调用性、资源与中文显示，不增加运行时内容门禁，不扩展法律业务。

## 核对范围与结论

项目共有 185 个 Skill：175 个法律库条目、4 个主业务方法、6 个辅助工具。源工作区、安装包种子目录、本机用户工作区均使用 Harness 官方 `FileSystemSkillProvider` 逐项发现和加载；每处均为 185/185，均允许模型调用，没有加载警告。

逐项资源、领域入口、嵌套调用与运行条件见 [完整核对表](checks/skills/report.md) 和同目录 `report.json`。这是开发核对工具，不是用户执行业务前的审批或校验门禁。

真实本机 MCP 接口核对包括材料工具 11 个、法律业务工具 17 个；四套主业务方法中的 38 处明确工具引用均能对应已注册工具，接待、合同、办案、庭审方法均能读取。

只读检查了本项目 42 个会话的工具事件元数据，共 346 次工具调用。未发现未知工具名或 Skill 加载失败。真实会话异常中，9 次是 Windows-MCP 在用户操作电脑时返回 `USER_CONTROL`；另有 4 次属于已修复的历史问题：方法路径、DOCX 正文读取、无扩展名图片。报告不复制客户正文、密钥或其他项目聊天。

## 本次修改

1. `bridge/server.py`：解析器明确失败时通过 MCP 正确标记错误，保留原有原因、恢复提示和原文件。此前超时、子进程失败、损坏返回等分支返回 `{error: ...}`，协议却标为成功。`no_text`、正常结果、分批续读仍保留原有结构。
2. `impeccable`：Windows 启动命令以加载器提供的真实 Skill 目录为准，不再指向本平台不存在的 `.agents` 路径。引擎未安装时沿用原 Skill 的说明与回退流程，不因缺少可选引擎阻塞工作。
3. `windows-desktop`：遇到 `USER_CONTROL` 不换工具反复抢控制权；文件和材料部分优先通过专用工具继续，需桌面操作的部分等待用户释放控制权。
4. 全部 185 个 Skill 配置对应中文名称，名称映射保存在 `config/skill-labels.zh-CN.json`。原生调用记录、斜杠技能选择列表、消息中的技能标签显示中文，候选列表支持中英文搜索；调用参数、历史记录及内部 ID 不改名。用户自加的未知 Skill 保留其原名。

中文 UI 补丁：`patches/@deepseek-ai__dsh-client-ui-skill@0.2.2-alpha.2.patch`，已登记于 `pnpm-workspace.yaml` 与锁文件。更新映射时，在同版本的干净 `pnpm patch` 目录运行 `python scripts/prepare_skill_labels.py <补丁目录>`，然后 `pnpm patch-commit`。不要直接改正在运行的 DOM 或重命名 Skill 目录。
