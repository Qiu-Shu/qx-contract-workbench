# JustOneAPI 小红书拓客内容真实联调

基于产品 0.2.16 / `b802e214d66c694e91350e59d57917c611ae1581`。分支仍为 `codex/skill-integration-checkpoint-20261102`，保留既有未提交工作；本轮没有提交、推送或发布安装包。

## 已验证的流程

以“劳动争议 / 企业负责人”为明确标注的示例画像，真实 JustOneAPI 搜索和详情读取已成功。取得 20 条候选，选取 6 条进入报告，其中 5 条正文、1 条视频标题简介；没有视频转写。四组搜索分别为业务方向、业务方向加目标客户，搭配热门和最新排序。

真实工作台主机使用锁定的 `@deepseek-ai/dsh 0.2.2-alpha.2` 与 Node 24.22.1，加载本仓库实际知识库和内容任务模块。已采集内容经实际任务服务保存，未入队缓存通过 HTTP 操作继续提交，真实 DeepSeek 请求成功；Agent 发出 `turn/end.reason.kind=completed`，结果进入 `qx-content-watch` 会话并保存为报告。停止、重启后，报告字节一致、会话只保留一次原任务提交。

这是隔离的本机主机联调，不是完整 Windows 桌面安装、线上部署或法律意见验收。示例任务在验证后暂停，避免按示例画像持续产生费用。正式律师在工作台填写业务方向和目标客户并启用后，按 72 小时运行；电脑与工作台服务需要持续运行，重开最多补一次当前任务。

## 本轮修复

- 按当前 Harness 的 `completed` 判断成功；模型协议中的 `end_turn` 不是工作台的结束原因。模型配置预检先于付费采集，缺少模型时明确提示。
- 明确尚未提交的失败报告可重试已保存内容，无需重新采集。界面传入报告 ID，画像改变、报告过期或已提交状态不明时，不将“重试”暗中降级为新的付费采集。
- 每个关键词与排序各保留一个队列并交替选择，避免宽泛业务关键词挤掉目标客户结果；保留去重、近一周筛选及每轮最多 4 搜索、6 详情、20 候选的边界。
- 修复任务启动与用户暂停交错时，被旧磁盘状态重新覆盖为启用的问题；保留最新暂停/恢复选择并验证持久状态。
- 实际模型摘要曾出现互动比较错误。数值、发布时间仍由工作台来源记录直接展示，摘要只接收内容、链接、作者、读取范围和零互动线索，避免让模型重写互动数字、比例或排名。选题起草仍保留完整已选来源。

- 真实 JustOneAPI：有效凭据完成 **4 次搜索 + 8 次详情**，均 HTTP 200 / code 0。多出的 2 次详情用于选样修复后的补充核对；四次搜索响应复用，没有重复搜索。此前无效凭据的一次失败另计，不作为采集成功。
- 真实 DeepSeek：使用同一份已采集来源完成 **3 次摘要验证**，各自在独立的验收会话中执行；均 HTTP 200。后两次用于修复观察到的摘要质量问题，没有重新采集小红书。未核对供应商实际账单，不把调用数量转换成费用结论。
- 最新摘要中仍有一句将“没有视频转写”误写成“没有视频”。供查看的核对版明确披露并修订该句，原始模型输出和会话保留；提示词已补充限制。这说明流程成功不等于模型内容完全正确，事实、法条、案例真实性与最终发布内容仍须律师核验。
