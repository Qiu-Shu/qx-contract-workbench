# 案件记忆

案件记忆默认开启，可以全局关闭，也可以只关闭某个案件。它与律所知识库分开：知识库保存律所通用资料，案件记忆只处理律师明确选入的本案记录。

## 使用方式

1. 从工作台侧栏打开“案件记忆”，选择案件。相同名称的案件仍有独立编号。
2. 选择已保存的案件记录加入，或填写记忆内容和来源。系统不会自动导入历史聊天。
3. 查看记忆时，可回看加入时的来源快照、类别、记录时间和版本。客户陈述、内部分析及模拟庭审记录仍保留各自性质。
4. 更正会更新当前记忆并使旧索引失效。来源快照保留，更正后的文字不冒充原文。
5. 删除会移除当前记忆及其本机来源快照，并清理对应 Hindsight 索引。服务离线时显示清理待完成，恢复后重试；原案件记录不受影响。

如果原案件记录后来被更正，选入的旧记忆会标出“来源已更正”并退出检索。应重新选择当前记录，避免把旧来源当作最新情况。

## 运行与隐私边界

- “已开启”表示允许使用案件记忆；本机服务是否就绪、索引是否同步另行显示。
- Hindsight 不可用时，可以继续管理本机记忆，并使用明确标为本机关键词检索的结果。
- 首次使用增强检索需点击“一键准备增强记忆”，下载本机运行组件和检索模型；准备成功后随工作台启动。基础安装包不携带大模型依赖。
- Hindsight 按本机安装标识及案件编号划分独立记忆库。浏览器和模型工具不能任意指定其他 bank。
- 本机存储不代表所有处理均离线：Hindsight 分析所选记忆时会调用配置的模型服务，可能产生模型用量。模型凭据不会交给网页界面。
- 当前增强分析默认使用已保存的 DeepSeek 密钥调用 `deepseek-flash`，本机检索向量使用 CPU ONNX 模型。默认不运行 Hindsight 后台观察整合，也不自动导入聊天历史。模型标识依据 [DeepSeek 当前接口说明](https://api-docs.deepseek.com/quick_start/agent_integrations/)。
- 关闭案件记忆后，模型工具不再读取它；律师仍可在管理面板查看、更正和删除。关闭不等同于删除。
- 已删除记忆可能仍存在于用户此前导出的备份、报告或模型服务侧历史中；本功能的删除范围是本机案件记忆及其受管理的 Hindsight 索引。
- Hindsight 的内嵌数据库在本版本中仅保存可重建的增强索引，不能作为唯一案件档案；本机 SQLite 来源账本保留权威记录。内嵌组件的适用边界见官方安装说明。

## 交付检查

41 项 Python、30 项 Node、3 项打包检查通过；15 项隔离浏览器交互检查通过。覆盖同名案件隔离、来源伪造、修订版本冲突、删除、失效索引、关闭读取竞态、切案竞态、凭据传递和升级设置保留。

Hindsight 1.2.0 在本机真实完成冷启动和暖启动，ONNX 384 维 CPU 模型和 PostgreSQL 正常，代理及原生 API 拒绝未认证访问，原生接口拒绝跨源请求，退出后无 PostgreSQL 残留。详见[运行报告](checks/case-memory/runtime.json)。实际数据库位于应用资料目录；pg0 的程序缓存及实例注册仍使用其官方用户 `.pg0` 目录。

上述冷启动验证使用虚构案件和合成凭据，模型端点被重定向到本机拒绝服务，模型调用计数为零；它与下述真实模型验证分别记录。尚未在另一台干净电脑完成安装验收。超时留存请求无法确认结束时，会继续显示索引清理待确认。
