# 白屏排查与加载恢复

日期：2026-11-04。针对更新期间用户提供的整窗空白截图。

## 查明的情况

- 排查时经历了并行对话正在执行的 0.2.4 安装及重启。日志中后台有明确的正常停止、重新启动记录，未发现本次白屏对应的 renderer crash 记录。
- 后台恢复后，同一安装版页面在独立 Chrome 和使用安装版 `main.cjs` / `preload.cjs` 的真实 Electron 中均正常显示，未复现前端脚本错误。不能据此断言用户截图的原始触发原因已经唯一确定。
- 旧版只检查后台是否可响应及页面导航是否完成，未检查前端根节点是否渲染。HTML 返回成功但脚本失败时，`loadURL` 仍会成功，窗口长期空白。真实 Electron 中用合成故障页面复现了这一缺口。
- 旧日志没有前端脚本错误和渲染就绪记录，因此无法从现有日志还原截图当时的具体脚本异常。不能把缺少记录解释为没有发生错误。
- 并行对话另外确认并处理启动超时后误进入 API 配置页的问题。本次白屏改动不负责密钥保存或后台启动策略。

## 本次修复

`desktop/preload.cjs` 复用已有的连接提示条：前端根节点为空时显示“正在打开工作台”；15 秒后仍为空，显示加载未完成和重新连接入口。渲染成功后自动隐藏；成功显示过的页面后来被清空，则显示中断提示。普通页面内的非致命错误不遮挡可用界面。

不自动刷新窗口或重发模型任务，不修改输入草稿、会话、附件、API Key 和微信配置。重连沿用既有用户操作入口。此检测只负责桌面展示状态，不是法律业务校验或内容门禁。

`desktop/main.cjs` 增加页面导航失败、预加载失败、前端错误类型/行号及加载状态日志。Electron 隔离世界中的 preload 不能可靠接收主页面 JavaScript 异常，因此通过主进程的 `console-message` 事件记录实际错误。日志不记录错误正文、URL、密钥或客户材料。

## 验证

- `desktop/check_page_loading.py`：旧版先失败，修复后 6 组通过；包括空白启动、超时、延迟成功、非致命错误不破坏草稿、渲染后清空和窄窗口。
- `desktop/check_page_loading_electron.cjs`：真实 Electron 与本机合成故障页，确认失败提示、真实主页面错误记录、延迟成功清除提示、根节点再次清空及日志不含模拟敏感内容。
- `desktop/check_recovery_ui.py`：原有后台断线提示、手动重连和草稿保留回归通过。
- `desktop/host-recovery.test.cjs`：9 项通过。

上述测试没有发送微信或模型任务。本机诊断记录位于被忽略的 `.local/white-screen-20261104`，不得把实际页面截图或用户运行配置随源码公开。

## 交付边界

白屏修复修改 `desktop/main.cjs` 与 `desktop/preload.cjs`，已经同步到共同打包目录 `.local/package-updates-0.2.3/app`。保留并行对话的启动恢复及发布工作。正在运行的 `app.asar` 不在线覆盖；新安装包及桌面重启后才会加载这两个文件。

根节点检测针对“应用未渲染或被清空”的空白状态，不能判断所有 GPU、样式或业务内容异常。原截图的唯一触发原因仍缺少当时的前端错误证据；后续遇到同类问题，应核对 `.local/desktop-events.jsonl` 的 `page_state`、`page_script_error`、`page_load_failed`、`preload_failed` 和 `renderer_exit`，再定位具体原因。
