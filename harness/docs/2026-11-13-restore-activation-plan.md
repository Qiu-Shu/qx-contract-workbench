# 备份、恢复和重新启用

用户已确认本轮落地此前提出的三项：恢复可迁移设置与账号重新连接、处置未完成任务、桌面备份至确认启用的完整入口。基线 `2e6d3396`，继续 `codex/audit-0216-fixes`。本轮不构建安装包或更新日常安装，不调用真实供应商；律师人工业务复核继续暂缓。

## 实现选择

沿用现有 Electron 本机设置窗口、restic 备份、Python 快照校验和已安装运行时。原生“工作台”菜单与首次 API 设置页均提供“备份与恢复”。新窗口采用现有绿色主按钮及中文表单，状态、错误和键盘操作明确，不更换设计系统。

原恢复目录的文件与修改时间必须保持，因此不直接在它上面应用配置。将经过完整校验的恢复资料复制成新启用目录，在新副本迁移设置、冻结任务和重绑定路径。旧目录保留，撤回仅切换目录，不删除任一份数据。旧 profile 不直接加载，只恢复已识别的安全偏好，账号走既有重新授权入口。

目录切换采用固定启动根下的原子选择记录，重启生效。初始化前核对 prepared 副本摘要；成功后标记 ready，再允许选择。普通入口继续拒绝原始恢复目录及未完成 prepared 副本。选择记录损坏或目标缺失只进入维护页，不自动创建空业务库。桌面持固定启动根的租约，升级/卸载停止入口共享目录选择逻辑。

## 用户流程

1. 查看当前资料目录，明确当前任务已完成后停止后台进入维护；后台重连、API 保存和更新启动在维护中互斥。
2. 准备固定版本、固定摘要的备份组件。仅明确点击时下载，已核验组件复用。选择父目录，输入口令，创建新备份文件夹。
3. 选择备份和新的目标父目录，恢复为独立副本。检查计数、设置及重新授权项。
4. 逐项保留待办、继续为草稿或取消。微信未处理项、拓客任务、Harness 定时任务及会话 inbox 均冻结，不能仅暂停拓客任务。
5. 准备新副本，安全迁移 locale/微信偏好，旧配置原文留在审计目录。只按已认证旧工作区前缀重绑定会话 header 和工作区登记，不全局替换正文。
6. 确认启用后重启，使用现有 API 设置及微信/拓客连接重新授权；草稿仍需用户编辑发送。可从维护页撤回上一资料目录。

## 模块与验证

- `restore-activation` / Python worker：只读审核、冻结复制、准备摘要、无覆盖发布；原副本不变、破损与并发拒绝。
- `restore-pending`：三类后台任务和 inbox 变成持久待办，继续生成草稿，保留历史；真实固定 Harness 合成验证，覆盖压缩会话、路径和零自动调用。
- `data-location` / `backup-controller` / Electron：固定启动根的原子切换及撤回，维护互斥、主进程持有原生选择路径、严格本机窗口 IPC、组件验证。
- `backup.html/css/js/preload`：可读状态、表单校验、忙碌/失败/重试、待办选择及完成页；浏览器与真实 Electron 的隔离虚构数据操作。
