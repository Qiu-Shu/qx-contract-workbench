# 脱敏预览与律师复核

用户在本会话确认：启用上传前脱敏后，每份材料先在右侧复核，点击“确认使用此版本”后才加入待发送附件。

## 已实现的使用流程

1. 选择标准或深度脱敏，再选择文件、拖入或粘贴；知识库使用相同复核流程。
2. 右侧显示实际发送的提取文字，可展开高亮预览和仅本机显示的原文对照。
3. 可直接编辑文字，选中文字补充脱敏，勾选同时处理全部相同文字；可完整选择一个标记恢复原文，也可撤销上一步。
4. 每份点击确认；本批全部确认后才交给原有附件上传器。关闭/取消、断线、会话切换均不交出未确认副本。切走再切回也不会复活旧批次。
5. 添加附件后仍沿用原有发送操作；本功能不会自动提交模型任务。

恢复原文或直接编辑可能带回身份信息，面板明确提醒以当前文字为准。原件保留，预览是提取文字，不代表保留 Word/PDF 版式、图片、批注和隐藏属性。标准/深度模式的业务信息保留规则沿用此前约定。

## 审计修复

- 已明确识别的名称优先确定边界，裸名称规则不再吞掉相邻的合同用语或否定词。
- 全称中的“大模型”等通用后缀保留，名称主体与其模块简称统一标记。
- 普通测评体系、四轮驱动产品体系不作为专名；补充有具体名称的未加引号赛事。
- 历史错误映射保留供旧副本恢复，但不再用于新材料吞句子；已发送附件不被回写。

对用户指定审计会话的原合同进行了本机复测：原件摘要不变、105 段结构保留；目标合同用语和普通业务术语保留；目标模型统一一个名称标记；目标赛事简称已脱敏。仅是这些明确目标的复测，不能推断所有材料完全匿名。

## 数据边界

4 个运行文件：`bridge/privacy.py`、`plugins/privacy/index.mjs`、`plugins/privacy/client.js`、`plugins/privacy/review.js`。

`prepare?review=1` 返回仅供本机页面使用的比较信息；原件、映射、提取文本、复核凭据和人工调整记录保存在工作区外 `.qx-private/uploads`。`confirm` 校验文档标识与随机复核凭据，另存不可变复核副本；前端验证返回文字与当前编辑文字完全相同，才创建新的纯文本附件。原文件名、映射和原文对照不加入附件。

旧窗口不带复核标识的请求返回 409 并提示刷新，防止沿用自动加入附件的旧流程。拒绝时先流式丢弃本机请求正文，不落盘；这是为了让 HTTP 载体正确返回刷新提示，而不是关闭尚有未读正文的连接。

## 验证

- Python：规则边界、否定句、编号、旧映射、复核凭据、路径、原件保留和最终副本；现有脱敏测试一并回归。
- Node：鉴权来源、格式/模式、实际 Python 调用、复核凭据/路径错误、最终字节一致、旧客户端拒绝。
- 浏览器：手动全部替换、恢复、撤销、编辑、取消、批量、并发、切换、断线重试、HTML 以文本显示、1280/420/320 像素布局。
- 实际提取：TXT/DOCX/PNG × 标准/深度共 6 条链路，逐份确认后由独立测试收件器接收；原件摘要不变。
- 安装版：用虚构材料在独立会话验证选择文件、拖入、粘贴，确认前无附件上传，确认后真实附件收据成功；本机 API 验证保存后的文字逐字一致。
- 独立审阅发现并复验关闭了 A→B→A 会话切换旧批次问题，覆盖准备、排队、确认等待三个阶段。

测试未提交模型任务或微信消息。主体 Python 环境不含 Scrapling，整套测试中 3 个检索测试因此无法导入；改用项目已配置的 Scrapling 解释器后，该检索测试文件 12 项全部通过。未为此安装新依赖或改动检索实现。

公开摘要与发布输入哈希：`docs/checks/privacy-review/`。真实材料、私有比较、凭据、运行配置备份及包含真实侧边栏的截图仅留在被忽略的 `.local`，不得整目录上传。

## 部署和打包

本机安装版的 4 个文件已备份更新，仅重载脱敏插件；没有替换 app.asar、运行安装器或提交模型任务。旧桌面窗口需要刷新或重新打开以加载新面板；不强制刷新用户正在编辑的窗口。

更新备份位于 `.local/privacy-review-deployment/`。重载时需等待文件监听器确认新的模块标识可被管理，再启用；管理 API 返回 applied 不是完成依据，应检查真实 prepare/confirm/旧客户端拒绝结果。短暂连接关闭经诊断是旧请求未读完正文的拒绝分支，不是其他会话重启。
