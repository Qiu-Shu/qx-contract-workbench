# 劳动合同 Skill 实测失败根因

2026-11-16。用户要求查明原因；本报告基于真实模型原答、实际 MCP 调用与离线重放。模型为 DeepSeek Flash，思考 high。未改安装版或更换主模型。律师复核前置已取消，未以律师审批为失败理由。

## 结论

错误有三处来源：自由生成没有持续保持事实约束，工资解析器的条件作用范围过宽，以及金额保护的触发条件过窄。保存回读、Word 和聊天的一致性检查能证明交付的是同一份内容，不能证明内容正确。另有一个评测器错误退出码问题，已单独修复。

| 层次 | 已确认现象与原因 | 证据 |
| --- | --- | --- |
| 生成 | 原答开头准确保留年薪、未读考勤等限制，后面的意见或候选条款却改变了这些事实。提示词只约束模型生成，没有将已确定的单位、人员和事实状态变为不可变字段。 | [第二轮逐例独审](spec-review-retest2.md)，尤其 A/G/H |
| 程序误拦截 | 正常工资行能算；加入无关员工手册“未提供”即不能算。加入肯定性的税前月工资尾句也不能算。身份信息前放同一行说明会使 C-1 不被识别为身份编号，继而触发带符号数值拦截。 | [原调用重放与9个变体](e2e-diagnosis.json) |
| 程序漏拦截 | 实际模型选择 `stage=dispute` 且没有显式 `rule`，试用工资自动规则只在 `hiring` 阶段触发。因此“周期未知”的3500元在普通行动文字里变成“试用期月工资”，最后成功保存。 | [实际原答](e2e/employment-live-01-thinking/wage-unlinked.json)，`employment_review.py` 的 `program_owned` / `stage=='hiring'` 条件 |
| 自由文本检查 | `DraftReview` 只覆盖有限主题和否定/比较句式。肯定的考勤内容和“口头陈述”媒介不在其覆盖范围内；真实引用匹配不检查新陈述是否由该引用支持。 | [实际保存探针](saved-claim-diagnosis.json)，[复现脚本](diagnose_saved_claims.py) |
| 工具流程 | 保存入参的 `findings.items` 是开放字典，必填字段仅写在说明中。首次保存调用缺少部分 `source` 被后端拒绝；模型之后又换引文、传错误偏移并多次重新保存，10轮耗尽，未调用回读和导出。离线补调用可正常导出。 | [调用重放](e2e-diagnosis.json)及独审报告 |
| 评测器 | `withSecret` 把回调异常封装为不可用状态，而调用方只检查是否进入回调；缺少运行组件或结果已存在时可能退出0。 | [永久回归](../../../scripts/evaluate-practice-preflight.test.cjs)，[Standards审阅](standards-review.md) |

## 生成问题已定位到哪里

第一轮候选1/8通过、无专项对照1/5通过；补充约束和法条映射后的第二轮候选2/10通过。各项严重程度并不相同：例如 F 的主体法律与算术问题修正后，仍因来源媒介标签错误未通过；不能把8个失败都说成同等严重。G 的年薪改月薪、H 的具体考勤补造等仍是实质失败。

为区分“没有读懂”与“后续生成失守”，另预先固定 G/H/C 各两次事实提取诊断，只改变任务为事实提取，模型、系统和 Skill 不变。[诊断输入](diagnostic-inputs.json)、[6份原答](model/retest3)：

- G 两次都保留四项元/年，并将4800元/月区分为用户提议；H 两次都没有再把未读考勤写成具体缺勤记录。
- 提取本身仍有错误：G-1新增“口头”及“未协商、未签署、未生效”；G-2替用户确定了拟修改字段；C-2仍写“用户口述”。C-1正确记为文字转述。

这支持“事实能被识别，但后续推导、拟稿没有持续受其约束”的局部解释，也证明 JSON 或分步骤提示本身不够。实验同时改变了输出任务与格式，样本很小，不能单独证明长上下文、模型档次或某句提示词是唯一原因。本轮没有对其他模型做同题对照，不能据此断言换模型就能解决。

金额错误在无工具指令评测中已出现，不涉及 OCR、Word 解析或导出。实际 E2E 的源文件摘要与读取正文一致，也未发生原件被修改。错误不是由已证实的文件损坏造成。

## 工资解析器为什么会误拦截

独立代理使用原始合成材料字节和10次捕获调用，在新 MCP 案件逐轮重放，只替换新案件/笔记标识，结果与实际运行相符。9个局部变体证明三个独立触发因素：

1. 全片段扫描把奖金附件的“未提供”传播到工资可计算性，缺少按字段或句子的条件作用范围。
2. 金额行允许的连接/尾部文字不足，明确的“上述四项均为税前月工资标准”反被识别为未解析条件。
3. 身份头识别依赖行形状；同一行有前导说明时识别失败，C-1 的连字符落入数值/日期保护。将说明独立换行即可通过该单因素控制。

这不是删除所有限制就能修复的问题：跨人员、跨期间、年薪及真正否定条件仍需拦截。正确修复应解析“哪个条件作用于哪些字段”，并保留正反两类测试。

## 保存成功为什么还会交付错误

来源引用校验回答的是“这段引文是否存在于当前本案材料”，没有证明模型新写的事实与引文一致。离线实际保存探针中，引用均为 `matched`：

- “公司考勤记录显示……未出勤记录”与“本轮为员工口头陈述”原样保存；`review_changes=[]`。
- 控制组“公司没有协商记录”被现有规则改成待核，说明检查确实运行，但覆盖有限。

实际 unlinked 案更进一步：笔记、真实 Word 和受保护聊天均保留错误月工资表述。保存记录仍标记 `unverified`，并没有谎称已通过法律认证，但这不足以满足可用稿件的事实准确要求。不能将哈希一致、Word可读、引用匹配或免责声明作为语义质量通过依据。

## 已修与未修

已修复评测器异常退出码，永久回归先2失败，修复后相关17项通过；独立探针确认缺组件时退出1且0次联网。过程中测试隔离路径断言曾失败，已纠正测试中的环境传递，最终结果按实际记录。

本轮没有用继续堆提示词、只增加重试轮数或删除拦截规则来宣称修复上述产品问题。以下仍待实施：

1. 把人员、工资单位/期间、材料读取状态、来源媒介及提议/既成事实分成结构字段，拟稿引用这些字段，不自由重写已知值。
2. 金额约束按事实内容及参数触发，不能因模型选择 `dispute` 或换标题而漏掉；未知单位不得进入确定金额条款。
3. 修复工资解析的作用范围及身份/尾句识别；同一组测试同时覆盖正常和跨人、跨期、年薪反例。
4. 将保存工具的必填与嵌套结构落实到 schema，明确可修正的输入错误与需保留待核的业务状态；待核也可保存回读、导出，不陷入重复核算。
5. 在保存前和实际 Word/聊天中检查结论与已绑定事实、计算结果和法源对应；超出可验证范围的结论继续保持具体待核状态。

以上是根因对应的修复方向，尚未作为产品实现交付。完整 Skill 继续保留候选；下一次实测应先跑这些最小复现，再保留新场景验证，不能只反复抽原题到偶然通过。
