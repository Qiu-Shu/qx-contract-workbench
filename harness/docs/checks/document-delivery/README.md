# DOCX 交付能力合成样稿核验

日期：2026-11-03。所有样稿都是本次构造的合成内容，未打开或修改用户原合同和真实案件材料。

最终回归：项目全套 `pytest -q` 为 **126 passed，21 subtests passed**；本模块 9 个测试全部通过。最终 Word 导出 PDF 中亦核实六项诉请、五项事实和八项证据标识全部存在。

## 核验方式与结果

1. 对生成后的 DOCX 包全部 `.xml`／`.rels` 做解析；单元测试另核对原件字节不变、旧批注／旧修订仍在、未修改部件原样保留、跨 run 与表格精确定位、重复和重叠范围逐条退回、同名另存，以及七种模板的长列表完整性和示例残留。
2. 技能 `render_docx.py` 首次尝试因本机没有 LibreOffice `soffice.exe` 而失败。随后使用本机 Microsoft Word 的独立隐藏 COM 实例，以只读方式打开三个合成样稿，未启用自动修复、未加入最近使用列表、禁用宏；导出带审阅标记的 PDF 后关闭该实例。
3. 每份样稿在 Word 打开前后 SHA-256 相同。Word 识别 `review.docx` 有 2 个批注（原有与新增）及 3 个修订（原有插入、新删除和新插入），并正常导出 1 页 PDF。
4. 起诉状正常导出 2 页，六项诉请与五项事实完整；证据目录正常导出 4 页，八项证据完整，续页重复表头，未给定证据页码均显示“待编页”。
5. 使用项目现有 PDF 渲染库将所有 PDF 页面输出 PNG，并逐页视觉检查。第一次检查发现默认 Title 的蓝色边框、序号表头换行和普通证据行跨页残片，已修复后重新生成。当前页图中标题为纯黑、表格序号表头单行、每页两项证据，未见裁切、重叠或乱码。

## 文件

| 样稿 | 用途 | 最终实测页数 |
|---|---|---|
| source.docx | 带旧修订与旧批注的合成原件，仅供对照 | 未改动 |
| review.docx / review.pdf | 指定段落跨 run 修订、新批注与原审阅历史共存 | 1 |
| complaint.docx / complaint.pdf | 多项长诉请、事实、当事人、法院及落款 | 2 |
| evidence.docx / evidence.pdf | 四列证据表、长内容、八条证据与未编页提示 | 4 |

`word-render-check.json` 记录 Word 页数、批注数、修订数和只读打开前后的文件摘要。`render-pages.json` 记录各渲染页的尺寸和可提取字符数；`*-page-*.png` 为最终页面图。

本次是真实 Word 打开与 PDF 分页实测，另加 OOXML 自检；没有实测 WPS、macOS Word、其他打印机字体或真实案件超长文档。七个模板均经过 XML 和内容完整性测试，实际渲染抽样覆盖修订、买卖合同诉状和证据表三种输出路径。页眉、脚注、域、已有修订段落等未支持的修改不因本次样稿通过而被宣称支持。
