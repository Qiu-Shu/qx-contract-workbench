# 本机知识库与 bb-browser 兼容改动

## 用户反馈后的入口修订

用户反馈“知识库暂时无法打开，请刷新工作台后重试”。读取现有 UI 文件服务得到 HTTP 200 和 JavaScript 内容，说明当时路由能返回源码；没有浏览器异常堆栈，不能据此断言全部根因。原入口依赖额外的原生动态 import 与 React.lazy，且错误边界吞掉具体错误、没有重试入口。

已将 createKnowledgeView 移至 desktop/integration/client.js，随原有官方注册客户端模块一同加载，移除额外 UI 脚本路由及 plugins/knowledge/view.js，避免该独立模块加载与失败缓存。错误边界提供“重试”“关闭”和可展开的具体错误；dialog 生命周期补齐关闭清理。仅重载客户端即可获取新入口，不需要重启主服务。用户此前取消验证的要求继续有效：只做故障读取和代码修改，未运行测试或浏览器验收，未重建安装包。

用户确认第一版为本机内置知识库，可上传、检索、引用资料；同时明确取消本轮测试和实际操作验收。下述内容是已写入的实现和配置，不是通过验收的声明。

## 知识库

侧栏新增“律所知识库”，同一程序内打开资料管理窗口。上传可选分类；每次上传使用新标识保存原件，同名资料不会覆盖。相同内容记录 duplicate_of，但不擅自删除用户上传。文件支持范围复用现有文档桥，包括 PDF、Word、常见文本/表格/幻灯片和图片；复杂格式及 OCR 仍受现有解析器限制。

资料保存在当前工作区 knowledge/documents，独立索引在 knowledge/.qx-materials/index.sqlite。不会扫描本机其他目录或导入其他案件、聊天、第二大脑。案件材料列表排除 knowledge 子目录，知识库索引不混入案件材料索引。

索引在本机后台串行处理，PDF 按二十页分批。界面显示等待/解析、完成或错误状态；解析失败保留原件，可重新解析。主机重启导致的处理中状态显示“解析中断”，不当作已就绪。

全文检索复用 Python 内置 SQLite FTS5 trigram；短词采用原文匹配。多个关键词空格分隔按任一词匹配，命中按全文相关性排序（短词匹配按资料时间排序）。此版不等于向量语义检索，不下载 embedding 模型，也不配置远程向量服务。正文检索不保证完整自然语言问题直接命中，助手路由要求拆成关键词。

来源引用为 KB:资料ID:片段编号:文件哈希前缀。检索结果提供资料名、页码/段落、摘要；点击可定位原文，复制时回读引用并核对完整文件哈希。AI 的 read_knowledge_citation 采用相同路径。归档撤出检索和引用，保留原件，可恢复；历史已经发送的对话不会因此被抹除。

上传、索引和检索不调用远程模型。助手使用命中片段回答时，片段随已配置的模型请求发送；此事实已写入界面与工作区路由，不能宣称“全程离线问答”。历史范本不能视为现行法律或当前案件事实。

## 复用项目调研与取舍

| 来源 | 调研结论与本次采用范围 |
| --- | --- |
| [TencentDB-Agent-Memory](https://github.com/TencentCloud/TencentDB-Agent-Memory/tree/feat/server_team) | 当前默认分支包含 memory-core、memory-hub、proxy 多服务以及团队记忆资产。借鉴归属、版本、状态、来源的管理思路；不接管现有模型代理，不自动提炼聊天或上传律所资料至腾讯服务。 |
| [AnythingLLM](https://github.com/Mintplex-Labs/anything-llm) | 官方仓库提供本地文档问答、上传与来源引用等完整产品能力。借鉴资料列表与引用操作方式；整体引入会重复现有 Harness 和聊天界面，本次不安装第二套应用。 |
| [RAGFlow](https://github.com/infiniflow/ragflow) | 强调文档理解、切块、知识组织与检索；本次已具备解析器，暂不引入整套服务。 |
| [RAGLite](https://github.com/superlinear-ai/raglite) | 当前 README 使用 DuckDB/PostgreSQL、embedding 和 reranker 组成 RAG 流程；不是可无配置直接替换现有 SQLite 的组件，本次不引入。 |
| [sqlite-vec](https://github.com/asg017/sqlite-vec) | 可用于后续本地向量检索；仍需要向量生成模型与相应部署，并非装扩展就具备语义理解。第一版只记录为候选。 |
| [SQLite FTS5](https://www.sqlite.org/fts5.html) | 实际复用已有 SQLite 的全文索引；trigram 支持子串匹配，少于三个字符的查询采用原文匹配。 |

本次没有复制上述仓库源码，没有新增第三方包。使用现有代码与标准库，实现适合当前一键安装路径的本机版本。未来多人共享仍需身份、访问权限、服务器和备份方案，当前不宣称支持。

## 浏览器改动

此前原生点击无事件的问题有相同的 [上游 Windows 报告 #183](https://github.com/epiral/bb-browser/issues/183)。源码中的 click 直接调用 CDP 坐标事件；press 只传 key，缺少特殊按键所需的完整键码。本轮没有重现实测，点击原生失效的根因仍不能断言。

改动在工作台 bridge/browser.py，不修改用户全局 npm 安装：

- snap 后保存实际节点身份；click 使用最近快照节点进行一次 DOM 激活。目标断开、不可用或被遮挡时拒绝，不按同一 XPath 猜另一个新节点；点击后旧快照失效。
- 不先尝试原生点击再补点，避免重复提交。DOM 激活不是可信鼠标事件，iframe/shadow DOM 或依赖可信事件的网站可能仍需桌面工具或人工操作。
- press 经 browser-keyboard.mjs 发送完整 key/code/windowsVirtualKeyCode/nativeVirtualKeyCode 和修饰键，目标页置前并临时获得焦点模拟。只连接显式本机地址或 bb-browser 管理的本机端口；完整 tabId 必填。支持常见特殊键和字母数字组合，正文继续使用 fill/type。
- 返回 action_dispatched 只表示动作已发出，business_outcome 明确 not_checked。没有自动补点和业务成功推断。旧 docs/checks/web-tools 的结果仍是旧版证据，不证明新代码通过。
