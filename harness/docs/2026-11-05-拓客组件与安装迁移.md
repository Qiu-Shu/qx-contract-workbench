# 拓客内容助手：组件准备与安装迁移

本片负责发行与迁移；任务、画像、会话派发和界面由 `plugins/content-watch/` 实现。

2026-11-08 更新：默认采集方式已改为 JustOneAPI，下述本机组件作为律师显式选择的替代方式保留。API 方式不下载或启动本机爬虫。最新范围与验证见 [一期开发交接](2026-11-08-拓客内容一期开发.md)。

## 安装与现有用户

`packaging/stage.py` 和 `refresh-stage.py` 明确携带 content-watch 插件、`scripts/prepare-content-watch.mjs` 与 Apache-2.0 声明。构建校验会拒绝缺少入口或准备脚本的包。首次安装和升级通过 `installed-runtime.cjs` 调用独立的 `content-watch-v1` 配置迁移。

配置使用当前用户的 `@DATA@/workspace` 与 `@DATA@/.local/content-watch`；组件代码使用 `@APP@/plugins/content-watch/index.mjs`。迁移只补缺失的插件 ID，备份原配置，不覆盖已有同 ID 的用户设置/停用选择，不创建任务、账号或登录态。与现有安装迁移一致，修改过且无效的配置会保持原文件并报告错误。

## 显式准备组件

后台仅在用户选择准备/连接小红书时调用：

```js
import {prepareContentWatch} from '../../scripts/prepare-content-watch.mjs';
const {executable, version} = await prepareContentWatch({stateDir});
```

源码开发诊断也可运行 `node scripts/prepare-content-watch.mjs <stateDir>`。这个脚本只下载及校验，不启动任何产物，不读取已有账号文件。之后的 `xhs-runtime.mjs` 负责独立进程和登录会话。首次启动上游组件还可能联网下载专用浏览器，应在界面说明准备可能需要一些时间；二进制准备成功不等于浏览器准备、平台登录或内容采集成功。

上游固定为 [xpzouying/xiaohongshu-mcp v2.7.2](https://github.com/xpzouying/xiaohongshu-mcp/releases/tag/v2.7.2)，已查询 annotated tag，指向本次审查的源码提交 `539d296f5623ab1a359065d8dc74dccfb237b05a`。以下 SHA-256 来自该 GitHub Release 资产元数据；程序会按大小和摘要拒收不一致的下载。

| 系统 | 大小（字节） | SHA-256 |
| --- | --- | --- |
| Windows x64 | 16,353,280 | `1f62e1fe137d0293595197b3a76e280e4114293b425e9c4082a334d1f7fb5316` |
| macOS ARM64 | 16,834,514 | `e3068363fc4d6572d1e4cf2aeccda7e1d37844191aa8ce0944706f73700a4130` |

文件保存到 `stateDir/runtime/xiaohongshu-mcp(.exe)`，同目录携带许可证。下载先写独立临时文件，验证后原子替换；失败保留旧组件，账号目录不受影响。并发准备共享同一任务，阻止重复下载。脚本拒绝链接目录，不在代码仓库保存用户的下载或登录资料。

## 本机验证范围

- 新增迁移与准备模块按失败测试后实现；迁移验证原文件备份、自定义停用选择、重复运行、不完整配置不标记成功。
- 下载模块使用合成字节，验证校验成功/失败、大小错误、网络错误、并发和符号链接拒绝。没有执行第三方可执行文件。
- 新增 portable 配置测试使用隔离配置，验证应用代码/用户数据位置明确，开发路径不会进入新插件配置。
- 本机无法完成原生 Windows 安装构建。原 `test_stage.py` 中 Windows 长路径复制、开发机绝对路径两个检查在 macOS 上失败，未扩大到本功能之外修复；不可把本片离线检查写成整包构建或新安装验收通过。
