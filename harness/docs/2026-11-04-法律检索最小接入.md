# 法律资料检索接入交接

本次按用户批准的最小方案接入：保留 Harness 的 DeepSeek 检索，只增加一个匿名备用渠道。没有安装 union-search 全套依赖，没有接入媒体下载、本机账号令牌或额外模型，也没有添加业务审批步骤。

## 用户能得到什么

- 法律资料调用显示为“法律资料检索”；回读显示为“读取法律检索资料”。现有法律 Skill 共用这两个工具，无需新增或选择另一套 Skill。
- `legal_search` 先调用 `ctx.web.search`。某条查询失败或无结果时，才使用 360 备用；正常成功不重复搜索。取消后不再启动备用；排队时取消也能立即保存进度。
- 每条查询完成即保存。部分查询失败仍保留其他查询的结果，所有渠道返回的原始结果分别留档，URL 去重后保留来源、查询词和可打开的原链接。
- 完整返回内容保存在工作区 `research/web/<recordId>.json`。默认显示 8 条目录；`legal_search_read` 用 `offset` 继续看，或用 `entry` 读某条、`start` 接着读长摘要。分页只控制本轮输入模型的内容，不删除文件中的结果。
- 提示模型用抽象法律争点搜索，按需打开官方原文；不会把上传的整份合同自动送到搜索引擎。

这里的“完整”指渠道实际返回的数据，不代表已经下载了全部网页正文，也不代表检索穷尽。原网页仍通过现有 web_fetch / Scrapling 读取。

## 真实验证与限制

2026-11-04 使用三个公开查询：合同编通则司法解释、民法典、劳动争议司法解释（二）。

1. 原生 `web_search` 经真实模型调用成功，返回 8 条合并展示来源。
2. 新工具经本机真实模型调用成功，三条查询全部由主渠道返回，共保存 29 条去重后的来源，并成功调用 `legal_search_read` 回读。仅查询公开资料，没有使用案件文件或微信发送能力。
3. 360 前期三条查询均获得 7 条结果；抽查了最高法国际商事法庭、市场监管总局和最高法的三条公开原文，网页可打开且内容相符。
4. 继续压力式连测时，360 出现验证码。通过安装版 Python 的真实调用返回 `CAPTCHA`，同批后两条备用请求返回 `COOLDOWN`，没有反复请求或把挑战页当成资料。这是明确的外部可用性限制，不能承诺匿名备用永不受限。百度和搜狗也实测遇到验证码，因此未加入更多同类渠道。
5. 42 项 Node 检查和 12 项 Python 离线检查通过，包含存档、分页、中文展示定义、主备切换、超时、取消、验证码识别、迁移与用户配置保留。公开证据摘要见 `docs/checks/legal-search/report.json`。
6. 隔离浏览器打开上述真实测试会话，验证检索/回读中文卡片、展开后的 8 个来源链接和保存数量，页面错误为 0；没有切换用户桌面中的会话。

主渠道某次只返回标题和链接时，回读会如实保留这些内容，不编造摘要。需要引用法条内容时仍应打开官方原文，不能把 HTTP 成功等同于现行有效。

## 文件与复用来源

- `plugins/legal-search/core.mjs`：主备调度、错误状态、原子保存、去重、分页回读。
- `plugins/legal-search/index.mjs`：Harness 工具、中文调用卡片、模型路由说明、Python 子进程生命周期。
- `desktop/integration/client.js`：原生 `tool.call.toolview` 槽位中的中文检索/回读卡片。不能仅靠后端 `presentCall` 设置标题：当前 Harness 列表使用客户端渲染器。
- `bridge/legal_search_fallback.py`：现有 Scrapling 运行环境下的匿名 HTTP 请求与失败分类。
- `bridge/vendor/union_search/`：最小解析器、MIT 许可证及 `NOTICE.md`。
- `config/cordis.patch.yml` / `config/workspace-AGENTS.md`：开发环境配置及规则。
- `desktop/installed-migrations.cjs` / `installed-runtime.cjs`：已有安装增量迁移，保留凭据、自定义设置及已禁用插件。
- `packaging/stage.py` / `refresh-stage.py`：将上述代码与已存在的 Scrapling 运行环境纳入后续安装包。

## 本机与 0.2.6 发布

本机通过独立扩展目录 `.local/legal-search-runtime` 装载，使用现有工作区及安装版 Scrapling Python。扩展路径位于应用数据目录，避免并行准备的旧安装包替换程序目录时丢失新工具；将来的安装包会刷新这份应用自有代码。没有替换运行中的 app.asar，没有改写模型密钥。
