# 法官背调与开庭提纲

把一位法官的公开信息，整理成一份能直接带去开庭的工作文件。

## 这个技能解决的问题

律师在二审分到主审法官之后，需要摸清这位法官的裁判偏好，再据此决定主攻改判还是主攻发回。公开信息散落在裁判文书、开庭公告、人大任免文件、法院公众号、学术数据库里，逐一翻找耗时，而且容易把推断当成事实写进报告。本技能固定检索路径、固定来源分级、固定成稿结构，保证每一份提纲的结论都能追到出处。

## 三条硬约束（不可协商）

1. 全文零半角符号，只用中文标点。生成后必须跑自检，ASCII 标点计数必须为零。
2. 数字一律中文写法。日期写二〇二六年十一月八日，比例写百分之三十八点五，不用百分号、不用小数点、不用箭头与星号。
3. 每篇独立成稿。不写“与上一篇不同”“承前所述”，不假定读者看过其他法官的材料。横向对比只在用户明确要求时做。

## 工作流

### 第一步　确认锚点

问清或确认五件事：法官姓名、所在法院、所在庭室、案件案由、本案所处程序。姓名必须用法院加庭室加年份三重限定排除同名。姓名不确定就先做检索确认，不要凭猜。

### 第二步　按三十二路检索

读取 `references/channels.md`，按五组顺序逐路检索，每次作业不少于二十路。每路记录检索式、日期、有效信息、印证来源，直接写成附表一的行。发现有效线索时用联想收集法跳转：拿到学校就反搜学生生涯与学位论文，拿到导师或合著者就反搜学术圈，拿到同组法官就反搜其裁判尺度。

### 第三步　分来源等级

- 甲级：裁判文书落款、人大常委会任免文件、法院官网公示。可直接引用。
- 乙级：开庭公告、律所公开案例页、百科词条、法院公众号报道。可证明时间与参审，不能单独证明审判职务。
- 丙级：由甲乙方信息推出的结论。必须写“推断”二字，且不得进入庭审发言。

样本不足时写“不足以形成比例结论”，不要为了凑数据把未核对的文书算成维持。这条比数据好看重要。

### 第四步　写 JSON 内容稿

按 `references/format.md` 的区块语法写一份 JSON。区块类型有七种：h1、h2、body、item、tip、caption、table，另加 pagebreak。推荐章节顺序：

一是先看这一页（三到五条结论）；二是已查实的事实；三是履历读法；四是数据缺口与替代口径；五是开庭提纲（调查五问、举证质证、辩论三层、最后陈述）；六是两条路线与本案取舍；七是庭前待办清单；最后两张附表。

`templates/blank_outline.json` 是填好的骨架，每一处占位都写成【待填：……】。做法是复制这份骨架，逐处替换，不要从空白文件开始写。骨架生成的 `templates/法官背调与开庭提纲模板.docx` 可直接给用户当纸质稿用；`templates/参考范本-通用背调提纲.docx` 是十章方法论的完整范本，用于向用户解释结构与口径时引用。

### 第五步　生成与自检

```
python scripts/build_dossier.py 内容稿.json 输出名.docx
```

脚本会自动做三项检查并在命令行报告：半角符号计数、每张表列宽合计是否超过版心、段落与表格数量。半角符号计数不为零时，回改 JSON 再生成，不要在 Word 里手工替换。

### 第六步　版式复核

Windows 下用 `references/verify.md` 里的 Word COM 片段逐段取所在页码，确认没有标题孤行、没有表格跨页断裂。附录表一律各占独立一页。macOS 无 Word COM，改看导出 PDF 的分页。

## 交付件的形态

一张 A4 七到八页的 Word 文件。首页顶部是标题与副标题，紧接第一条结论，不放封面页、不放目录。正文宋体小四、一点五倍行距，一级标题黑体加粗。末尾两张附表分别是检索台账与结论一页纸，后者留一格给“本案主攻方向与三条理由”，这是整份文件的落点。

## 常见错误

- 把开庭公告里的法官栏当成审判职务证明。公告常把承办法官与法官助理并列，认定职务要看人大任免名单或文书落款。
- 用代理样本倒推出某位法官的发改率。代理数据只能定方向，不能写成该法官的指标。
- 为了版面好看删掉待核实清单。缺口本身就是信息，写清楚比填满更有用。
- 在正文里做跨篇引用。每篇自足。
