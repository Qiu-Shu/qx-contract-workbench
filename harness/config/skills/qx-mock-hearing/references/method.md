# 五阶段庭审方法

适用：围绕本案明确材料进行民事原告/被告演练。我方立场由用户明确，不能从甲乙方或材料先后猜测。当前服务只负责组织和保留发言，不负责事实认定、自动外发或案件结果预测。

| 阶段 | 实际发言顺序 | 本阶段产出 |
|---|---|---|
| `issues` 争点整理 | `moderator` 主持、`plaintiff` 原告、`defendant` 被告 | 请求、回应和真正存在分歧的问题；分清双方说法与材料支持。 |
| `evidence` 证据核对 | 原告、被告 | 各自材料能支持什么、不能证明什么；逐项指出来源和缺口。 |
| `questions` 双方问答 | 主持、原告、被告 | 对关键事实、时间、金额、条件及相反材料提出具体追问并回应。 |
| `debate` 辩论 | 原告、被告 | 围绕已确定争点回应对方最强主张，保留尚未解决的事实与解释分歧。 |
| `review` 复盘 | `reviewer` 复盘 | 按实际记录归纳争点、答复不足、补证事项与下一步准备。 |

主持和复盘使用中立语言，不冒充真实法官；原告和被告各自提出最有力且有材料基础的观点，不为配合剧情编造证据。无资料支持时说清假设和待核问题，不补造真实人物经历或心理。

未明确诉讼请求时，不自行将演练目标改为“解除并退款”等具体诉请；可以条件式说明不同请求需要什么事实。未知是否交货或验收时，双方不能用第一人称断言“我已经交货”“从未验收”“对方已使用”；应写成“若能证明交付和使用，可提出……，目前缺少……”或直接指出待核问题。每条发言就地标明假设，不靠最终统一免责声明把编造的事实洗成有效主张。反方的价值在于检验己方依据和举证缺口，不靠补造一套反方事实。

每份演练冻结本案关联材料的路径、内容摘要和版本，以及当前 `consultation`、`fact`、`stance` 输入笔记的编号与全文摘要。原件改变、增添材料、缺失或输入笔记更正时，旧记录仍可读取，新发言须通过显式关联前序的新演练继续。角色上下文把 `evidence_materials`、`source_notes` 与 `simulation_turns` 分列；长笔记预览带分页位置，须按原编号续读。客户回复、内部笔记和演练输出不纳入事实基础，不会因复盘而自动重开；模拟言论不得作为新证据回灌到案件事实。

建议每个角色聚焦当前最关键的争点，避免同义复述。需要更长演练时按用户要求继续，而非为了凑轮次调用工具。保存完最后一项才算本次结构完成，结构完成不代表事实、法律依据或裁判结果已经核验。

每次实际生成一条发言后即调用 `record_hearing_turn` 保存，再按返回的下一阶段和角色继续；五阶段共十一条，不提前填充未完成发言。续接先 `get_hearing`，只有案件编号时用 `list_hearings(case_id)` 找回本案演练，不能混用别案或仅按全局最近时间猜测。发言列表按 `next_offset` 续读，长发言的预览按 `next_start` 调用 `read_hearing_turn(hearing_id, turn_id, start)` 回读全文。恢复后从已保存下一项继续，重试同一发言沿用 `request_id`，不重复生成已完成阶段。

阶段/角色顺序摘自旧工作台 `src/cn_contract/integrations/chiheng.py`，固定版本 a26ae24；没有加载其私有外部引擎或严格回答 DTO。MiroFish 的逐轮记录和定向采访机制仅作设计参考；其人物画像、社交平台、Zep 云图谱与预测宣传未迁入。具体来源见同目录 `sources.json`。
