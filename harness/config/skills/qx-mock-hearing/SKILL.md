# 庭审演练

先读取 [references/method.md](references/method.md)。本能力复用旧项目的阶段与角色顺序，新建本机记录服务；原私有持衡引擎没有恢复。MiroFish 仅提供角色与运行记录的设计参考，没有接入其云图谱或社交模拟引擎。

未知事实用条件式抗辩，不编出“已交货”“已使用”等第一人称经历。没有明确诉请时，不擅自替用户选择解除、退款或赔偿；按已知争点检验依据，具体参见方法。

## 开始与续接

1. 使用用户明确的 `case_id`，或通过案件工具识别并展示对应案件；不能取全局最近案件。普通短问答不强制建案。演练需要明确我方为原告或被告，未知时只询问这个必要信息。
2. 用 `get_case` 返回的 materials 核对本案已关联材料，按需通过 `read_case_material` / `search_case_materials` 阅读。不要把同工作区其他案件当成材料。
3. 新演练调用 `start_hearing(case_id,our_role,focus,request_id)`；继续既有演练先调用 `get_hearing(hearing_id)`，从返回的 `next_stage` / `next_role` 接续。请求编号在一次操作的重试中保持一致。
4. 为当前角色调用 `get_hearing_role_context`。它分列冻结材料、`source_notes` 客户原话/事实/立场和模拟发言，不会代读附件原文。笔记的 `content_preview` 不是全文；若 `next_start` 非空，通过 `read_case_note(case_id,note_id,start)` 续读。模型笔记仍是待核陈述，不能因保存就当成已确认事实。

## 发言和记录

- 输出自然语言，不要求用户阅读或编写 JSON，也不让正文满足旧 DTO 字数和字段约束。
- 每实际完成一个角色发言，调用 `record_hearing_turn`，参数为 `hearing_id,stage,role,text`，可另附 `citations,unresolved,request_id`。`citations` 可用 `{path,quote,chunk}`；只填实际读到的逐字出处，不猜字符偏移。
- 每个发言用稳定的请求编号，例如 `演练编号:阶段:角色`；超时先回读，再用原编号重试。不得预先记录尚未执行的后续阶段。
- 工具返回 `recorded:true` 才说明该发言已保存。引文未匹配时正文仍保留，向用户明确待核；`matched` 仅证明材料中存在逐字摘录，不证明主张成立。
- 如果返回 `recorded:false` 且原因为 `materials_changed` 或 `context_changed`，保留并展示本次已生成的文字，不把它说成已入旧轮次。用户补件或更正后要求继续时，先关联新材料/保存更正原话，显式调用 `start_hearing(...,previous_id=旧演练编号)` 新开演练，旧发言不覆盖。不要偷偷在旧快照内续写。
- 每阶段结束可简洁呈现已记录要点；用户要求暂停就停在当前记录。最后的复盘角色保存后自动结束；再次打开只需回读，不重新运行模型。

## 角色执行方式

当前运行时确实提供可用的独立 Agent 工具时，可按角色派发并提供该角色的材料与发言上下文，再顺序记录实际返回内容。没有这些工具时，在当前对话按角色完成演练，明确这是同一助理的角色扮演，不宣称独立智能体、相互盲评或隔离记忆。无论采用哪种方式，都不编造未发生的执行、法官意见或胜诉概率。

最终交付争点、双方回应、关键未答问题、补证与庭前行动清单；用户需要文档时，通过现有 `write_word_draft` 生成真实 Word。模拟发言与原始证据分开引用，继续标明待律师核对。
