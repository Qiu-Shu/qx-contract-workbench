# 劳动解除清单与情景归档

本方法提供解除初审条件清单和材料所列假设的算术，不能代替事实认定、完整劳动争议分析或地方规则核验。

先确认本案ID并用 `mcp__qx_legal__read_case_material` 回读已关联原件。引用用实际返回的 path、sha256、ordinal（填到 chunk）和逐字 quote；已知到手工资照录，不等于法定工资基数，其他未知项不能使已知事实消失。

调用 `mcp__qx_legal__assess_employment_termination(case_id, citations)`。citations为1至30条原文引用，不传模型判断的事实布尔值。程序生成不同解除路径、通知/代通知金及历史分段等条件清单，不自动选定任何路径；开业日、入职日或拟生效日不自动成为实际解除日。

## 同时要求计算并归档

材料已明确给出独立完整一行的假设时，可在同一次调用中追加 `scenario_citations`（每项仍为 path/quote/sha256/chunk），最多10项。支持格式示例：`情景假设：基数12345.67元，折算年限3.5年，倍数2。` 数字必须来自本案原文，不能套示例。

程序解析假设、复用精确计算器，并与清单保存为同一条笔记。各情景分别列示，不相加、不当作实际应付款。没有合格原句时说明联合归档尚缺明确情景来源；不从到手工资、入职年份或未知终点猜参数，也不把自己的改写登记成原始材料。独立纯算术可使用现有 calculate_employment_amount，但不能声称已并入清单或Word。

## 保存与交付

- recorded成功后，用返回的 id 调用 `read_case_note`，按 next_start 回读全文；需要Word时 `mcp__qx_legal__export_case(case_id, note_ids=[id], audience="internal")` 导出同一记录。
- 最终使用返回的 user_summary 和实际成功生成的文件链接，算式也以已保存的同一内容为准；不在聊天另加未归档的事实摘要或金额。工具没有计算时不得声称已计算。
- recorded=false、来源失配或导出失败时保留失败状态，不把旧文件当作本次成功结果。request_id只用于同参数重试；supersedes仅在用户明确要求更正时使用，保留旧记录。

工具缺失时如实说明本流程未执行，不改用自由正文绕过来源和版本校验。录用、变更、竞业等其他劳动需求不由本窄方法宣称完成。
