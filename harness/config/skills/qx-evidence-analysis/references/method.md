# 办案方法与保存约定

## 最小工作底稿

围绕请求或抗辩，将规则拆为当前争议的单一待证命题。举证责任与证明标准依实际案由、程序和有效规范确定；没有可靠规则时列待核，不套用一个固定阈值。每个命题交付：现有支持材料、反对材料、未知与缺件、三性待核问题、当前分析及补证动作。补证说明补什么、向谁核实、要解决哪个命题；申请法院调取/责令提交须另核法定条件、期限，不能把一般缺件写成拒绝举证或当然不利推定。

原句必须同时标陈述主体和来源载体；转述还应保留“谁转述谁”。材料明确写出的事实可称“材料记载”，不能直接变成法院已认定事实。未知载体不补造。履行催告不能仅凭发生于签约后就证明签约时合同不存在；签收和验收、主张和承认、承认某段文字与承认全部请求也应分开。

支持/反对材料须实际指向同一命题：抽象违约主张不能补成特定违约行为，对某材料证明限度的异议不能自动反驳实体义务，缺少某种材料不能充当相反证据。不能完成这一对应时，放入证据异议或未知/缺件栏，并说明现有内容能证明到哪一步。表格和正文采用同一标准。

填写反对材料栏前，指出材料中哪一句内容与该命题不相容；若理由只是“未写到、未见、未提供”，这一项放未知/缺件，不放反对栏。文件存在只证明有该文本，制作、发送、到达和生效是不同事件；对每个已发生动作分别寻找事实依据，不能凭通知或函件本身补出已经发出。

真实性审查关注原件/原始载体、主体身份、生成取得保管过程、完整上下文、修改痕迹及相互印证；电子数据另看账号对应、完整导出、生成存储传输提取与原始设备。合法性核查取得方式及适用规则；关联性核查它具体证明哪个命题及限度。不要因仅有截图、存在争议或尚未核验就认定伪造或一律排除，也不要用原句定位代替三性结论。

这些是核查方向，不是已观察到的缺陷。只把题设或实际读到的属性写成事实；未说明的平台、时间信息、生成设备、提取方法、签字或在场记录，保持未知，不能由模板补成缺失或不存在。材料被称为摘要、截图、录音等，不足以断定其取得合法或违法。程序记录未提供，只能说尚不能判断相应条件是否成立，不能说条件不存在，也不把举证责任本身推迟到法院通知后才存在。

## 实务摘要

直接给“案件及阶段—请求与争点—按时间与来源排列的关键材料—可支持与不可支持的结论—缺口和下一步”。没有裁判或程序记录就标未提供，不写成尚未起诉、尚未举证、法院已采信。保留原金额、条件、日期、范围；假设规则只在明示条件内使用，不外推出新的期限或拆分交易规则。

## 引文与工具

先使用本案材料读取工具取得 path、sha256、chunk、page/location；已有逐字摘录可用 `ground_case_extractions` 本地核对。引用保留 quote、sha256、chunk、start/end 与返回状态。重复原句 ambiguous、unmatched 和版本变化都继续保留正文及警示，补上下文再定位，不能删掉 null 位置或改标 matched。只用明确关联本案的材料，不用另一案文件补空缺。

`save_evidence_analysis(case_id, issues, request_id='', supersedes='')` 保存每项以下结构：

```json
{
  "proposition": "需要证明的单一命题",
  "finding_kind": "unknown",
  "assessment": "当前分析，明确材料陈述与推断边界",
  "supporting": [{"statement":"材料陈述或内容", "speaker":"原陈述主体或待核", "carrier":"明确载体或待核", "citations":[]}],
  "opposing": [],
  "unknown": ["材料未提供，事实是否存在待核"],
  "admissibility": {"authenticity":["真实性待核问题"], "legality":["合法性待核问题"], "relevance":["关联性待核问题"]},
  "supplement": ["需补材料和解决的命题"]
}
```

finding_kind 仅为 material_statement（材料记载而非认定事实）、inference（推断）、unknown（未知）；supporting/opposing 中 citations 为引用对象列表，未定位可为空但必须说明待核。不得向 issues 添加评分字段。每次1至30个命题；单个列表至多30项，每项材料引用至多20个；正文过长按争点分批。

返回记录含 id、saved、citations、warnings、review_status；`legal_verified=false` 始终表示待法律复核。引用状态由本机重新核验，不信任输入 matched。`saved=false` 时保留未保存内容并按原因续办，不能宣称成功。长正文须按 read_case_note 的 next_start 分页读完。更正依据和更正原因分开：用户确认新值可以形成拟更正底稿，不能因此猜旧值是笔误、录入错误或伪造，更不能在尚未保存时写已更正。

更正追加同类记录并保留历史。保存后回读新记录，`export_case(audience='internal', note_ids=[当前新记录ID])` 只接收当前记录；已被 supersedes 的旧记录不能混入 note_ids，历史用 `get_case(include_history=true)` 或 `read_case_note` 另行查看。客户版不能直接包含内部证据策略。导出不等于法律审核通过。

## 官方法源索引（开发核验：2026-11-05）

已联网打开最高人民法院官方正文，并检索后续修正；本次未发现替代以下证据规定的更新版本。此为开发参考索引，不是每个案件已完成法源核验的证明。办理时按案由、时间效力、程序、特别规定及民诉法后续修订重新核验，未能联网则明示。

- [最高人民法院关于民事诉讼证据的若干规定，2019修正，2020-05-01施行](https://www.court.gov.cn/zixun/xiangqing/212721.html)：第3—9条用于核查自认语境及例外；第14—15、93—94条用于电子数据范围、原件与真实性审查；第85、87—90条用于综合审查及不能单独定案的情形；第95条涉及控制证据拒不提交的条件。这里只是查阅定位，不概括为任何单项证据自动胜负。
- [最高人民法院关于适用《中华人民共和国民事诉讼法》的解释，2022修正官方正文](https://www.court.gov.cn/zixun/xiangqing/353651.html)：第90—91条核举证责任；第103—108条核质证、三性、取得方式、和解妥协与证明标准。正文援引的民诉法条号须结合后续法律修订核对，禁止将“高度可能性”转换为固定百分比。

控制证据拒不提交与书证提出命令要区分：证据规定第95条明文列控制、无正当理由拒不提交及负举证责任方的不利内容主张；解释第112条及证据规定第45—48条另规定申请、审查和责令提交书证的机制。适用时分别核条文与本案事实，不把法院先责令一概写成第95条明文条件，也不反向断言所有场景均无须法院要求。以上于2026-11-05重开官方正文核对。
