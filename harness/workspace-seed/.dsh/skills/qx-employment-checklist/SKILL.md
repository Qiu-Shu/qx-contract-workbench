# 劳动清单、参数核查与情景归档

本方法提供来源绑定的初审清单、参数候选和条件算术，不能代替事实认定、完整劳动争议分析或地方规则核验。

先确认本案ID并用 `mcp__qx_legal__read_case_material` 回读已关联原件。引用用实际返回的 path、sha256、ordinal（填到 chunk）和逐字 quote；已知到手工资照录，不等于法定工资基数，其他未知项不能使已知事实消失。

调用 `mcp__qx_legal__assess_employment_termination(case_id, citations)`。citations为1至30条原文引用，不传模型判断的事实布尔值。程序生成不同解除路径、通知/代通知金及历史分段等条件清单，不自动选定任何路径；开业日、入职日或拟生效日不自动成为实际解除日。

## 录用、变更及竞业条款

条款初审使用 `mcp__qx_legal__assess_employment_terms`，review_stage 为 hiring/change/noncompete，仍先回读本案原件并保留正反原文。录用或离职后竞业需要参数提取时设 `extract_parameters=true`；合同变更只形成来源清单，不套这两类核算。

程序从材料识别限定格式的期限、工资等候选；完整且未识别冲突的参数才能做条件比较。跨行关联需要原件明确的“劳动者：姓名；合同编号：编号”（也支持相邻两行），后续为连续参数行。Word需引用全部相关连续段落的实际ordinal，程序核原始位置；空段、漏读段落、新身份头、不同文件、冲突或未知值会隔开或暂停核算。相同参数换算后一致时只核算一次，但保留全部原文位置；副本不会增加核算次数或证据效力。不能为通过解析而改原件、补合同编号，或把模型改写登记成用户材料。

跨文件候选关联另要求每份原件明确相同的“劳动者：姓名；劳动者编号：编号；合同编号：编号”（可为连续三段）。必须逐份回读并引用全部相关段落，不能自行补编号。同名和合同号不足以跨文件拼接；版本、身份或参数冲突会暂停比较，相同值重复记载不算冲突。复杂表格不擅自按视觉位置补关联。

回读 `parameter_extraction` 的 groups、linked_groups、cross_source_groups、warnings 和 missing_parameters；未关联不表示原件不存在该约定。候选参数及其主体归属仍待核，两个工资口径分别列示，不当作已认定法定基数或欠薪。自动关联不足时明确列缺口，保留原文人工核对。

表格可读取已经解析的物理行，location保留行列和合并范围；扫描件保留页码、文字框和置信信息。明确的键值身份行及连续参数行可以由程序关联，不必先手工抄成文本。逐片段读取，低置信行、缺失页或公式缓存仅标明相应部分；先完成其他独立、完整的来源。failed_pages可单独重试，不把局部失败说成全文件不可用，也不填补空白单元格或纵向合并的继承值。

跨页扫描表请读取相邻页的全部片段，包括重复表头和页脚。连续页边界的姓名、劳动者编号、合同编号均明确重复时，程序可关联参数候选；不要自行去掉冲突数值或未知行来促成关联。方向恢复的文字框基于返回的旋转图像尺寸和角度，页码仍指原文件。部分记录不能关联时继续保存原文和其他独立记录的结果。

多层表头的候选对应保存在 header_bindings，包含上级标题、列名、表头位置及数据格位置；明确单位可随列名解释数值，保留来源链。ocr_reviews 记录高置信初识与局部重识别的差异，候选不是已更正原文，不擅自选其中一个数字或否定词。向用户交付差异和可处理行，不因某个单元格或扫描行待核而停下整份材料。

扫描页有清楚的横竖表格线时，scan_grid记录物理单元格、表格编号和行列范围；同一格中分行的列名和单位可以组合为表头候选。无明确表格线、越界文字或未能对应的内容仍保留，不能靠相邻位置臆测继承值。明确同名续表、相邻完整页和相同列边界可由header_continuation给出跨页表头候选，保留两页标题与父标题来源；重复列名和单位不同则不继承，历史标题不因换页丢失。其他表格分别处理；已确定的独立行先完成。

模糊片段可作本机放大、对比度和锐化重识别。locally_supported仅表示至少两种处理支持同一初识文字，没有替换原文或确认事实；差异候选仍需核对。page_recovery表示初识为空后通过增强获得的候选，原件未改；残缺内容不补造数值，明确的其他行继续核算。局部重识别有数量上限，未标出差异不代表全部核实。

复杂表格保留完整表头层级及独立单位行，不以八层为截断点。并列重复字段按有明确父标题的column_scope分别核验，不混合历史和现行数值；嵌套表格保留所属外层单元格的原文上下文。扫描表的纵向合并记录起止行，续页仅重复父标题时仍按原有层级关联字段。Excel格内制表符、换行不等于新列；以工具记录的物理格和字符位置为准。无法唯一对应的部分仍保留原文，不能声称任意版式均已还原。

## 同时要求计算并归档

工资表对账使用 `assess_employment_terms(review_stage="payroll", extract_parameters=true, citations=原文引用)`，读取全部相关表头和行。支持同一行明确的姓名（或劳动者）、工资期间（或月份）、应发工资、代扣合计、实发工资，人民币单位及年月须明确；也可读取原件已有的分号分隔键值行，不改写原件迎合格式。程序计算应发减代扣再减实发的账面差额，保留零值、负差额、来源及原始年份。缺代扣不补零，不跨人、月份或文件拼数，各行不相加为全案应付款；完整行先完成。回读 `parameter_extraction.groups` 的 `calculation` 与 `warnings`，待核行保留原文。工资对账不使用 `scenario_citations`，不认定代扣合法性或实际欠薪；按同一保存记录交付。

材料已明确给出独立完整一行的假设时，可在同一次调用中追加 `scenario_citations`（每项仍为 path/quote/sha256/chunk），最多10项。支持格式示例：`情景假设：基数12345.67元，折算年限3.5年，倍数2。` 数字必须来自本案原文，不能套示例。

程序解析假设、复用精确计算器，并与清单保存为同一条笔记。各情景分别列示，不相加、不当作实际应付款。没有合格原句时说明联合归档尚缺明确情景来源；不从到手工资、入职年份或未知终点猜参数，也不把自己的改写登记成原始材料。独立纯算术可使用现有 calculate_employment_amount，但不能声称已并入清单或Word。

## 保存与交付

- recorded成功后，用返回的 id 调用 `read_case_note`，按 next_start 回读全文；需要Word时 `mcp__qx_legal__export_case(case_id, note_ids=[id], audience="internal")` 导出同一记录。
- 最终使用返回的 user_summary 和实际成功生成的文件链接，算式也以已保存的同一内容为准；不在聊天另加未归档的事实摘要或金额。工具没有计算时不得声称已计算。
- recorded=false、来源失配或导出失败时保留失败状态，不把旧文件当作本次成功结果。request_id只用于同参数重试；supersedes仅在用户明确要求更正时使用，保留旧记录。

工具缺失时如实说明本流程未执行，不改用自由正文绕过来源和版本校验。条款核查和候选算术通过，不代表完整劳动审查或实际责任已确认。
