# 开源许可证合规审查

## 任务

把实际许可证及代码使用事实映射到所需履行动作。

## 输入证据

组件与精确版本、来源和实际 LICENSE/NOTICE、修改情况、链接或集成方式、分发/网络服务/内部部署、输出许可与履行记录。

## 关键判断

1. 清单许可证标签只是线索；对每个组件核验实际许可文本、版本、多重许可及来源一致性。宽松许可标签也不能自动放行。
2. 按真实使用和传播方式分析触发条件，再列署名、文本提供、源码提供及其他可能义务。没有许可原文或使用方式时，义务与兼容性均待核。
3. 区分“许可类型初筛”“义务核对”“履行证据充分”三个状态；前两者不能写可继续使用、绿色或发布通过。
4. 对自有代码发布另核权属、第三方内容与拟选许可证；整改动作指向确切组件和文件。不开源、不上传、不安装依赖来代替审查。

## 输出

组件/版本/许可来源/使用事实/触发条件/义务及履行证据/状态；发布前缺口与可执行检查清单。

## 证据与执行

先用本次材料完成可做部分。每项事实保留来源、陈述者和状态；“拟议”“未明确”“未提供”“未查询”分别记录，不能改写成已约定、不存在或查询无结果。业务负责人不自动成为审批人，机构名称不自动成为委托客户。

真实法律判断先取得适用法域、时点、官方原文和具体定位，再判断主体、触发条件与例外。无法核验的那一问题列待核，不用记忆、原库模板或具体条号当占位。仅有假设规则时按其明示要求逐项分析，其他问题列独立待核或建议，不把额外义务归入给定规则。

仅读取当前明确授权材料；实际文件可用材料解析工具，规则检索用真实可用的官方来源工具。无工具仍交付草稿及证据需求，列明未执行项目。仅在用户要求保存时写入已核实的当前事项位置并回读；报告完成状态以工具返回为准。对外发送、提交、审批或系统变更须有对应明确授权，不因调用本技能自动执行。
